# 王朝循环维护指南

适用版本：本地 descriptor 标注 CK3 1.19.0.6；整理日期2026-09-13。本指南解释当前职责和维护方法，不提供未经验证的新引擎接口。先读 [当前差异](README.md)，再查 [功能表](功能与参数总表.md)。

## 执行链和作用域

### 情况观察与自然入口

| 触发 | 链路 | 关键顺序 |
|---|---|---|
| 情况月度脉冲 | `hd_dc_request_monthly_observation` → 记录维护、皇室维护、党争维护 → 请求观察 | 不假定同一on_action里的effect和event列表顺序 |
| 政治观察 | `hd_dc_observe_political_state` → 快照 → W/H同步 → 影响来源 → 时代判定 → 各实例战争/治理观察 → 年度危机池 | 先读实际政治状态，再结算；不能直接由W切时代 |
| 人物年度脉冲 | `hd_dc_ordinary_yearly` → `hd_dc_observe_ordinary_pool_effect` | 原生作用域是人物，不是情况；保留成年/有地/参与检查 |
| 标题/封臣变化 | `hd_dc_observe_title_transfer`、`hd_dc_observe_hegemony_destruction`、`hd_dc_observe_vassal_change` | 合并尚未处理的观察请求，避免每个事务反复扫描 |
| 额外派系 | `hd_dc_extra_faction_yearly` → 情况十年锁 → 参与者 → `hd_dc_check_extra_faction_year_effect` → 头衔十年锁 → 合法类型/宣称元组 → 创建后读回 | 当前双层十年节流；改动时同步debug和测试的等待预期 |

### 状态归属

| 真实对象 | 代表键/引用 | 不可混用 |
|---|---|---|
| 情况 `situation:dynastic_cycle` | `hd_dc_pressure_raw`、`hd_dc_prosperity_raw`、`hd_dc_pressure_band`、`hd_dc_instances`、`hd_dc_acute_instance_id`、`hd_dc_annual_epoch` | 不在参与者或保管人身上另造一份权威W/H |
| 郡头衔 | `hd_dc_control_baseline`、`hd_dc_development_baseline`、`hd_dc_control_processed`、`hd_dc_development_processed` | 换领主不能等于新周期，离区只清本系统实时修正 |
| 记录保管人 | `scope:hd_dc_keeper` | 只是引擎story的owner，不因此取得政治身份或收款资格 |
| 当前记录 | `scope:hd_dc_record`、`hd_dc_record_id`、`hd_dc_record_version` | 临时scope不是持久引用，延迟事件必须有记录与版本 |
| 实例记录 | `scope:hd_dc_instance`、`hd_dc_instance_ref`、`hd_dc_instance_id`、`hd_dc_stage` | prepared、acute、aborted等状态代表实际流程，不靠UI窗口判断 |
| 人物节点记录 | `scope:hd_dc_actor_story`、`hd_dc_node_version` | 相同人物后来的节点不能接受旧节点答复 |
| 提案记录 | `hd_dc_origin_version`、`hd_dc_proposal_wait`、`hd_dc_callback_committed` | 接受提案不等于完成付款/政策/保护义务 |
| 收据 | `scope:hd_dc_receipt`、`hd_dc_points_committed` | 无收据重复调用写入器会产生新请求；写入器自身不是节点去重器 |
| 实际付款记录 | `scope:hd_dc_payment`，提交状态 absent/1/2/3 | 未付/处理中/已付/金额不符；不能把预期金额当已到账 |
| 政权主头衔 | `hd_dc_extra_faction_cooldown`、`hd_dc_extra_faction_year`、`hd_dc_extra_faction_result` | 锁跟随头衔，换统治者不自动重置 |

查询某键的全部消费者：`rg -n 'hd_dc_node_version' common events gui localization/simp_chinese`。表列代表性键，不替代CSV的逐文件符号索引和实际脚本。

### 金额和郡账本的细分字段

| 记录 | 字段 | 含义 |
|---|---|---|
| 付款 | `hd_dc_payer` / `hd_dc_payee` | 实际付款人/收款人的持久引用 |
| 付款 | `hd_dc_amount_due` | 本次约定金额；不是实际到账 |
| 付款 | `hd_dc_debit_kind` / `hd_dc_credit_kind` | 金钱/国库方向；值1分支使用gold，另一路使用treasury |
| 付款 | `hd_dc_actual_debit` / `hd_dc_actual_credit` | 分别读真实前后余额得到扣款/到账 |
| 付款 | `hd_dc_unreturned_debit` | 扣款减到账的非负差额；取消/退款消费者另跟踪，不重新全额扣款 |
| 付款 | `hd_dc_payment_commit` / `hd_dc_payment_date` | absent未付、1处理中、2足额完成、3金额不符；记录真实日期 |
| 郡 | `hd_dc_loss_cycle` / `hd_dc_highest_loss_band` | 当前周期及已处理最高档，决定是否补差 |
| 郡 | `hd_dc_control_processed` / `hd_dc_development_processed` | 已处理的累计目标额 |
| 郡 | `hd_dc_control_paid` / `hd_dc_development_paid` | 真正扣除的存量；可能与累计目标不同，不能混读 |
| 郡 | `hd_dc_county_recovery_since` / `hd_dc_county_recovery_wait` | 低档连续恢复观察；60个月后结束旧周期，不返还旧损失 |

时代分母在 `hd_dc_initialize_scope_effect` 从 `title:h_china` 的法理郡初始化到 `hd_dc_counties`，并给郡 `hd_dc_core_county_v1` 标记。修改地图/法理归属时需要重新核验新存档的核心集与真实领地快照；不要只改显示百分比。

## W/H 写入的维护合同

1. 增量写入器运行在情况作用域，参数W/H为原始点；`SOURCE`传单个来源标记。同步函数负责首次初始化与派生显示，不将原生时代进度反导入。
2. 节点先确认真实后果和义务，再通过持久收据提交。`hd_dc_points_committed`先置处理中，再写入，最后置已提交；旧回调不能二次消费年度净额。
3. 写入器保存请求前值、限制后的实际值、日期、来源与序号；钳制到0增量的请求也有记录。不要只在中文提示里显示预期值。
4. 需要算式时先 `save_scope_value_as` 得标量，再传给宏。当前引擎日志已经证明把算式块直接作为这些宏的参数会错误展开。
5. 调试绝对设值先计算差额，再调用正式写入器；随后刷新影响。直接 `set_variable` 改权威值会绕开历史、年度限制和收据。

## 记录、答复、付款与结案

| 阶段 | 应做什么 | 必须拒绝的捷径 |
|---|---|---|
| 准备实例 | 从合法政治快照选择实际人/头衔，创建记录，保留pending锁 | 覆盖现有活动实例，或伪造缺少的候选 |
| 提交BOOT | 再核对准备记录，置acute，登记实例，写类型冷却 | 在BOOT失败时假称剧情已发生 |
| 投递节点 | 保存节点记录与版本、接收人、期限 | 直接控制台投递深层事件而缺少上下文 |
| 接受/拒绝 | 检查记录、版本、真实答复人和到期状态；回调只提交一次 | 玩家选项代替另一角色签约 |
| 支付 | 检查双方授权，先冻结/读取约定金额，读取真实前后余额并记差额 | `add_gold`给钱却未扣另一方，或失败仍置paid |
| 履行 | 审查真实释放、战争、郡修正、答复份数、保护期限 | 关闭事件即履行、到期即守约、签名即到账 |
| 部分履行 | 保留已付/已放/已答部分及未清偿事项 | 失败清理时顺便删除欠款或回滚真实世界变化 |
| 最终结案 | 当前合法档、未纠正重大毁约优先、一次性终奖 | 无视未结束战争/义务强行提前结案 |

查错优先跟随实例和记录引用，不先修改人物金钱或W来“修正显示”。记录owner死亡由 `hd_dc_repair_record_keeper_effect` 处理；保管人死亡不等于合同双方死亡。

## 保护承诺与标题事务

处罚前证据必须发生在原生理由被消费之前。显式处决使用真实killer；拘押使用实际ACTOR/TARGET；夺头衔需分别冻结命令人、旧持有人、接收人、具体头衔、日期和合法依据。接收人可能是第三人，不能代替命令人。

| 接口 | 用途与维护要点 |
|---|---|
| `hd_dc_begin_protection_reason_effect` | 真实目标/行动/理由的前置快照；调用方必须提供正确对象 |
| `hd_dc_begin_protection_positive_imprisonment_effect` | 特殊拘押仅有可读正证据才记合法；缺理由不自动判违法 |
| `hd_dc_begin_protection_positive_execution_effect` | 祭祀/质子等特殊执行正证据路径；不能由事件名推罪 |
| `hd_dc_capture_protection_direct_title_revocation_effect` | 参数TITLE/ACTOR/RECEIVER；逐头衔冻结，保持原生判定上下文 |
| `hd_dc_capture_protection_capital_revocation_effect` | 实际夺都；参数ACTOR，原生新天子与自定义root各按实际调用者 |
| `hd_dc_clear_title_protection_reason_effect` | 放在真实resolve后；过早清理会使回调丢证据，永不清理会污染后续行为 |
| `hd_dc_record_protection_unknown_revocation_effect` | 无可靠命令人/依据时登记待核；不据此授予守约完成奖励 |

当前title记录的consumed标记仅保证同一事务内重复回调不再次消费；下一真实动作开始重新冻结。纯引擎回调没有通用操作编号，因此事务清理后收到的旧回调无法与某些同日新动作完全区分。维护时必须继续披露这一边界。

## 修改常见内容时的最小工作范围

| 需求 | 必查/必改位置 | 验证重点 |
|---|---|---|
| 改W分界或量程 | parameters、pressure values、modifier映射、debug、中文 | 原始/显示单位、四处分界、钳制、收据 |
| 改危险倍率 | 对应hazard/faction/epidemic/disaster/unity value | 动态p0、0/100、非目标分支、误差预算 |
| 改普通发生率 | parameters、ordinary effect、observer on_action | 真实人物作用域、年度锁、每人pending、合法池 |
| 改派系频率 | faction pulse on_action与effect两层锁、debug场景和中文 | 失败也消耗轮次、继承后锁、低W、单次最多一个 |
| 改节点金额 | parameters及节点固定50等局部约定、proposal/payment、中文 | 提案冻结、付款人/收款人、部分到账、重复回调 |
| 改等待期 | 正式wait变量与具名delay values、对应maintain逻辑 | 实际日期、到期边界、旧版本拒绝、提示同步 |
| 增加原生概率入口 | 实际原文件 + 窄适配；必要时已有helper | 保留全部非适配AST，不能用AI权重/独立随机池代替 |
| 新增节点 | 合法trigger、BOOT/dispatch、记录、事件、结案/失败、自然池、debug、中文 | 所有必需分支闭合后才加入自然池 |
| 改保护捕获 | 实际处罚前调用、helper、on_action、清理 | 同日不同动作、多标题、第三方接收、未知依据 |
| 改中文 | `simp_chinese`及必要的`replace/simp_chinese` | 唯一键、BOM、格式占位符、运行期flag别名 |

不要为仅一处新逻辑再造一层通用框架；优先复用已经验证的正式流程。也不要为了减少行数删去真实世界的支付、答复或失败分支。

## 已遇到的解析坑

| 现象 | 已确认原因 | 维护做法 |
|---|---|---|
| 宏出现未知H/add/multiply | 把算式块作为宏实参 | 先保存数值scope，再传标量 |
| 名单清理报未知效果 | `clear_list`不存在 | 按已验证的列表迭代移除方式 |
| 基础概率总为0 | script value的min/max钳制方向颠倒 | 本语言min为下界、max为上界；勿套其他语言直觉 |
| 阶段边报枚举错误 | `takeover_type = none`无效 | 此处使用已验证untyped，不附points阈值 |
| GUI获取角色提示报错 | `Char.GetTooltip`不是该类型接口 | 当前用 `GetUINameNotMeNoTooltip`；改前核对类型 |
| debug描述flag解析为scope链 | 点号flag token歧义 | 下划线flag配中文别名；不要批量改所有事件ID中的点号 |
| days/months报Named value not found | 直接动态变量用于不支持该表达式的时长位置 | 使用已有具名script value并保留原作用域 |
| 全局debug条件找不到trigger | 调用了另一事件文件的局部trigger | `hd_dc_debug_native_relation_triggers.txt`保存核验后的独有全局定义；随原版同步 |
| 郡资格报未知条件 | `title_tier = county` | 当前验证形式 `tier = tier_county` |
| 中文标题串到人名 | 本地化哈希冲突 | ORD-19归档标题已用 `hd_dc_ord_correspondence_archive_title` |
| 中文出现重复原生描述 | 原生键覆盖位置不当 | 当前两条时代描述位于中文replace目录 |

## 原版更新与冲突维护

盗库四门准确位置：`common/schemes/scheme_types/tgp_dynastic_cycle_schemes.txt` 中 `celestial_siphon_treasury.allow`、`.valid`，以及 `common/character_interactions/10_tgp_interactions.txt` 中 `celestial_siphon_treasury_interaction.is_shown`、`.can_send`，均有 `always = no`。这些文件中的“王朝循环已禁用”旧注释不能作为当前情况系统整体关闭或崩溃根因已证明的证据。定位具体块，不能删除整文件内所有 `always = no`。

1. 先读descriptor和真实安装版本。当前descriptor没有整体替换 `common/scripted_effects` 或 `events`；同路径原生文件覆盖仍可能遮住更新后的原版内容。
2. 从CSV筛选原生同路径文件；每份都比较“新原版、当前mod、上次认可基线”，不要只保留hd_dc几行后丢掉其他mod改动。
3. 先核对原生触发条件、p0表达式、目标scope、随机池总权重、最终后果，再移植窄适配。
4. 对保护插入核对实际操作前后位置；对概率插入做精确逆变换。逆式应校验参数、邻接操作、原payload再剥离，不能按helper名字全部删除后声称保留原生。
5. 验证中文、debug资格与正式入口同步。当前被关闭的门不得因为合并新版而意外打开。
6. 只处理本需求相关差异；不reset、restore、清空其他人物、地图、文化或图形工作。

后续检查脚本依赖D盘的历史AST、manifest和安装原版，不是独立可移植工具包。换机器或清理D盘前应明确这些依赖；不要只复制runner就以为验证环境完整。
