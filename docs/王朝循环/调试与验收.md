## 玩家检查顺序

| 步骤 | 操作 | 预期与失败信号 |
|---|---|---|
| 1 初始化 | 新存档打开总菜单，查看情况及W/H；必要时正常推进日期或执行正式观察刷新 | 不存在情况时决议不可执行；记录具体资格提示 |
| 2 边界 | W/H分别设0/20/40/60/80/100；各边界−1再+1；0−10、100+10 | 两轴独立；原始/显示换算正确；钳制；高档边界无错位 |
| 3 存量 | 同一郡W=20→80→40→80，再多次刷新，随后换领主 | 控制/发展不重复补扣、不返还；取整可能使发展损失为0 |
| 4 时代隔离 | 只改W或H，观察原生阶段与政治状态 | 不因点数按钮直接退出割据、解散派系或清空政治状态 |
| 5 人物修正 | 比较五档压力/正统性、离区与重新进入 | 本系统修正替换而非叠加；其他原生修正继续存在 |
| 6 危险机会 | 合法谋杀/绑架/勒索场景及实际事件 | 原目标、计谋容量/能力、秘密资格保留；单次成功不证明倍率 |
| 7 派系 | W≥20，查看当前两层冷却与实际合法类型；允许条件后执行正式检查 | 最多额外一个，失败也不重抽；原生其他创建仍运行；当前按十年锁等待 |
| 8 疫病/灾害 | 真实病种/强度、DLC/规则/地理/季节均合法的场景 | 生成实际疫情/灾害；重复同灾不重复处理；缺条件显示原因 |
| 9 特质/关系 | 饮酒等合法抽样、正式压力/旅行/关系事件 | 不靠直接加特质验证概率；保留伤亡分流；必然结仇分支不再放大 |
| 10 团结/民意 | 合法家族团结负增量；五档郡民意与离区 | 真实家族读取；无机制不强造；民意重复刷新不叠加 |

## 报错时如何记录

| 症状 | 先收集什么 | 优先检查 |
|---|---|---|
| 无调试决议 | 是否debug、新存档、情况存在、实际角色 | decision可见与有效条件、namespace/中文 |
| 节点不出现 | 当前实例ID、节点版本、待答复、冷却、资格提示 | 正式dispatch及trigger，不直接改标记绕过 |
| 钱/奖励异常 | 付款前后余额、双方、金额、收据与结案状态 | proposal签名、payment实际差额、重复commit |
| W/郡反复变化 | 周期、基准、已处理额、请求与实际增量 | 重复写入器调用、存量最高处理档、年度净额 |
| 保护无法结案 | 冻结对象、命令人、标题、日期、合法/未知依据 | 前置捕获是否早于原生消费、resolve后清理 |
| 派系久不出现 | 两层十年锁、W、合法类型/真实宣称元组 | 当前自然调度与旧年度说明是否混淆 |
| 启动或点击报错 | 新日志时间、第一条相关错误、按钮/角色/日期 | 实际解析错误优先；后续连锁报错可能只是结果 |
| 崩溃 | 最新完整 `ck3_*`目录、meta、exception和logs（若存在） | 重新选择最新包，不能沿用旧崩溃的根因猜测 |
