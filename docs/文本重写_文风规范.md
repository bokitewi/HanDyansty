# 汉晋春秋 · 中文文本沉浸化重写规范（2026-10-09）

本规范是全 mod 中文文本重写的唯一标准。所有执行者（含子代理）必须完整阅读后再动手。

## 0. 用户已定的决定（不可更改）

| 项 | 决定 |
|---|---|
| 范围 | 全部 mod 新增中文文本，含整合子 mod（tk 建筑、UUII、DM、zgrc、embattle、quix、saas 等） |
| 不改 | 人名/地名/头衔/朝代/家族/年号等**名称**；游戏规则 `setting_*`/`rule_*`；百科概念 `game_concept_*`；界面数值标签（含 `Var(...)`/`GetValue` 的面板数字行）；debug 文本 |
| 改脚本 | 允许。**效果以文案为准**：叙事（标题/正文/选项）与脚本效果不符时，改脚本去贴合叙事意图 |
| 英文 | 不动，只改 `simp_chinese` |
| 语体 | **正文：白话带古意**（原版式叙述，略带汉末气息）；**选项：文言短句** |
| 人称 | 事件正文统一第二人称"你"（人物引语内部照常用"我/吾"等） |
| 隐藏/延迟效果 | 一句叙事 + `show_as_tooltip` 让引擎显示真实效果 |
| 建筑/特质/修正描述 | 汉末三国时人视角；去现代行政区、"距今"、"始建于某某年（公元）"、后世朝代沿革 |

## 1. 文本分类与各自要求

### A. 叙事文本（必须完全沉浸）
事件标题 `.t`、正文 `.desc`（含 triggered_desc 片段）、选项 `.a/.b/...`、决议 `_decision_desc`、建筑/特质/修正/宝物/文化传统/信仰的 `_desc`、故事/通知正文。

- **禁止**出现数字化收益："获得100金""兵力+300""压力-15""持续5年""（30 金）"。数值由引擎在效果提示里自动显示，不需要也不允许在文案里复述。
- **禁止**机制讲解："此选项会……""触发后……""AI 会/玩家不受……""本事件不会使其死亡""修正""冷却""层数""概率""门槛""沿用原版"。
- **禁止** AI 提示词残留/契约腔：实际、真实（作"确实存在"义时）、复检、核验、回执、结算、履约、据实、本案、不另、仍由……扣押、发送提案不付钱、只能接受或拒绝、文书只有……条款、两份具名确认齐备……等。
- 叙事中**可以**出现有叙事意义的量词，如人物说"百金赎之"，前提是脚本里确实如此（效果以文案为准，见 §3）。尽量少用。
- 选项：文言短句，体现人物态度与意图，一般 4–16 字。例："百金赎之，勿复多言。""此事暂且按下。""以俘易俘，各归其主。"
- 正文：白话带古意，第二人称"你"，描写场景、人物、情绪与抉择；不用"你可以选择……"列菜单式写法。参考原版：`送来的文书上写着[...]的名字……`
- 标题：2–8 字，有画面感，不剧透机制。

### B. 效果提示（`custom_tooltip`、`.tt`、`_tooltip` 中描述后果的部分）
处理顺序：
1. **引擎已显示的效果**（同一选项里未隐藏的 `add_gold`、`add_opinion`、`add_county_modifier` 等）：删除手写复述的 `custom_tooltip` 行；若该本地化键不再被任何地方引用，一并删除该键。
2. **`custom_tooltip = { text = X  <效果…> }` 包裹真实效果**：去掉包裹，让效果裸露出来由引擎显示；若包裹里有不适合直接显示的内部效果（set_variable、flag、list 操作等），把这些放进 `hidden_effect`，可显示的效果留在外面。
3. **隐藏或延迟结算**（`hidden_effect`、`trigger_event` 后续结算、向他人发提议等对方答复）：保留一句叙事（例："[对方]将斟酌这份赎金。""此事成败，且看来日。"），并用 `show_as_tooltip = { <真实效果> }` 展示接受/成功后的主要效果；若后续结果随机或取决于对方，用原版式提示："#EMP 此举成败难料。#!"之类。
4. **随机结果**：可用原版式"#EMP 你或许能……#!"、"有一定可能……"，不写百分比。
5. 必须保留的少数**非效果信息**（比如某人会记住此事、某件事将在数年后见分晓），写成一句叙事，不写数值。

原版参考：
- `adultery.1004.a.tt: "我把秘密埋在我心里。目前如此。"`
- `child_personality.0061.a.tt: "#EMP 你有一定几率改善你的外交能力，并对饮酒上瘾。#!"`
- `hold_court.6000.c.tt: "你派遣[inspector.GetTitledFirstName]为巡视官员，主持该伯爵领的恢复工作"`

### C. 条件/失败原因文本（`custom_description`、`custom_trigger_tooltip`、交互失败原因、催化剂条件、决议 `is_valid` 的自定义条件）
- 这类在原版里本就是讲条件的，允许出现条件与阈值，但写成原版式简洁句："你须有足够的金钱""[recipient.GetShortUIName]不在你的宫廷中""天子的宰辅才能平庸"。
- 选项 `trigger` 里已有的条件，不要在选项文本/提示里再用散文重写一遍（"管理至少12、持有至少120金"→删掉）。

### D. 界面文本（GUI 标签、按钮、面板说明）
- 标签/按钮保持简短，不改名称体系。
- 面板说明性 tooltip 可简明说明用途（原版 UI 提示也讲用途），但删去 AI 残留、实现细节（"本面板沿用原版……""脚本每月刷新……"）。

### E. 决议 / 交互
- `_decision`：名称，一般不改。
- `_decision_desc`：叙事，原版式，可第一人称内心独白（原版惯例）或中性叙述。例：`我的家族历史包含了大量成就与荣耀的事迹……`
- `_decision_tooltip`：一句话概括所为之事（原版式，可用 `[concept|E]`），不列数值。例：`正式[pay_homage|E]你的[liege|E]并宣誓效忠`
- `_decision_confirm`：短促的决心之语，文言为宜："事不宜迟！""开仓！"
- 交互 `_desc`：一句话说明此举（原版式），不列数值、不讲 AI 行为。

### F. 特质 / 修正 / 建筑 / 宝物描述
- 特质：原版式"该角色……"一句或两句，写其人风貌，不写"不授予额外军权""本朝同名仅一人持有"之类规则。
- 修正：一句描述该人/该地的处境，如原版 `苍天预示该角色将健康长寿。`
- 建筑：当时人视角描述其形胜、功用、传说与当世声名。建筑本身晚于汉末（如唐陵、宋庙、明代遗迹）时：写该处山川/旧址在汉末的样貌或相关上古传说，**名称不改**，并在报告"超时代建筑"一节列出，交用户决定去留。
- 同类建筑 `building_type_*_desc`（如"铁矿""名山"）可按类别写一句共用的描述（同一类别文字可相同）。

## 2. 技术硬性要求（违反即错误）

1. 文件保持 **UTF-8 with BOM**，首行 `l_simp_chinese:`，键行格式 ` key:0 "value"`（保留原有的 `:0` 或无版本号写法）。
2. 值内不得出现未转义的英文双引号 `"`；引语用中文引号“”或「」。
3. `[...]` 数据函数：只能使用原文件中（同一事件/同一键）已经出现过、确定在该作用域有效的表达式；不得臆造新的 scope 名。若确需新的人物引用，先在脚本中确认该 scope 在此事件中已保存。
4. `$key$` 引用必须指向存在的键。
5. 格式码 `#X ... #!` 必须成对。图标 `@gold_icon!` 等可删不可乱造。
6. 不得删除仍被脚本/GUI/其他本地化引用的键。删除键前先全局 grep（events/、common/、gui/、localization/）。
7. 改脚本：保持花括号平衡；新增的本地化键必须同时写入对应中文本地化文件（英文不动，英文缺键可接受，在报告中列出）。
8. **重复键**：同一键在多个文件定义时，`localization/replace/` 或 `localization/simp_chinese/replace/` 下的版本生效。只改生效版本；非生效副本改为与生效版本相同的文本（或在报告中列出由主控统一同步）。
9. 只编辑分配给本单元的本地化文件和"拥有"的脚本文件。需要改动他人拥有的脚本时，不要动手，在报告"跨单元请求"中写清楚文件、位置、改法。
10. 不启动游戏。

## 3. "效果以文案为准"的执行细则

- 先读脚本，逐个选项比对：标题/正文/选项所说的事 vs 实际效果。
- 不符时，**以叙事意图为准修改脚本**：例如选项写"厚赐金帛以谢"却无任何花费→加入合理花费；写"严惩其罪"却给对方好感→改为负面后果。
- 数值幅度参照同 mod 同类事件与原版同类事件，不得明显破坏平衡（金钱用原版 `*_gold_value` 类脚本值优先；好感用常见档位 ±10/±15/±20/±30）。
- 叙事本身是残留机制腔、意图不明时，以脚本效果为准重写叙事，不改效果。
- **每一处效果改动都必须写进报告**（文件、事件/选项、改前→改后、理由）。
- 发现明显的脚本 bug（与文案无关）只报告不修。

## 4. 生成器提醒
`docs/tools/gen_party_*.py`、`gen_era_outlets.py` 等会生成本地化/脚本。改动其产物后，在报告中注明"生成器未同步"，或同步修改生成器中的对应字符串（二选一，报告说明）。

## 5. 自检
完成后运行：
```
python -X utf8 "docs/tools/text_rewrite_check.py" --unit <单元名>
```
修到 ERROR 为 0；WARN 逐条复核（残留词、叙事键含数字、新出现的 [scope]）。

## 6. 报告
写到 `docs/文本重写_报告/<单元名>.md`，包含：
1. 改动概览（文件、改写键数、删除键数）。
2. **效果改动清单**（逐条）。
3. 删除/新增的本地化键。
4. 跨单元请求。
5. 超时代建筑/内容清单（如有）。
6. 自拟项与不确定处。
7. 校验结果（ERROR/WARN 计数）。
