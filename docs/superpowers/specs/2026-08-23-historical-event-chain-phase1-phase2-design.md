# 历史事件链第一批、第二批彻底修复设计

- 日期：2026-08-23
- 状态：待所有者审阅
- 实施门槛：本文件获批后才编写实施计划并修改模组脚本
- 目标版本：Crusader Kings III 1.19.0.6
- 范围：第一批九场地方起义；第二批奉迎天子、官渡、赤壁、刘备入蜀衔接、荆州覆亡、夷陵

## 1. 设计依据与效力顺序

本设计按以下优先级处理冲突：

1. 用户在旁边 Chat 中明确锁定的设计与本轮“完整方案执行”授权。
2. 当前 HanDyansty 项目已经存在、且未被用户撤销的个人线结构。
3. CK3 1.19.0.6 已安装原版的实际脚本语法和工作范例。
4. ChatGPT 的外部建议只作为设计检查清单，不作为事实来源。

旁边 Chat 已锁定的核心边界：

- 第一批只有九场地方起义，全部是事件强制发动的起义战争；不增加故事周期或额外内容。
- 曹操线只新增“奉迎天子”，袁绍线只新增“奉迎天子”，其余沿用现有个人线结构。
- 刘备线只新增 LB-24“荆州覆亡”和 LB-25“夷陵”；入蜀属于 LB-22，并在 LB-22 成功占据益州后提供任命关羽为荆州最高统治者的事件。
- 个人故事由 story cycle 管理；至少具有历史结局、非历史结局、替代失败、替代成功。
- AI 对历史选择具有极高权重，但绝不硬编码为 100%。
- 官渡、赤壁是由世界状态开放的历史机会，不是日期到点自动开战。
- 日期仅提供最早开放和失效窗口，不能单独构成触发原因。

## 2. 成功标准

完整修复须同时满足：

1. 第一批严格只有九场起义，每场只触发一次，合法发动战争，兵力、目标、人物和结算均符合锁定表。
2. 第一批不再出现当前日志中的 effect/trigger 上下文错误，不再依赖破损的空姓名表。
3. 第二批删除五个“日期到点直接发动/直接改制”的旧启动器；日期只能开启检查窗口。
4. 奉迎天子由曹操、袁绍各自的个人 story cycle 呈现，但共享同一个世界事实，不能生成两个天子或两个互相冲突的世界结果。
5. 官渡和赤壁只有硬性世界状态满足时才成为机会；战争过程和结果由实际游戏状态决定。
6. 入蜀不再作为独立日期战争；它接入刘备 LB-22。LB-24、LB-25 按批准的因果链出现。
7. 所有新故事均有明确的启动、进行、失效、所有者死亡、战争失效、成功和失败状态，不会卡成永久活动故事。
8. 静态验证、启动验证和运行时场景验证分别留证；只有三层均通过，才可称“彻底修复”。

## 3. 非目标

- 不重写曹操、袁绍、刘备现有且未被撤销的其他个人事件。
- 不新增 LB-23，也不借本次修复扩写刘备早期生涯。
- 不把九场起义改造成故事周期。
- 不按现代地理猜测目标；一律以游戏 title/province 实际定义为准。
- 不增加动态兵力缩放、新兵种、攻城器、永久全局增益或额外文化。
- 不为了兼容而覆盖原版全局 on_action、story cycle 或 CB 文件。
- 不顺手整理无关代码、格式、历史数据或用户的其他未提交改动。

## 4. 总体架构

### 4.1 第一批状态流

`窗口检查 → 解析目标与最上层防守者 → 生成/复用首领 → 锁定本次尝试 → 建立战争 → 生成绑定军队 → 战争结算 → 清理军队与临时状态`

每场起义使用独立状态：

- `eligible`：窗口和全局前提成立，尚未处理。
- `committed`：已经选定合法防守者、目标和进攻者，开始建立战争；用于阻止同一脉冲重复进入。
- `active`：战争 scope 已存在，固定军队已生成。
- `resolved`：战争胜、负、白和、失效之一已经结算；永久禁止再次触发。
- `retryable_failure`：只允许在战争实际未建立、且没有生成军队或改变领地时回滚到可重试状态。

现有 `hd_revolt_*_fired` 标志保留为永久兼容标志。实现时要避免“战争未建立却永久吞掉事件”和“战争已建立但下一脉冲重复生成”两类竞态；具体用临时标志还是变量，在实施计划中依据 CK3 实际可用作用域确定。

### 4.2 第二批状态流

`世界状态形成 → 开放机会窗口 → 相关个人故事/世界事件取得唯一所有权 → 选择与实际战争 → 事实结果写回 → 参与者视角事件 → 终止或失效`

原则：

- 世界事实只能有一个权威状态。
- 个人 story cycle 是人物视角和决策入口，不复制世界战争。
- 任何战争的胜负必须读取实际战争结局，不能由延时事件预写历史结果。
- 所有者死亡默认结束个人故事，不自动继承；只有已明确批准的角色接续才例外。
- 条件不再有意义时失效，不做“历史补发”。

## 5. 第一批：九场地方起义

### 5.1 全局规则

共同触发条件：

- 黄巾起义已经开始。
- 当前日期在该起义的专属窗口内。
- 该起义永久 fired 标志不存在。
- 至少一个规定目标 title 存在有效持有者。

不得添加的门槛：

- 不等待黄巾战争结束。
- 不检查控制度、好感、文化、统治者性格、玩家/AI、当前战争数量或政局稳定度。

仅允许的阻断原因：

- 没有合法目标 title。
- 起义首领已经是目标的实际统治者。
- 引擎无法形成合法战争。
- 该起义已经 fired。

防守者与目标解析：

- 防守者是规定目标当前持有者的 `top_liege`，不是直接 holder。
- 多目标起义选择持有规定目标数量最多的一个 top ruler。
- 同票时使用稳定、可复现的 title 优先顺序，不随机漂移。
- 只把该防守者实际拥有的规定目标加入同一战争。
- 使用一个战争和重复的 `target_title`，不靠胜利后的自定义补发模拟多目标战争。

战争与军队：

- 必须先成功建立战争，再生成军队。
- 固定兵力，不按防守者实力缩放。
- `uses_supply = yes`、不可继承、与战争绑定。
- 不含攻城器和新 MAA。
- 进攻胜利：取得所有正式战争目标并独立；不得授予帝号或永久 buff。
- 防守胜利或白和：不转移土地。
- 任何终局：绑定军队消失，起义不再二次触发。
- 首领可正常死亡，不复活、不重生；战争按 CB 的合法继承/失效规则处理。

人物规则：

- 有批准的既存历史人物时优先复用。
- 匿名首领必须低微出身、无家族，不得 `dynasty = generate`。
- 文化、信仰从指定本地来源取得；无来源时使用明确的降级顺序，不能创造新文化。
- 仅为本次起义所需的人物赋予最少特质和能力，不增加无关家属或关系网。

### 5.3 王国并战的实现边界

王国是第一批唯一允许接入既有起义战争的特殊项。其设计必须满足：

- 同一防守者时不能形成两场重叠大战。
- 不能清空或覆盖北宫原有目标。
- 不能让王国加入军队后失去自己的陈仓/扶风政治诉求。
- 如果 CK3 不能在已开始战争中安全追加正式 `target_title`，实现不得伪装成已经满足需求；必须在实施计划中提出经原版验证的单战承接方案，或把这一点退回所有者决策。

### 6.2 奉迎天子：曹操与袁绍的双视角、单事实

开放窗口：195–197 年。窗口只是检查期。

硬条件：

- 汉天子已脱离董卓直接控制，仍在世并保有可识别的汉帝政治身份。
- 中央权威虚弱，天子对外部诸侯实际可接触。
- 曹操或袁绍在世，具有独立决策和实际军事/政治能力，不是同一领地内的普通廷臣。
- 世界机会尚未被取得或终止。

曹操视角：

- 欲望：获得合法性和中央号令，同时承担朝廷财政、派系和猜疑成本。
- 选择：迎奉天子；只提供护送；拒绝；试图以更强控制方式接管。
- 历史 AI：极高概率迎奉，但性格、实力、关系和风险可改变结果。

袁绍视角：

- 欲望：决定是否把天子迎到河北，以及是否接受控制朝廷的政治成本。
- 选择：迎奉；观望/拒绝；提供有限援助；阻止竞争者。
- 若袁绍迟疑而曹操成功，袁绍故事记录“曹操控制朝廷”的战略事实，不另造天子。

世界竞争与结局：

- 首个完成合法迎奉的人取得世界机会所有权。
- 历史结局：曹操迎奉成功，形成可验证的朝廷控制关系。
- 非历史结局：袁绍迎奉成功，或天子由其他合格势力保护。
- 替代成功：角色仅护送/建立有限保护，获得较弱政治收益而不完全控制朝廷。
- 替代失败：行动中止、目标不可达、角色丧失独立权或死亡。
- 任何“摄政/二元权力”必须先验证 `try_start_diarchy` 成功，再设置 diarch；不能只写 flag 假定成功。
- 独立诸侯能否成为皇帝 diarch 必须以运行时验证为准；若引擎关系不支持，采用项目既有宫廷危机系统能表达的最小合法政治关系，不硬塞非法 scope。

即时后果与记忆：

- 合法性、威望、任官方面的工具，以及汉室忠臣的吸引力。
- 朝臣猜疑、派系紧张、供养朝廷的财政压力。
- 所有影响必须是有限、可解释、可清理的状态；不添加无边界永久 buff。

### 6.3 官渡：世界状态机会

开放窗口：198–203 年。

硬条件：

- 曹操、袁绍在世，均具有自主开战权，不是同一领地内普通廷臣。
- 袁绍已是河北主要霸主并有南下能力；曹操是中原主要霸主。
- 双方存在真实战略冲突，势力范围相邻或军事上可达。
- 官渡世界事件未发生且没有被不可逆地失效。

事件结构：

- 世界事件只负责形成决战机会、战争目标和参战态势。
- 曹操可选决战、守黄河、妥协、先清除其他敌人。
- 许攸投曹只有许攸在世、处于袁绍阵营、未被囚禁，并满足关系/家族压力；否则可用较弱的侦察粮仓替代路径。
- 乌巢只影响补给、士气、短期优势和战争压力，不施加永久削弱。
- 曹胜会打击袁绍威望和部属忠诚、提升曹操声势，但不瞬间吞并河北。
- 袁胜按战果分级；只有俘虏曹操、攻陷核心首府或控制天子等重大事实，才允许重大政治结果。
- 白和、失效、任一主角死亡均有终止处理。

四类结局：

- 历史：曹操在困难条件下获胜。
- 非历史：袁绍实际获胜。
- 替代成功：一方达成有限战略目标但未摧毁对手。
- 替代失败：决战机会因政治变化、不可达、主角失权或战争失效而终止。

### 6.4 赤壁：南征、联盟与实际战局

开放窗口：207–211 年。

硬条件：

- 曹操是北方/中原主要霸主，中原核心相对稳固并有南征能力。
- 荆州存在继承弱势或政治危机；刘琮投降由荆州世界事件依据实际角色和领地处理。
- 曹操选择继续东南进军。
- 孙氏控制江东且具有独立军力。
- 刘备仍保有独立军事力量；孙刘联盟实际形成后，才进入“赤壁”阶段。

系统性风险：

- 疫病、远征时长、水军经验、新附荆州兵忠诚、连环船、后勤和黄盖诈降分别成为可观察条件。
- 曹操玩家可以通过准备和选择缓解风险，不能被历史日期锁死。
- 孙刘阵营的合作程度、周瑜/鲁肃/黄盖等人物存在和关系影响方案质量；缺人时使用较弱的角色职能替代，而不是凭空复活。
- 曹操战败意味着远征结束、兵力损失和疲劳，不自动使整个国家爆炸。

四类结局：

- 历史：孙刘联军击退曹军。
- 非历史：曹操突破江防并取得实际战争胜利。
- 替代成功：曹操主动止损，或孙刘迫使撤军但联盟代价严重。
- 替代失败：联盟未形成、荆州局势改变、主角失权/死亡或战争不可成立。

### 6.5 入蜀与 LB-22 衔接

入蜀窗口：210–216 年，仅用于检查刘备既有链的阶段条件。

批准的既有因果：

- 刘璋受张鲁/曹操压力；张松、法正邀请刘备。
- 刘璋可邀请刘备、邀请其他诸侯、自守、与张鲁和解或依附曹操；历史 AI 高度倾向邀请刘备。
- 刘备以受邀盟友/客军身份进入益州，不立即变成刘璋封臣或无因开战者。
- 益州反刘璋人物的支持取决于关系、野心、恐惧和战况。
- 粮草争议、计划泄露、不信任或削减支援等破裂事实发生后，才形成战争理由。
- LB-22 的成功必须读取成都控制、刘璋投降或批准的益州核心控制事实；不能只看日期或事件选项。
- 失败时读取实际荆州：仍属刘备集团则返回；已经失去则流亡；留守者独立则发生重新依附/分裂处理。

本次修复边界：

- 若当前工作树确实缺少用户原有 LB-18～LB-22 文件，不自行重写整条早期线。
- 先恢复/接入能被现有用户结构调用的 LB-22 终局接口；只有所有者确认原链确实遗失且授权恢复时，才按另行审核的规格补回 LB-18～LB-21。
- 旧第二批 `Rushu` 日期启动器必须删除，不能成为替代入口。

### 6.6 LB-22 成功后的关羽任命

启动事实：刘备已满足 LB-22 益州成功结局，且仍有可处置的荆州政治权益。

事件目的：让刘备决定是否任命关羽为荆州最高统治者，并为 LB-24 提供可验证的政治和领地状态。

设计要求：

- 关羽必须在世且可被合法授予对应地位。
- 选项至少包括任命关羽和保持现有安排；历史 AI 高度倾向任命。
- 不得仅写人物 flag 伪装成统治荆州；必须与实际 title/政治制度一致。
- “荆州最高统治者”的精确落地（王国 title、实际公国/郡县集合、总督职位或项目自定义职位）是所有者审阅项，实施前必须锁定。
- 领地转让不得夺取刘备集团之外或受保护角色的土地。

### 6.7 LB-24 荆州覆亡

开放窗口：214–220 年；只有关羽实际控制荆州并进行北伐/对北方作战时才有意义。

关键条件：

- 孙—曹关系和现实利益。
- 糜芳、傅士仁是否存在、职位、关系、忠诚和恐惧。
- 荆州守备、兵力抽调、补给和关羽北线战况。
- 孙权必须有独立决策与执行能力。

流程：

- 关羽北伐形成机会，但不会因 219 年到来而必死。
- 孙权视角决定结盟、袭取荆州、继续观望或维持联盟。
- 荆州守将依据实际关系和局势决定坚守、投降或倒戈。
- 荆州归属和关羽命运由实际战争、围城、撤退、俘虏和处决事实决定。

结局：

- 历史：孙方夺取荆州，关羽死亡，满足 LB-25 的全部前置事实。
- 非历史：关羽守住荆州或成功撤退，孙刘关系转坏但不进入历史夷陵。
- 替代成功：孙方取得有限荆州利益，或刘备集团保住部分核心并撤出主力。
- 替代失败：北伐未形成、袭击不可执行、关键角色死亡/失权或荆州已由第三方控制。

### 6.8 LB-25 夷陵

开放窗口：220–224 年。

硬前提：

- 关羽已经死亡。
- 荆州实际落入孙权集团。
- 刘备在世、有自主战争能力，且复仇/夺回荆州仍具有现实意义。

刘备选择：

- 攻吴复仇（历史 AI 极高权重）。
- 接受诸葛亮战略，延续联盟。
- 只要求归还荆州。
- 延后复仇。

战争风险：

- 长补给线、山地、连营、陆逊的指挥、暑热分别影响实际战况。
- 刘备可以通过行动减轻风险；夷陵绝不能自动失败。
- 陆逊不存在或无权领军时，按孙方真实可用将领降级，不能凭历史姓名硬开效果。

结局：

- 历史：刘备进攻后实际战败。
- 非历史：刘备实际获胜并按战争目标处理荆州。
- 替代成功：外交取回部分诉求、有限胜利或在灾难前主动撤军。
- 替代失败：战争未能成立、第三方夺取荆州、刘备死亡/失权或复仇目标失去意义。

## 7. Story cycle 统一规范

依据原版 1.19.0.6 的 `_story_cycles.info` 和现有 story cycle 范例：

- `on_setup` 只初始化故事状态、保存必要 scope 和安排首次检查，不直接预写最终结果。
- `effect_group` 使用有限频率的天/月检查，避免每月全地图扫描所有角色。
- `triggered_effect` 或 `first_valid` 的每个分支必须互斥或具有清晰优先级，并提供 fallback。
- `on_owner_death` 默认清理并结束故事；不暗中转给继承人。
- `on_end` 清理临时 flag、变量、保存 scope 和 modifier；永久历史事实另行保留。
- 玩家可见故事必须有本地化标题、描述、图标/背景和进度状态；纯内部协调状态不滥用可见故事。
- 每个故事只有一个 owner，跨角色事实通过保存 scope 和世界 flag 协调。
- 任何 `make_story_owner`、转交所有权或延期都必须有原版语法依据。

## 8. AI、叙事与本地化规范

- 历史选择使用“极高但非绝对”的基础权重。
- 权重根据人物性格、关系、实力、恐惧、野心、健康、战况和政治利益进行合理修正。
- 不使用 `ai_chance = 100` 或唯一有效选项伪装历史倾向。
- 事件必须先交代当前可观察事实，再表达角色判断；不写上帝视角预言。
- 角色诉求保持区分：曹操重秩序与控制，袁绍重门第与联盟，刘备重汉室名分与集团生存，孙权重江东安全，关羽重名义与忠诚。
- 选项立即反馈、短期记忆和后续传播分层处理；避免一个选项同时堆叠领地、关系、战争、长期 buff 和大量隐藏状态。
- 所有新增事件、CB、故事、modifier、决议提示和战争结果必须有简体中文本地化；不得留下 `$missing_key$`。

## 9. 失败、失效与恢复矩阵

| 场景 | 第一批 | 第二批 |
|---|---|---|
| 目标不存在/无持有者 | 本脉冲不触发，窗口内可重试 | 机会保持未取得；条件恢复前不推进 |
| 战争建立失败 | 不生成军队；安全回滚 committed，窗口内重试 | 记录可恢复失败；不得写成历史结果 |
| 战争建立后首领死亡 | 按 CB 失效/继承规则结算并清军 | story 读取战争事实，进入失效或替代失败 |
| 目标换主 | 发动前重新解析 top ruler；发动后由战争 scope 管理 | 每次关键推进前重验世界状态 |
| 多目标分属不同 ruler | 只纳入选中 defender 所持目标 | 不把多个独立政治冲突强塞进一战 |
| 玩家改变历史 | 起义仍强制合法发动 | 玩家选择和实际胜负可产生非历史结果 |
| 角色失去独立权 | 起义按目标现状重算 | 个人故事失效或进入替代失败 |
| 日期窗口结束 | 尚未 fired 的起义永久错过 | 机会失效，不补发、不强制结果 |
| 存档已有旧 fired flag | 视为已处理，避免重复 | 通过迁移映射转为终态；不重新触发 |

## 12. 验证方案

### 12.1 静态验证

- 花括号、编码、BOM、本地化 YAML 和命名空间检查。
- 全量查找重复 event ID、story cycle ID、CB ID、flag 和 localization key。
- 校验所有 title、province、character、culture、faith、trait、MAA 和 script key 都存在。
- 按原版语法检查 effect/trigger 作用域；重点禁止在 effect 上下文直接使用 trigger。
- 验证多 `target_title`、`top_liege`、story owner、`on_owner_death`、`end_story` 和 diarchy 调用链。
- 九场逐项核对窗口、降级地点、兵种数量总和、人物数值、目标和 fired flag。
- 确认旧五个日期直启路径已不存在。
- 确认无缺失本地化、空姓名表、孤立 scripted effect 或未引用 CB。

### 12.2 启动验证

- 使用目标 1.19.0.6 版本启动到主菜单/书签加载。
- 检查最新 `error.log`、`game.log` 和必要的 crash bundle。
- 新错误必须按时间戳和标识符归因；不能用旧日志证明新版本通过。
- 任何崩溃后先读取最新 crash/log，再修改，禁止猜测式连续补丁。

### 12.3 第一批运行时矩阵

A. 标准历史开局：九场在各自窗口和条件下各发动一次。

B. 玩家是防守者：不得因玩家身份跳过。

C. 目标换主：攻击当前 top ruler，不攻击历史写死人物。

D. 多目标分裂：只取得同一选定防守者持有的目标。

E. 防守者已有其他战争：仍可合法发动。

F. 晚开局/越过窗口：窗口内可触发，窗口后不补发。

G. 进攻胜、防守胜、白和、战争失效：土地和军队清理均正确。

H. 首领死亡：不重生、不重复起义，战争按设计结束。

另对王国执行：同防守者并战、不同防守者另战、北宫已胜后三种专测。

### 12.4 第二批运行时矩阵

- 每条机会在“仅日期满足”时不得触发。
- 每条硬条件逐一缺失时不得推进。
- 曹操和袁绍竞争奉迎时只能产生一个世界结果。
- 奉迎成功、护送、拒绝、抢夺失败及主角死亡均能正常结束故事。
- 官渡曹胜、袁胜、有限结果、白和、失效均由实际战争事实结算。
- 赤壁联盟成立/不成立、曹胜、孙刘胜、主动撤军、关键将领缺失均有路径。
- LB-22 成功/失败读取真实益州和荆州状态；关羽任命与实际政治状态一致。
- LB-24 中关羽守住、撤退、被俘、死亡以及第三方夺荆州均可结算。
- LB-25 的四个刘备选项和战争胜负均不被日期强制覆盖。
- 保存/读取后 story scope、计时器和唯一世界状态不丢失、不重复。

## 13. 实施顺序（获批后）

1. 为第一批现有缺陷建立可复现静态检查，逐项修复九场数据、scope、战争目标和生命周期。

3. 建立第二批唯一世界状态和 story cycle 骨架，以测试先行验证启动、失效、死亡和终局。
4. 实现奉迎天子，再接入官渡、赤壁世界机会。
5. 移除旧日期直启器，接入 LB-22 既有接口，实现关羽任命、LB-24、LB-25。

7. 经所有者授权后执行启动验证和完整运行时矩阵；失败则读取最新日志并迭代。
