- **选项**：庙号大类选项（001.a–e）、自拟选项（001.j、011.zdy、092.a、008.a/b）、确认与加字选项（009.a/b、012.b）都改成文言短句。
  - 谥法释义加名号的选项（003–007、011、015、081、082）保留古籍原文。只做了两处修订：
    - 改掉"先帝"二字。原因见下一条。
    - 修正两处释义错误，见 §6。
- **共用键**：谥字选项 `HuangDi_miaoshi.011.*` 和 `.shturl` 同时被公王议谥（`WJ_rf_shihao.1/.3`）使用。原文"定先帝谥号为"用在公王身上就错了，现在统一改为"定谥为"。
  - 庙号选项（003–007）只用于天子，仍保留"先帝"。
- **特质描述**：
  - 六个评价特质（开基/中兴/明君/守成/幼主/昏君）改为原版式"该角色……"。
  - 70 个庙号特质 `SanGong_miaohao_NN_desc` 统一为"{谥法释义}，故上庙号曰{庙号}。"，例如"肇造区夏、始受天命，故上庙号曰太祖。"这样写是因为 `WJ_tianjia_history_on_actions` 也会把这些特质授给真实的东汉皇帝（光武、明、章、和、安、顺、桓），描述里不能出现"你"或"先帝"。
  - 自拟庙号特质改为"嗣君亲拟庙号，取「…」字。"
- **实封/封爵**：
  - 决议 desc 改为第一人称内心独白（原版惯例）。原来写在 desc 里的资格条件，移到 `is_valid` 的 `custom_description` 中，见 §2。

## 2. 效果改动清单

**游戏效果未改动。** 脚本改动全部在显示层或交互一致性上：

1. **`events/WJ_peerage_events.txt` · `WJ_peer.010`，30 个地点选项（`WJ_peer_slot_1…30`）**
   - 改前：选项上只有 `custom_tooltip = WJ_peer_choose_place_tt`。册封王爵（rank 4）时，`WJ_peer_finish_grant` 会在 hidden_effect 里暗扣 50 金、50 虔诚、50 影响力，玩家从头到尾看不到。
   - 改后：每个选项加了 `if = { limit = { var:wj_peer_pending_rank = 4 scope:wj_peer_slot_N ?= { tier = tier_duchy } } show_as_tooltip = { remove_short_term_gold = 50 add_piety = -50 change_influence = -50 } }`。只有在王爵流程里、而且点的是会直接册封的郡级地点时，才显示真实花费。点州级地点只是进入下一级，不显示。
   - 理由：§1B.3，隐藏结算须用 `show_as_tooltip` 显示真实效果。
2. **`events/WJ_peerage_events.txt` · `WJ_peer.021`（袭爵通知）**
   - 改前：`desc = WJ_peer_awarded_desc`，与受封通知共用。正文里"爵命送到，先听宣读"对袭爵来说不成立。
   - 改后：`desc = WJ_peer_inherited_desc`（新键，承袭先人册书的叙事）。
3. **`events/WJ_peerage_events.txt` · `WJ_peer.001` 选项 `WJ_peer_rank_1`（亭侯）**：这一条应 U07 转交的建议而改。
   - 改前：trigger 里只判断非同宗，"军功或政绩 ≥25"只在 hidden_effect 的 `WJ_peer_rank_allowed` 里检查。不达标时选项照样能点，流程会静默中止。
   - 改后：trigger 补上 `OR = { has_trait_xp … jungong ≥25 / zhengji ≥25 }`，与县侯选项（≥50）的写法一致。文案"受封者的军功或政绩须达25"从此有了对应的条件。
   - 实际影响很小。`WJ_peer_base_candidate` 已经要求非宗室男性 ≥25，所以这一条主要是让文案和条件对得上。
4. **`common/decisions/WJ_real_fief_decisions.txt`，三个决议的 `is_valid`（逻辑未变，只加了 custom_description 外壳）**
   - `WJ_rf_request_decision`：
     - `WJ_rf_duke_qualification = yes` → `custom_description = { text = WJ_rf_request_valid_tt … }`
     - `NOT has_variable wj_rf_target` → `WJ_rf_no_pending_tt`
   - `WJ_rf_expand_decision`：三项条件分别包上 `WJ_rf_expand_liege_tt`、`WJ_rf_expand_cooldown_tt`、`WJ_rf_no_pending_tt`。
   - `WJ_rf_promote_decision`：`WJ_rf_can_promote = yes` → `WJ_rf_promote_valid_tt`。
   - 理由：原 desc 是条件清单，按 §1E 改为叙事后，条件应由 `is_valid` 以原版式条件句显示（§1C），以免引擎展开 `has_variable`、脚本值等原始条件。
   - 冷却条件的措辞：`WJ_rf_commit` 在**初次受封**时也会给受封人设 3 年 `wj_rf_cooldown`（见 `WJ_real_fief_effects.txt` 第 299 行）。因此 `WJ_rf_expand_cooldown_tt` 写作"距你受封或上次益封已满三年"，同时涵盖受封和益封两种情况。
   - `WJ_rf_pick_desc` 末句写作"旧有的长吏大多仍守其职，只是从此改隶封国"。`WJ_rf_transfer_duchy` 会把国都所在县，以及天子或王级以上直辖的县转给受封人，其余县的长吏只是改换上级。所以用"大多"，不写成全部。
