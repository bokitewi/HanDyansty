### 主要处理

**正文**
- 全部由"我"改为第二人称"你"，删去"实际/真实/复检/核验/回执/结算/履约/本案/不另"等残留。
- 菜单式写法（"我可以……也可以……"）改为场景描写。

**多读者事件**
以下回执改为点名叙述，用 `scope:<记录>.Var('…').Char` 取人名，避免"你"指代错位：
- ord.0119 / 0219 / 0319：来客与保人，0319 另加主君
- support.0108 / 0308：宣称者与受邀者
- par.1101 / 1201 / 1202：出资者、守令、两党魁
- com.0004：答复者，还价后变为原提议人

**提议书（`*_terms`）**
- 原为"条款清单"，现改为"某某致书某某""某某复书某某"的书信体。
- 只用第三人称点名，不用你我，因为还价条款双方都会读到。
- 删去"复检""文书只有金钱与释放条款""两人都获释才算履约"等契约腔。
- 保留与脚本一致的期限与金额，用汉字书写："百金""谢仪三十金""三月不复，此议作罢""一年之内此席不复更易""三月之内具名回奏"。

**选项**
- 全部改为文言短句，如"百金赎之，勿复多言。""以俘易俘，各归其主。""论人当论其行，不论其父。""朕之席次，不容宗亲置喙。""君昔欠我一诺，请罢兵一年为偿。"

**效果提示**（详见 §2）
- 删除逐条复述数值的手写提示，改由引擎显示。
- 对方答复后才生效的效果（延迟效果）：一句叙事 + `show_as_tooltip`。
- 选项效果在执行中途才判定成败的（先设变量或付款、再按结果分支），引擎提示会显示错误分支或什么也不显示。这类改为 `show_as_tooltip`（成功结果）+ `hidden_effect`（真实调用）。

## 6. 自拟项与不确定处

1. **ord.0019.c 的 30 金**：原文是"书信事务费用、实际支付青年"，叙事很别扭。现改写为"赠来客一份薄礼以示诚意"，脚本不变：仍是主君付给来客 30 金。
2. **support.0008.d 选项"君昔欠我一诺"**：`use_hook` 可能是恩情，也可能是把柄。措辞按恩情写；用把柄时略显温和。
3. **提示显示的前提**：我按"CK3 生成提示时按当前状态评估 `if` 的 limit，不执行之前的 `set_variable`"来处理。
   - 凡分支依赖本次效果里刚设的变量或付款结果的，一律改为 `show_as_tooltip` + `hidden_effect`。即使引擎实际行为不同，这样写也不会重复或误显示。
   - 预览只列主要效果，从略：
     - 求助成功时宣称派系封臣 −10
     - 换俘时双方家属 ±10
     - 其余宗亲 −15（只显示被挤者）
     - 其他候选 −10
4. **以下死变量需用户拍板（只报告，未修）：**
   - `hd_dc_x`（矛盾）、`hd_dc_m`（动员）只有 `change_variable` 写入，全 mod 无读取。原提示写的"矛盾−5""动员+10""冲突值−15"等实际不起任何作用，现已从文本中去掉。
   - `hd_dc_ritual_pledge_breach_date`（roy.0102.b 失约）和 `hd_dc_major_uncorrected_breach`（保护盟书违约）同样无人读取。"食言""不得无故拘押处死"目前只是叙事，没有后果。
   - 是否要给这些计数和违约接上实际后果，需用户决定。在此之前，0208.a.tt 写成誓言，0102.b.tt 写作"食言"，都只作叙事，不暗示有惩罚。
5. **ransom 退款**：`hd_dc_refund_ord09_payment_effect` 对扣押者仍用 `add_gold = { … multiply = -1 }` 扣回。若引擎确实拒绝负值，退款会失败。这条与文案关系较远，按规范只报告，未改。
6. **调停还价**（`hd_dc_roy01_mediation_written_terms`）：与原条款在脚本上没有任何差别，只是措辞（请求载入宗册）。保持原设计。
7. **保留的数字型数据**：都是事件内容本身（账目、席次、许诺数额），保留 `GetValue`。
   - par.1302 核账回报中的拨出/到账金额与控制、发展的起止值
   - roy.0102 的席次
   - support.0008 的酬金数
8. **叙事中的汉字数量**（百金、三十金、五十金、三月、一年、五年、"第 N 席"）均与脚本一致：
