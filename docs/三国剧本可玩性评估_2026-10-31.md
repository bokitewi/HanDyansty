# 三国鼎立组三剧本可玩性评估（2026-10-31）

范围：书签组 `bm_hd_group_sanguo` 的三个剧本——218「三足鼎立」、253「姜维北伐」、263「钟会伐蜀」。
方法：只读静态审查（HEAD e386c1ad），未改任何 mod 文件，未进游戏。
- 主线程：按开局日重放全部 `history/titles`，算各势力的县数；查游戏日志和当前启用的模组列表；复核三路子审查报上来的 P0/P1。
- 三路子审查：每个剧本一路，逐个人物、逐个节点读代码。
- 标注：
  - 「已复核」：主线程亲自读代码确认过；
  - 「子审查确认」：子审查读码确认，主线程没有逐条复核；
  - 「推断」：静态读不出来，需要实测。

## 一、跨剧本问题（先处理）

### X-1｜P0｜环境｜已复核：旧的工坊议和子模组仍与主 mod 同时启用
- 证据：
  - `E:\documents\Paradox Interactive\Crusader Kings III\dlc_load.json`（10-30 16:19）启用了 `HanDyansty`、`ugc_3820784621`（工坊「汉晋春秋·议和与战争结算」，10-29 08:30 的快照）、`HanJIn_Clothes`。
  - 子模组的 `descriptor.mod` 写了 `replace_path="common/casus_belli_types"`，加载顺序排在主 mod 之后。
- 后果：
  - 主 mod 的整个宣战理由目录被替换。子模组的 `zz_hd_sg218_war_cb.txt` 里只有 `hd_sg218_war_cb`，所以 218 的**白衣渡江 `hd_sg218_baiyi_cb`、襄樊 `hd_sg218_xiangfan_cb` 不存在**。10-30 的 error.log 里有 50 多条 `Can't find casus belli Type`。另外缺 `hd_warlord_cb`、`zz_hd_89_war_cb`、`zz_hd_j16_border_cb`，10-21 已删的旧 CB 文件则复活。
  - 子模组整份覆盖了 253 的三个文件：
    - `zz_hd_253_history_effects.txt`：旧 562 行，现 961 行；
    - `events/zz_hd_253_events.txt`：旧 602 行，现 784 行；
    - `zz_hd_253_beifa_cb.txt`：旧 452 行，现 513 行。
  - error.log 里那些 `hd253_fashu_tries`、`hd253_guanqiu_war_ok`、`hd_hev_253_*`「用了但没设」的报错就是这么来的：旧文件里这些变量出现 0 次，现文件里都有设置。
- 结论：只要这个子模组还开着，218 的荆州线和 253 的整条链跑的都是旧代码，或者干脆断掉。按 10-29 的记录，子模组「不能与主 mod 同开」。
- 处理：在启动器里把 `汉晋春秋·议和与战争结算` 从播放集移除，或者在工坊下架、更新。这一步只能由你操作。

### X-3｜P1｜议和整合副作用｜已复核：剧本战争只能打满 100 分才结束，没有超时
- 证据：
  - `events/hd_peace_monitor_events.txt:12-16`：专用战争只在任一方 ≥100 时自动结算。
  - `gui/window_war_overview.gui:1334/1364/1390`：原版的投降、白和、强制胜利按钮都设了 `visible = no`。
  - `common/scripted_guis/hd_peace_routing_guis.txt`：结算按钮同样要求 ≥100。
- 影响：
  - 218 的全部战争（汉中、襄樊、白衣、夷陵、北伐……）、253 的新城、北伐、起兵，263 的伐蜀，都属于专用战争。
  - 战事一旦僵持，玩家没有任何退出办法，链条就挂着不动：
    - 218 汉中僵持时，襄樊（要求 `liu_got_hanzhong`）和吕蒙入口一（要求汉中不在打）都到不了，荆州到夷陵整段冻结。
    - 253 新城僵持时，毌丘俭一直在战中，他起兵的节点（要求 `is_at_war = no`）就无限往后推。
  - AI 对 AI 时引擎还会不会原生白和：推断，需实测。
- 修复方向：在心跳里给剧本战争加超时，例如满 N 个月按战分判胜负或白和；或者让剧本 CB 支持按时间累积战分。253 的非接力局节点也要补 `_late` 截止日期。

### X-4｜P1｜推断（关键代码已复核）：脚本用 `independence_war` 起兵，可能被郡国制政体挡掉
- 证据：
  - `common/casus_belli_types/00_civil_war.txt:1823-1827` 的 `allowed_for_character` 要求攻方 `NOT = { government_has_mechanic = administrative }`。
  - 天朝政体 `common/governments/zz_WJ_celestial_government.txt:4` 是 `mechanic_type = administrative`。
- 影响：
  - 253 的毌丘俭、诸葛诞起兵（`hd253_rebel_effect`），263 的钟会起兵、邓艾拒命、姜维拒命或复汉（`hd263_rebel_effect`），全部用 `independence_war`。
  - 如果脚本 `start_war` 也检查这个条件，这些起兵都会失败：253 重试 3 次后放弃，263 只写一行 `HD263 REBEL_WAR FAILED`，节点就静默消失。
- 实测关键字：`HD253 REBEL_WAR FAILED / REBEL_GAVE_UP`、`HD263 REBEL_WAR FAILED`。
- 补充（已复核）：`hd263_rebel_effect`（`zz_hd_263_history_effects.txt:46-74`）**没有**设 `hd_peace_scripted_war`。253 的同类效果设了（`zz_hd_253_history_effects.txt:578`），约定写在 `docs/议和系统_说明.md:75`。所以即使 263 的起兵能宣出来，也会当成普通独立战，走和约系统结算。

- **253-07｜P2｜推断** 司马师死后，hd_court 在第 2 天自动立继承人为权臣，253 在第 3 天才发 0600；0600.b「亲揽朝政」不解除权臣，可能无效。
- **253-08｜P2｜推断** 新城和伐蜀的目标经过连通筛选，可能退化成郡或州目标，而胜利结算只转目标头衔本身（与 263-02 同源）。
- **253-09/10｜P2**：10-18 新加的键缺英文（0595、0700_shi、0715）；诸葛恪的书签头衔 d_lujiang 开局就交给了郡守，书签显示与实际不符。
