**归段规则（审查 10-26 补）**：跨年多跳节点按**窗口起点**归段；窗口起点早于本段下界的节点不得编入本段（例：A4 王恭出镇京口窗口 392 起，已由 E5-J12 改号 E4-J97）。

**首跳全段扫一次（必须）**：
- 只按日期粗筛有漏洞：开局晚于某时代时，该段永远不会进入，段里新节点的自保护（§3.1）一次也不执行，done 就设不上。
- 例子：370 开局里，E2 的「东晋建立」没有 done，而它是 E4-J10 废立的上游，于是 E4-J10 会一直等到截止日、然后跳过。
- 改法：每段的粗筛写成 `OR = { <日期区间> NOT = { has_global_variable = hd_j16_eN_swept } }`，执行一遍后设 `hd_j16_eN_swept`。卒年的十年分段也照此处理。
- 节点内部都有截止跳过分支，所以全段扫一遍不会让任何节点误触发。

## 4. 人物解析

### 4.1 统一解析效果与触发器【R4 §2.3；参数名为本草案自拟】

```
hd_j16_resolve_effect = {        # 参数 ID、AS
    if = { limit = { character:$ID$ ?= { is_alive = yes } } character:$ID$ = { save_scope_as = $AS$ } }
    else_if = { limit = { hd_hb_alive = { ID = $ID$ } } global_var:hd_hb_p_$ID$ = { save_scope_as = $AS$ } }
}
hd_j16_alive_trigger = {         # 参数 ID
    OR = { character:$ID$ ?= { is_alive = yes }  hd_hb_alive = { ID = $ID$ } }
}
hd_j16_dead_trigger = {          # 参数 ID；在库中且已死
    OR = {
        character:$ID$ ?= { is_alive = no }
        AND = { has_global_variable = hd_hb_p_$ID$  global_var:hd_hb_p_$ID$ = { is_alive = no } }
    }
}
```

写法依据：
- 指针一侧照搬现成的 `hd_hb_alive`（`common/scripted_triggers/zz_hd_hbirth_triggers.txt:11-17`）：先判 `has_global_variable`，再取指针。这样变量不存在时不会报错。
- `character:` 一侧沿用已经在用的 `?=` 写法（`zz_hd_nbc_history_effects.txt:206`）。
- 这段每 30 天要跑约 200 次，一条报错就会刷满 error.log。上线前抽一跳的 error.log 核对。

| 规则 | 内容 |

| 解析顺序 | 先取 history 原生人物，再取 hbirth 指针（开局时未成年的原生人物，要到出场年才写指针，所以两头都要试） |
| 宏参数命名 | 一律用 `ID`。生成器正则 `\bID\s*=` 能自动把它们收进指针名单（§4.2） |
| 存活判定 | 两处都加 `is_alive`：指针在载体死后仍指向死人 |

### 6.1 合并与分类

| 类 | 含义 | 效果 | 前提不成立时 |
|---|---|---|---|
| N 普通 | 病死、老死 | `hd_j16_death_effect = { ID DATE }` | 不适用 |
| K 被杀 | 史实上被杀、被处死、战死，但不涉及「结局」 | `hd_j16_death_kill_effect = { ID DATE REASON KILLER }` | （已被 D15 覆盖，见文首）前提不成立（含凶手取不到、已死，前置节点未 fire）时顺延；史料卒年满 10 年仍不成立，改按 N 类病逝。原写：凶手取不到或已死时照日期自然死（F4） |

- **合并**：三张表共 61 条，没有冲突（R4 §2.5）。表值与 history 不一致的 15 人，以表值为准（R4 附录 B）。
- **扩表**：D12 由脚本扫描 history，挑出死于 304–421 年、带 `historical_character`、并且是君主、储君、权臣、名将或节点当事人的人，生成候选 tsv，再人工裁剪。R4 附录 C 的 57 人和 R5、R6 列出的卒年问题要先并进来。
- **数据源**：★`docs/两晋十六国_卒年表.tsv`（列：ID、中文名、日期、类别 N/K、死因、凶手 ID、出处、备注）→ 脚本生成 `zz_hd_j16_deaths_effects.txt`，按十年分段，每段外层用 `current_date >= 段起 且 < 段止 + 3 年` 粗筛（F10）。

### 6.2 单条卒年的判定流程【自拟】

1. 已设 done → 结束。
2. `current_date < DATE` → 结束。
3. `hd_j16_dead_trigger`（人在库里但已死）→ 设 done，结束。
4. 解析不到人（hbirth 尚未出场，或指针随载体丢失，要到次年元旦才补出）→ 计数器 `hd_j16_dmiss_<ID>` 加 1。满 24 次（约 2 年）后设 done，记 `SKIP missing`。理由：现状是取不到人就立刻设 done（`zz_hd_nbc_history_effects.txt:206-208`），改成解析后，指针短暂缺失会把这条卒年永久吞掉。
5. 解析成功、是 AI → 执行死亡（N 用 `death_natural_causes`；K 见 6.4），设 done。K 类先查前提，不成立按 D15 顺延，到 DATE + 10 年转 N（10-27，见文首）。
6. 解析成功、是玩家 → 走 6.3 的病笃事件（K 类见 F6）。

### 6.3 病笃只能强撑一次（D10）

| 项 | 改法 |
|---|---|
| 事件 | 沿用 `hd_nbc.0100`（`events/zz_hd_nbc_events.txt:81-103`），ID 不变 |
| 选项 b「强撑」 | 加 trigger：`NOT = { has_variable = hd_j16_endured }`。效果在原有内容上再设永久人物变量 `hd_j16_endured`。事件里没有 $ID$ 可用，所以不能用 R4 建议的按 ID 命名的全局变量 |
| 再次弹出 | 一年的 `hd_nbc_death_delay` 到期后再弹。第二次只剩选项 a「交代后事」：用 `triggered_desc` 换成交代后事的文案；选项 a 之前可以加一个无代价的「立嗣 / 托孤」提示。【自拟】 |
| AI | 不变，到日直接死亡 |

### 6.4 死因与凶手（F5）

- ★K 类写成 `death = { death_reason = <REASON> killer = scope:hd_j16_killer }`。凶手同样用 §4 的方法解析（已被 D15 覆盖：取不到或已死属前提不成立，顺延；只有史实本无凶手的部众所杀、自缢、投水才留空 killer，见文首）。
- REASON 取原版死因：`death_murder`（暗杀、毒杀）、`death_execution`（处斩、赐死）、`death_battle`（阵亡）。具体用哪个，以原版 `common/deathreasons` 现有的键为准，开工前核对。
- 宏参数没有可选写法，所以 N 类和 K 类分成两个效果。
- 顺带清理：R7 指出 history 里有 112 处 killer 写成中文，R5 指出 2 处无效引用。这些开局前的条目由人物数据那一节处理；开局后的被杀者一律进卒年表，凶手写 ID。

### 6.5 hbirth 生成的人

- 生成器不写死亡，hbirth 生成的人只会自然老死、病死，或死于事件，不会在史实卒年准时死去（R4 §0-3）。
- ★只把要角放进卒年表（D12），不让 hbirth 给所有人按卒年处死（F11）。

### 7.2 禁止事项

1. 不给无地者凭空建国（D16 授郡例外不算凭空建国；授郡后是否独立以各节已拍板分支为准，如 A6-F3 西凉、A4 E4-M20 选项 b、A3-F13 拒之即内战，没有这类分支的保持原政权封臣）。只有标为「严格」的节点（冉闵建魏、苻健入关、卢循据番禺、石勒称王）在严格局面条件下可以这样做（R4 §3.2）。
2. 不为了凑节点条件而生成政权、销毁政权，或成片转移王国级以上的头衔。
3. 不在没有选项的情况下夺走玩家的头衔，也不直接杀死玩家角色（卒年见 6.2-6）。
4. 不新造虚构人物充当史实当事人。
5. 不用 `every_living_character` 扫人。
