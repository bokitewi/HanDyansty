## 3. 实施方式

- **暂存与落盘**：代理只写暂存区。汇总人用 apply.py 落盘，落盘前查 ck3.exe 是否在运行、查原文件哈希是否未变，并先备份。
- **闸门**：gate.py 与基线比对。每次落盘后重建基线。
- **工作流**：每个任务都走「实施 → 独立审查 → 修正」三步。收尾另加全线复核和对抗核实。
- **排程偏离**：08 §9 规定「期间串行」、§1.2 规定节内单链。实际按文件分路并行，例如 3-B2 自建 304b 文件、由 3-B1 的入口调用，4-C、5-A2、6-N1、6-N2 同理。各期之间也有交叠：4-A/4-D 和 5-B/5-C 先行，5-A 与 4-B 同跑，跨节接口名由汇总人事先定好。
- **会话额度中断三次**：都用 resumeFromRunId 续跑；中断的实施任务在已有暂存上续做。
- **生成器**：
  - hbirth、popclean：第 2 期末跑一次，收尾再跑一次；
  - hd_fo：收尾跑；
  - 卒年表生成器：每次改 tsv 都重跑；
  - 纹章：第 2 期只追加 24 个新王朝。

### 8.1 闸门剩余项（08 §6-5 要求逐类说明）

本线文件中，闸门仍然报出的条目都是带 `$参数$` 的变量名。gate.py 跳过参数化写法，所以认不出这些变量的设置处：

|---|---|
| `hd_j16_<KIND>_started` / `_att` / `_def` / `_key` | 宣战工具：hd_j16_b4_war_go_effect、hd_j16_b1_war_effect、hd_j16_304_army 等，以 `$KIND$` 拼名 |
| `hd_j16_<KIND>_won` / `_lost` | 结局宏 hd_j16_304_war_result_effect，以 `$KIND$` 拼名 |
| `hd_j16_<KEY>_go` / `_asked` / `_wait` / `_skip` | 问询与跳过工具：hd_j16_b4_ask_effect、hd_j16_b4_reply_go_effect、hd_j16_b1_usurp_rebel_effect、hd_j16_304_skip_effect，以 `$KEY$` 拼名 |
| `hd_j16_<步>_heir_done` | R-继统工具 hd_j16_304b_rjt_effect，以 `$KEY$` 拼名 |
| `hd_nbc_<KIND>_active` | hd_nbc_start_war_effect、hd_j16_border_start_war_effect，以 `$KIND$` 拼名 |
| `hd_nbc_<KIND>_won` / `_lost` / `_white` / `_invalid` | 结局分发表 hd_nbc_war_result_kind_effect，以 `$KIND$_$RESULT$` 拼名 |
| `hd_j16_border_<KIND>_target` | hd_j16_border_start_war_effect |
