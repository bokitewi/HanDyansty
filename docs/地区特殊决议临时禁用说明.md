## 当前禁用方式

八个现有 `is_shown` 块的首部都加入同一组临时门闩：

```text
is_shown = {
	# 临时禁用：恢复时删除本注释及下一行 always = no。
	always = no
	原有显示条件……
}
```

`always = no` 会使决议不显示，因此玩家和 AI 都无法从决议入口启动它；其余显示条件、可用条件、花费、效果、事件链和清理逻辑均保留。现有文件中的 `ai_potential = { always = no }` 也保持不变，它不是本次临时门闩。

- `events/zz_hd_regional_decision_events.txt`：五石散、蜀道、南蛮、内迁、极西、夷州和两汉分治的事件链。

## 恢复步骤

1. 打开 `common/decisions/zz_hd_regional_decisions.txt`。
2. 在上述八个 `is_shown` 块中，逐处删除成对的临时内容：`# 临时禁用：恢复时删除本注释及下一行 always = no。` 和紧随其后的 `always = no`。
3. 保留每个块中原有的第一条判断及后续判断，不要删除或重排其他条件。
4. 按下方静态检查确认八个块都已回到原始条件首部；本次恢复不需要改事件、效果、变量、`on_action` 或本地化文件。

## 静态验证命令与边界

在 mod 根目录的 PowerShell 中，可用以下命令定位八处门闩：

```powershell
rg -n '^\s*is_shown\s*=\s*\{|^\s*# 临时禁用：|^\s*always\s*=\s*no\s*$' -- common/decisions/zz_hd_regional_decisions.txt
```

应再用逐项契约检查确认八个决议键的 `is_shown` 首个非空行均符合预期：禁用状态为 `always = no` 共 8/8；恢复状态则应为各自原有条件、且临时注释和门闩均为 0 处。括号平衡和差异检查可使用：

```powershell
$p = 'common/decisions/zz_hd_regional_decisions.txt'
$t = Get-Content -Raw -LiteralPath $p
if (($t.ToCharArray() | Where-Object { $_ -eq '{' }).Count -ne ($t.ToCharArray() | Where-Object { $_ -eq '}' }).Count) { throw 'brace count mismatch' }
git diff --check
```

这些检查只覆盖文本层面的门闩位置、括号数量和 Git 空白错误；不等同于 CK3 引擎解析、决议界面、事件执行、变量清理或存档行为验证。本次工作不启动游戏，也不修改英文文本。
