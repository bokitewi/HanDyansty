# 历史入侵（184–600）设计草案

参考 Historic Invasions Fix and Addon（创意工坊 3599748822）的“故事循环 + 分阶段征伐”写法，在本体里自建前缀 `hd_hi_` 的独立框架，不依赖 HI 本体。
与已有系统不重叠：五胡大单于（刘渊、石勒、李特、苻洪、姚弋仲）、僚人入蜀、REV-01～09 史实叛乱都不在本系统内。

## 1. 原则（用户定稿）

- 只由史实人物本人推进。本人未出场就等，本人死亡、被俘、失能或放弃，这场入侵就结束。**永不生成替身。**
- 环境合适就直接起兵；环境不合适（盛世，或目标过强）就舍下根基，变成带宣称的强力冒险者，在故地每年复查，时机一到再起兵。
- 本人有地时弹事件让本人选：电脑在最高头衔为公爵及以下时选历史入侵，高于公爵时选安守。

## 2. 流程

1. **每年检查**（`yearly_global_pulse` 子 on_action，每场一个）：规则开启、在窗口内、未发生过。本人已死或过了窗口 → 记为已发生。本人在世、成年、未被囚、未失能、没有进行中的入侵 → 掷骰：平时 5%，史实年前两年 15%，史实年 40%，窗口最后一年 100%。
2. **开始**：建故事 `story_hd_hi_invasion`（数据存在故事上），隐藏事件 `hd_hi.0100` 评估环境并分流。
3. **环境评估**（当前阶段的公爵领）：
   - 盛世（天朝循环 stability / stability_expansion / stability_advancement）且目标在汉地 → 不合适；
   - 治世中，目标里占地最多的是天子（持有 h_china）→ 不合适；
   - 目标七成以上伯爵领归同一家，且其兵力超过本人兵力加起事兵马估值的两倍 → 不合适；
   - 其余合适。
4. **分流**：玩家本人或有地的本人 → 事件 `hd_hi.0200` 自己选；无地且主上是玩家 → 事件 `hd_hi.0300` 问主上放不放人；其余直接起兵或蛰伏。
5. **起兵**：封臣脱离主上；无地者在故地立营；获得“乘时而起”加成、钱财、威望和一支常备部众；其他玩家收到通报（可改扮此人）；电脑本人立即宣战。
6. **蛰伏**：有地者把领地交给继承人；在故地立营；对第一阶段的公爵领和王冠取得强宣称；同样获得加成与部众；第一阶段有地的玩家收到警讯。每年复查，合适就起兵。
7. **征伐**：每 60–180 天检查一次（`hd_hi.2001`）。当前阶段八成伯爵领已归本人 → 第一阶段后取王冠、定国号，最后阶段后结束；否则电脑本人向当前阶段占地最多的对手宣战（排除停战与已在交战的对象），并生成一支事件军。玩家本人用决定“进取下一处”宣战。
8. **战争结果**：胜利夺取守方及其电脑封臣在本阶段各公爵领内的头衔，冒险者得地后改为本场设定的政体；失败时无地者退回蛰伏，有地者就此罢手。本人阵亡则战争失效。
9. **王冠**：遵守天朝循环的建国限制（`hd_cycle_title_creation_allowed_trigger`）。王国未创建则创建，被电脑（非天子）持有则篡夺；改国号并写入王朝固定国号（`hd_fixed_realm_name`）。

## 6. 实测要点

- 控制台把年份推到窗口内（或直接 `effect` 调 `hd_hi_begin_effect = { KEY = <场次> }`，作用于本人），看 0200/0300 事件、起兵或蛰伏是否符合环境。
- 盛世下应蛰伏：本人变冒险者、有宣称，第一阶段有地的玩家收到警讯。
- 起兵后检查宣战对象、事件军规模；战胜后头衔转移、阶段推进、王冠与国号。
- 本人死亡后故事结束、战争失效，不会出现替身。
