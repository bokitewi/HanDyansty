# 原版机制停用（空壳）全面审计 · 2026-11-01

只读审计，**未改任何 mod 文件**。对照原版 CK3 1.20.1.2（`D:/SteamLibrary/steamapps/common/Crusader Kings III/game`），比对时 HEAD 为 a47f9453。审计脚本在 `tools/hd_stub_audit/`，用法见其中 README。

## 一、结论摘要

**扫描结果**
- mod 覆盖了 2155 个原版同路径文件或同名定义。按块比对后，共找到 **1645 个被禁用的原版定义**。
- 禁用写法有三类：事件改成 `hidden = yes trigger = { always = no }`；决议、宣战理由的门槛改成 `always = no`；脚本效果清空成 `{ }`。
- 另有 **6000 多个原版定义**因同名文件整文件替换而消失。其中 5574 个是地形映射，属地图替换，正常。

**分类**
- 约 **1400 个**是欧洲、中东、印度、日本、蒙古等本图不存在的地区内容，属有意剥离，保持即可。
- 剩下的才是问题，可分三类：
  - **工具误伤**：通用机制被整个关掉，只因为某个配图、描述或某一个分支引用了本图没有的头衔；
  - **旧副本**：mod 拷的原版文件比 1.20 老，与已是 1.20 的调用方对不上；
  - **整文件遮蔽**：同名文件把原版整个文件替换掉。

**最严重的 8 条**（详见第三节 P1）
1. `common/on_action/game_start.txt` 只有 44 行，把原版 7356 行的开局脚本整个遮蔽了。
   - `game_has_started` 全局变量从未设置，天朝循环的「霸主任用低贤总督」诱因永远不会触发。
   - 开局正统性、多条游戏规则（性别平等、同性、随机信仰等）、宫廷威仪初值、开局加冕法，都没有代码执行。
   - 圣地圣物事件、开局王冠事件虽在 mod 里，但没有任何地方调用。
2. **拜谒本地神祠**（`local_rites.1`）是空壳。儒、道和多数佛教仪轨都带本地神祠教义，人人能看到这个决议，点了什么都不发生，还白扣 5 年冷却。
3. **战争胜负给正统性**（`war_end_legitimacy_effect`）被清空。约 89 个宣战理由的战后正统性增减全部失效。
4. **AI 冒险者换王国**（`ep3_adventurer_ai_contract_find_next_kingdom_effect`）被清空。AI 冒险者在一国把雇主用完后就停摆。
5. **开朝会、向君主请愿**两个决议被整个关掉，唯一原因是配图里引用了 `b_constantinople`。原版宫廷界面的这两个按钮因此消失。
6. **更换国教、改奉国教**被删：`ep3_decisions.txt` 整文件清空。
   - 天朝政体允许国教，mod 自己的 `gui/window_government_administration.gui:1130/1146` 还在引用这两个决议。
   - 同一文件里还有「钓鱼」（冒险者）等通用决议一起被删。
7. **约 26 个原版行政帝国年度事件被一刀切**（`ep3_emperor_yearly_2` / `_8`）。按事件顶层触发条件核过，它们只要求行政机制（`government_has_mechanic = administrative`）或总督身份，天朝政体能过。
8. `war_for_imprison_effect` / `war_for_retraction_effect` 还是旧的无参数版，原版 `yearly.3001` 传参报错，开战选项失效（error.log:8783）。

## 二、方法

**比对范围**
- `common/**` 与 `events/**` 的顶层定义，`replace_path` 目录除外。
- 同名文件替换和跨文件同名覆盖都算；多份定义时按最后加载的那份判断。

**检测内容**
1. 定义整体清空或改成 `always = no`；
2. `trigger / is_shown / is_valid / potential / allow / valid_to_start` 等门槛改成 `always = no`；
3. 新加 `hidden = yes`；
4. `immediate / effect / option / on_*` 效果块消失，或选项减少；
5. AI 权重归零；
6. 同名文件里原版有、mod 没有的定义；
7. on_action 事件列表缺失条目；
8. defines、游戏规则、GUI 的新增隐藏。

**人工核实**
- 通用机制和东亚相关项由 4 组只读子任务逐项看原版块、mod 块、调用方和 error.log 核实。
- 每项判定原因：地图引用、工具误伤、旧副本或有意替换。

**桩的来源**
- 大部分 `always = no` 桩在仓库首个提交 c277b6ce（2026-08-25）里就已存在。
- 文件头注释多为英文，例如「Absent vanilla-map title links isolated」「public IDs remain inert」「Deliberate total-conversion override」，与此前 UUII 误伤是同一类来源（见记忆 project-uuii-stub-restore）。
