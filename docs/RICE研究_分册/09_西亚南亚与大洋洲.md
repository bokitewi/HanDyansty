## 哈兰（Harran / namespace `harran`）——「最后的希腊化异教徒」

### 1. 主题与史实背景
- 风味包官方名「The Last Hellenic Pagans」，2021-05-22 发布（`common/on_action/RICE_game_start.txt:91` 注释）。
- 哈兰（今土耳其东南）直到 10~11 世纪仍有崇拜七曜的「萨比教徒/哈兰异教徒」，出过塔比·伊本·库拉（Thabit ibn Qurra，阿拔斯「智慧宫」数学家/天文学家）等学者；传说雅典新柏拉图学园被查士丁尼关闭后，部分哲学家东逃，学统辗转到哈兰。RICE 把这些全部做成可玩内容：七曜祈祷、月神庙、新柏拉图学园、学者著作、两位可扮演的历史人物。
- 事件文件头注释误写成「AACHEN: Charlemagne's Capital」（`events/RICE_harran_events.txt:3`），是从亚琛包复制模板留下的痕迹，ID 段划分本身是对的（`:5-10`）。

### 3. 触发入口
1. **开局 setup**（`common/on_action/RICE_game_start.txt:91` → `common/scripted_effects/RICE_harran_effects.txt:1`）：把 8 位古代哲学家 `make_unprunable`（`:6-13`）；按开局年代决定学园在哈兰（600~1050 年，直接放特殊建筑）、在雅典（仅 TFE 早期开局）、或已消亡（写入原版的 `unavailable_unique_decisions` 全局列表，`:270-310`）；给附近 AI 统治者发 `harran.0030` 生成哈兰廷臣（`:320-393`）。
2. **扮演邀请**：实际生效的是 `RICE_setup_character_picker_effect`（`common/scripted_effects/RICE__game_start_effects.txt:25-63`）——850~900 年开局、玩家持有 `c_harran` 或 `d_sunni`（哈里发）时 `every_player` 发 `harran.0040`；1000~1100 年开局同条件发 `harran.0060`。它在 `on_game_start_after_lobby` 中、未开 `RICE_new_characters_off` 规则时调用（`common/on_action/RICE_game_start.txt:144`、`:172-178`）。`events/RICE__setup.txt:96-112`、`:176-191` 的 `RICEintro.0003` 里有同样的调用，但该事件 `orphan = yes`（`events/RICE__setup.txt:85-89`），且在 on_action 中的引用已注释（`common/on_action/RICE_game_start.txt:137-141`），是旧版遗留。
3. **伊本·瓦赫希亚开局事件**：`RICE_setup_optional_flavor_events_effect`（`common/scripted_effects/RICE__game_start_effects.txt:67` 起，由 `common/on_action/RICE_game_start.txt:177` 调用）内 `:159-162` 直接 `character:RICE_nabati_001 = { trigger_event = harran.0013 }`。
4. **年度脉冲**：风味事件挂在 `RICE_events_yearly_pulse` / `RICE_events_tri_yearly_pulse` 的加权随机池（`common/on_action/RICE_events_on_actions.txt:1275-1278`、`:1576-1580`）；学园衰落 `harran.0024` 在「历史脉冲」池里权重 25（`:2125-2126`）；廷臣生成 `harran.0030` 在廷臣五年脉冲权重 50（`:2031`）。

### 4. 机制循环
```
开局：学园状态 = {在哈兰 | 在雅典(仅TFE) | 已消亡}
  ├─ 在雅典 → [停止资助]决议 → 全局变量 wandering → [迎接流亡者]决议 → 学园进哈兰
  ├─ 在哈兰 → [资助]（20 年冷却，5 年修正，按信仰三档）/ [振兴]
  │          → 1000 年后历史脉冲 harran.0024「学园衰落」→ 写入 unavailable_unique_decisions → 全部学园内容关闭
  └─ 已消亡 → 建筑 is_enabled 失败、决议 is_shown 失败
个人线：塔比（867）/伊本·纳卜罕（1066）扮演 → 各自事件链
学者线：伊本·瓦赫希亚 → 旅行积 XP → 三轨满 100 → 决议「完成纳巴泰农书」
信仰线：向行星祈祷（15 年冷却）→ 七曜随机祝福；月神庙献祭/拆毁
```
学园状态机全靠两个全局变量 + 一个全局列表成员：`RICE_harran_neoplatonic_academy_in_athens` / `_wandering`（`common/decisions/RICE_harran_decisions.txt:644`、`:670-672`、`:736`、`:759`）和 `unavailable_unique_decisions` 里的 `flag:RICE_harran_neoplatonic_academy_declined`。`unavailable_unique_decisions` 是原版用于「一局只能做一次」决议的全局列表（`vanilla:common/decisions/00_major_decisions_east_europe.txt:29`），RICE 直接复用它当「这条线已经结束」的开关，连特殊建筑的 `is_enabled` 也查它（`common/buildings/RICE_harran_buildings.txt:81-92`）。

### 5. 人物个人故事（本包重点）

**(a) 塔比·伊本·库拉的「自选人生」（CYOA）——用事件链给历史人物做角色创建**

- 入口 `harran.0040`（`events/RICE_harran_events.txt:2056-2141`）：玩家（哈里发或哈兰县主）被问「是否给哈兰更多自治」。选 b 则 `scope:thabit_ibn_qurra = { get_title = title:c_harran }` 并 `set_player_character = scope:thabit_ibn_qurra`（`:2115`、`:2123`），玩家立刻变成塔比；选 a 则继续当原角色，tooltip 明说「哈兰将没有塔比家族的有地统治者」。
- `harran.0041`「归乡」（`:2143-2226`）：选项 tooltip 写明「接下来几个事件是关于塔比生平的自选冒险，部分随机，部分会影响开局局面」（`localization/english/rice_harran_l_english.yml:473`）；快速开始选项已注释。
- 五步人生（每步 `after = { trigger_event = 下一步 }` 串接）：
  | 事件 | 问题 | 作用 |
  |---|---|---|
  | `harran.0042` 出生（`:2228-2310`） | 占星师预言：美貌/强壮/家世/名望 | 加对应技能 + 随机美貌/体格特质/金钱/王朝威望；「家世」还和历史兄弟 `RICE_harran_032` 结为好友 |
  | `harran.0043` 童年（`:2312-2405`） | 强盗洗劫/大病不死/青梅竹马之死/被恶霸欺凌 | 先 `remove_trait` 掉两个原性格，再四选一随机给性格 + 33% 给生活方式/伤疤/抑郁 |
  | `harran.0044` 教育（`:2407-2452`） | 修辞/军事/天文数学/人性/史学 | 对应技能 +2 |
  | `harran.0045` 智慧宫（`:2454-2524`） | 入智慧宫的动机 | `add_courtier` 历史好友 `RICE_harran_014`，随机性格 |
  | `harran.0046` 婚姻（`:2526-2863`） | 青梅竹马/哈兰名门/外国学者之女/聪慧女奴 | `create_character` 生成妻子，`marry`，并对历史儿子 `RICE_harran_010`（锡南·伊本·塔比）执行 `set_mother = scope:thabit_ibn_qurra_waifu`（`:2554`、`:2589`、`:2776`、`:2846`）；「学者之女」再随机决定她来自哪个宗教/地区 |
  | `harran.0047`「最后的异教徒」（`:2865-2912`） | 收尾 | 按有地/无地给不同描述 |
- 设计亮点：**历史人物的母亲在史料中缺失，就让玩家在事件中「选」出来，再 `set_mother` 接到真实儿子身上**；所有加成放在 `hidden_effect` 里，玩家只看到叙事选项而不是数值面板。

**(b) 伊本·纳卜罕：一个穆斯林学者回归祖先信仰的心路**

- `harran.0060`（`:2914` 起）同样是「是否扮演」+ `set_player_character`（`:2970-2971`）。
- 链条：搬回哈兰 → 180~500 天后与友人谈话 → 选择「保持穆斯林」（`harran.0064` 结束）或「开始怀疑」（`harran.0065`，加修正 `RICE_harran_ibn_nabhan_internal_conflict`，100~365 天后找到祖父遗稿）→ `harran.0067` 设旗 `RICE_harran_ibn_nabhan_pondering_deeply`（`:3166`）。
- **事件把接力棒交给决议**：旗子让决议 `RICE_harran_study_grandfathers_writings` 出现（`common/decisions/RICE_harran_decisions.txt:868-941`，`is_shown` 查旗、`is_valid` 用 `custom_description ... always = yes` 只做文字说明、花费中量虔诚）。决议效果是 `trigger_event = harran.0068`，44~108 天后 `harran.0069` 让玩家最终决定是否 `set_character_faith = faith:harranian_pagan`（`events/RICE_harran_events.txt:3237`）。
- 这种「事件 → 旗子 → 决议 → 事件」的交替，让玩家在故事中段有主动按按钮的感觉，也让 AI 能按 `ai_will_do` 自行推进。

**(c) 已故古人做「梦中来客」**

`history/characters/RICE_neoplatonists.txt` 把 8 位 3~6 世纪哲学家写成有生卒年的历史角色（如 `RICE_neoplatonist_001` 普罗提诺 205~270，`:3-18`），开局 `make_unprunable` 防止被引擎清理，事件 `harran.0021`「哲学家」（`events/RICE_harran_events.txt:1166-1256`）用 `random_list` 随机抽一位存为 `scope:ancient_pagan_philosopher` 当右侧立绘，描述「梦中一位银发长者自称……」。**对汉晋 mod：孔子、老子、张良等都可如法炮制做「托梦」事件。**

**(d) 历史学者 + 多轨特质 = 有进度条的个人任务**

伊本·瓦赫希亚（《纳巴泰农书》作者）开局带 `RICE_the_nabataean`（`history/characters/RICE_harranian.txt:766`），见下节。

### 6. 目标任务
- **《纳巴泰农书》三轨进度**：特质 `RICE_the_nabataean` 有农业/宗教/传说三条 `tracks`，各在 50、100 XP 给技能和乘数（`common/traits/RICE_harran_traits.txt:8-37`）。原版会把特质 XP 轨显示成进度条，于是**特质本身就是任务面板**。
  - XP 来源：三个独特旅行选项（`common/travel/travel_options/0000_RICE_unique_travel_options.txt:3` 起，`is_shown = { has_trait = RICE_the_nabataean }`），旅行时每走一步由 `on_travel_plan_movement`（`common/on_action/RICE_travel_on_actions.txt:2`）掷骰，若当前县「算纳巴泰地区」用更高概率，弹 toast 并 `add_trait_xp`（`:88-140`，效果定义在 `common/scripted_effects/RICE_harran_effects.txt:437-459`）。
  - 完成：决议 `RICE_nabataean_ibn_wahshiyya_decision` 要求三轨都 ≥100（`common/decisions/RICE_harran_decisions.txt:965-968`），效果 +1000 威望 +500 虔诚并发 `harran.0011` 通知外交范围内的统治者，写全局变量 `RICE_nabataean_ibn_wahshiyya_book_done` 防重复。
- **学术论著**：决议「写论著」→ `harran.0009/0010`，七门学科各有「本人著 / 本人著（自用）/ 抄本」三联修正（`common/modifiers/RICE_harran_event_modifiers.txt` 中 `RICE_harran_treatise_*_wrote/_wrote_self/_copy`），抄本可在宫廷间流传。

### 10. 问题与局限
- 文件头错写「AACHEN」（`events/RICE_harran_events.txt:3`）。
- CYOA 的「快速开始」选项被注释（`events/RICE_harran_events.txt:2220-2223`），玩家只能走完整条链。
- 塔比兄弟姐妹原想 `create_character` + `set_real_father`，注释写「can't connect to father for some reason」（`events/RICE_harran_events.txt:2183-2210`），最后改成在 history 里直接写兄弟 `RICE_harran_032`。

### 9. 写法亮点
**决议 widget 的完整用法**（`common/decisions/RICE_khuzestan_decisions.txt:421-555` 节选）：
```
widget = {
    gui = "decision_view_widget_RICE_khuzestan_repair_shushtar_hydraulics"
    controller = decision_option_list_controller
    decision_to_second_step_button = "RICE_khuzestan_pick_shushtar_hydraulics"
    show_from_start = yes
    item = {
        value = RICE_khuzestan_shushtar_dams_option
        current_description = RICE_khuzestan_shushtar_dams_option_desc
        localization = RICE_khuzestan_shushtar_dams_option
        icon = "gfx/interface/icons/widgets/RICE_khuzestan_shushtar_dams.dds"
        ai_chance = { value = 1 }
    }
    # ……canals / bridges / watermills 同构
}
effect = {
    if = { limit = { is_ai = yes } random_list = { 10 = { set_variable = { name = RICE_shushtar_work_type value = flag:dams } } ... } }
    else_if = { limit = { scope:RICE_khuzestan_shushtar_dams_option = yes }
                set_variable = { name = RICE_shushtar_work_type value = flag:dams } }
    ...
    trigger_event = { id = khuzestan.0010 }
}
```
要点：选中的 `item.value` 会变成 `scope:<value> = yes`；把选择存成**带 flag 值的变量**，后续事件用 `var:RICE_shushtar_work_type = flag:dams` 分支（`events/RICE_khuzestan_events.txt:209-227`）。作者注「Not sure why AI can't pick one option or another」（`:490`），所以给 AI 单独写随机分支——这是 widget 决议的通用补丁。GUI 文件（`gui/decision_view_widgets/...shushtar_hydraulics.gui`）只是把原版 `DecisionViewWidgetOptionList.GetEntries` 数据模型套进滚动框和按钮类型，按钮显示 `Entry.GetIcon/GetName`。

### 本包可迁移的设计模式
1. **工程类决议 + widget 选项 + 变量记选择 + 后续事件分支**：适合「修都江堰/郑国渠」「整修驰道」一类，四种子工程各给不同 10 年县修正。

## 宗教/族群按史实时点出现（emergence）的实现

> 以雅兹迪教（Yazidism）与亚尔桑教（Yarsanism/Ahl-e Haqq）为例。同一套写法 RICE 还用于罗斯文化（`RICE_rus_emergence_*`，见 `common/scripted_effects/RICE__game_start_effects.txt:2156` 起），本节只讲雅兹迪/亚尔桑。

### 0. 先搞清楚原版底座：1.20 的「信仰-礼仪（rite）」两层结构

1.20 原版里，雅兹迪不是独立信仰，而是 `yazidi_faith` 之下的三个 **rite**：`yazidi`（主礼仪）、`meshefaresism`（亚尔桑）、`kitebacilweism`（库尔德异教）。

- `vanilla:common/religion/faith_types/00_faith_types.txt:4468-4486`：`yazidi_faith = { main_rite = yazidi ... }`
- `vanilla:common/religion/rite_types/00_rite_types.txt:1427-1469`：三个 rite 都写 `faith = yazidi_faith`，各自带 tenets。

所以 RICE 的「宗教出现」**不是创建新信仰**，而是对已存在的 rite 做三件事：开局锁死改宗（`set_can_convert_to_rite = no`）→ 把已有信徒改成「前身」rite（`kitebacilweism`）→ 到时点用事件把发源地县份 `set_county_rite` 回来并解锁改宗。这一点对汉晋 mod 很有参考价值：**想让某教派「后来才出现」，不必等引擎支持动态建教，只要提前把它放进数据库、开局藏起来、到点再放出来。**

### 1. 游戏规则：四档

`common/game_rules/RICE_game_rules.txt:205-228`（雅兹迪）、`:230-253`（亚尔桑），四个选项都是空壳，只挂 `flag = GG_can_change_rule`，真正逻辑全靠脚本里 `has_game_rule` 判断：

| 选项 | 本地化说明（`localization/english/rice_misc_l_english.yml:89-106`） | 脚本含义 |
|---|---|---|
| `_default` | 开局约半世纪后可随机出现，12 世纪后更可能 | 开局随机挂一个 50/100/150 年的「冷却」全局变量，过期才开始掷骰 |
| `_historical` | 只在 12 世纪中叶（亚尔桑为 14 世纪中叶）后出现 | `current_date >= 1150.1.1`（亚尔桑 `1350.1.1`） |
| `_unrestricted` | 任何时候都可能 | 不设门槛，直接每年掷骰 |
| `_vanilla` | 开局即存在，和原版一样 | 跳过锁定和清洗 |

### 2. 状态机：四个全局变量串成的链

```
开局(after_lobby)：default 规则 → set_global_variable RICE_yazidi_start_timer (days = 18250/36500/54750 三选一)
      │ 每年 yearly_global_pulse
      ▼
阶段一「先知之死」：RICE_yazidi_appearance_prequel_effect
      写 RICE_yazidi_sheikh_adi_death（永久）+ RICE_yazidi_event_timer（10950 天）
      给 c_ninive 加县修正 RICE_yazidi_sheikh_adi_recently_died，通知玩家 yazidi.0001
      │ 每年掷骰，且 event_timer 已过期
      ▼
阶段二「教派成形」：RICE_yazidi_appearance_effect → c_ninive 持有者 0~365 天后触发隐藏事件 yazidi.0002
      写 RICE_yazidi_appearance（永久）；解锁 rite；扩散县份；生成宗教领袖并授 d_yazidi
      │ every_ruler（中东/东南欧/小亚有县者）
      ▼
yazidi.0003 通知 + 可选改宗 → c_ninive/c_kurdistan/c_hakkari 持有者收到 yazidi.0007「是否赐县给雅兹迪米尔」
```

逐段对代码：

**(a) 开局冷却计时**——放在 `RICE_setup_misc_after_effect`（`common/scripted_effects/RICE__game_start_effects.txt:1348` 起），它由 `on_game_start_after_lobby` 调用（`common/on_action/RICE_game_start.txt:132-147`）。放在「出大厅之后」是因为原版注释明确说那时才确定游戏规则（同文件 `:131`）。

```
# common/scripted_effects/RICE__game_start_effects.txt:2017-2047（节选）
if = {
    limit = { has_game_rule = RICE_yazidi_emergence_default }
    random_list = {
        10 = { set_global_variable = { name = RICE_yazidi_start_timer value = yes days = 18250 } }  # 50 年
        10 = { set_global_variable = { name = RICE_yazidi_start_timer value = yes days = 36500 } }  # 100 年
        10 = { set_global_variable = { name = RICE_yazidi_start_timer value = yes days = 54750 } }  # 150 年
    }
}
```

亚尔桑同理，但权重是 10/25/25，更偏向晚出现（`:2050-2083`）。**带 `days =` 的全局变量会自动过期**，脚本只要判断 `NOT = { has_global_variable = ... }` 就等于「冷却结束」——这是 RICE 全书最常见的计时写法，不需要每年自减计数器。

**(b) 每年掷骰**——挂在原版 `yearly_global_pulse` 上（`common/on_action/RICE_events_on_actions.txt:1-3`），属于全局作用域（没有 root 角色），所以后面用 `every_player`、`title:c_ninive.holder` 去找人。

```
# common/on_action/RICE_events_on_actions.txt:482-517（节选）
# Death of Sheikh Adi ibn Musafir
if = {
    limit = {
        NOT = { has_global_variable = RICE_game_started_on_TFE_start_date }
        NOT = { has_global_variable = RICE_yazidi_sheikh_adi_death }
        OR = {
            has_game_rule = RICE_yazidi_emergence_unrestricted
            AND = { has_game_rule = RICE_yazidi_emergence_default
                    NOT = { has_global_variable = RICE_yazidi_start_timer } }
            AND = { has_game_rule = RICE_yazidi_emergence_historical
                    current_date >= 1150.1.1 }
        }
    }
    random = {
        chance = 5
        modifier = { add = 10  current_date >= 1150.1.1 }
        modifier = { add = 15  current_date >= 1175.1.1 }
        modifier = { add = 20  current_date >= 1200.1.1 }
        modifier = { add = 25  current_date >= 1225.1.1 }
        RICE_yazidi_appearance_prequel_effect = yes
    }
}
```

要点：
- 年概率随史实年份递增：5% → 1150 年后 15% → 1175 后 30% → 1200 后 50% → 1225 后 75%。谢赫·阿迪实际卒于 1162 年，曲线把「大概率」压在史实附近，又保留偏差。
- 第二段（`:523-552`）条件是「阿迪已死 + 未出现 + `RICE_yazidi_event_timer` 已过期」，基础 20%，1250/1300/1350/1400 后逐级加，最高 80%。
- 亚尔桑两段在 `:555-593`（苏丹·萨哈克的传闻，1275 起加权）和 `:595-624`（基础 70%，几乎冷却一过就成形）。
- 所有段都排除 `RICE_game_started_on_TFE_start_date`：这个全局变量在开局日期早于 700 年时设置（`common/on_action/RICE_game_start.txt:39-47`），用来兼容另一个更早时代的大型 mod（TFE），防止在古典晚期开局时乱刷中世纪宗教。

**(c) 阶段效果**——`common/scripted_effects/RICE_yazidi_effects.txt:860-895`（prequel）、`:897-904`（appearance）。prequel 只做「记账+通知」：写两个全局变量、给拉利什（`c_ninive`）加县修正、通知相关区域的玩家。appearance 只做一件事：把真正的大事件 `yazidi.0002` 延迟 0~365 天丢给尼尼微县的持有者——**用随机延迟把「年脉冲」的整点感打散**。

注意一个小矛盾：亚尔桑 prequel 注释写「至少 25 年」，实际 `days = 10950` 是 30 年（`RICE_yazidi_effects.txt:907-911`）。

### 存疑点（未实测）
- **规则读取时机**：锁改宗的 `RICE_setup_yazidi_flavor_pack_effect` 由 `on_game_start` 调用（`common/on_action/RICE_game_start.txt:1-5`、`:114`），却在里面判断 `has_game_rule = RICE_yazidi_emergence_vanilla`（`common/scripted_effects/RICE_yazidi_effects.txt:19-22`）；而开局冷却计时器被刻意放在 `on_game_start_after_lobby`，原版注释也说那时才可靠地知道规则（`common/on_action/RICE_game_start.txt:131`）。如果大厅里改了规则，锁定这一步可能用的是旧值。是否真有问题取决于引擎在 `on_game_start` 时是否已载入最终规则，本文未实测，不定性为 bug。
- **vanilla 规则下的空头衔**：`faith:yazidi_faith = { set_religious_head_title = title:d_yazidi }` 无条件执行（`common/scripted_effects/RICE_yazidi_effects.txt:11-13`），而全 mod 唯一授出 `d_yazidi` 的地方是 `yazidi.0002`（`events/RICE_yazidi_events.txt:128-130`），该事件在 `_vanilla` 规则下永远不会触发（年度检测要求 unrestricted/default/historical 之一，`common/on_action/RICE_events_on_actions.txt:488-497`）。因此选 vanilla 时，雅兹迪信仰会挂着一个永远无人持有的宗教领袖头衔。

### 8. 对汉晋 mod 的启示

1. **「存在但隐藏」三件套**：数据库里提前定义（rite/文化/头衔）→ 开局锁改宗 + 把信徒改成前身 → 到时点解锁。适用于五斗米道/太平道之后的天师道、佛教在中原的扩散、景教入华等。
2. **规则四档 + 计时变量**：default（开局随机冷却）/historical（史实年份门槛）/unrestricted/vanilla，覆盖了「史实党」「随机党」「兼容党」三类玩家，代价只是 `has_game_rule` 的 OR 组合。
3. **两段式出现**：先「先知之死/传闻」做铺垫（县修正 + 通知玩家），30 年后再「成形」，比一次性弹出更像历史进程。
4. **随机延迟丢事件给地主**（`days = { 0 365 }`）+ 「赐县 / 换号扮演 / 拒绝」三选一，把世界事件变成玩家可参与的个人选择。
5. **反例提醒**：`yazidi.0007` 的 `has_title = title:c_hakkari` 分支错把 `c_kurdistan` 存为 `yazidi_county`（`events/RICE_yazidi_events.txt:868-874`），复制模板时要逐支核对。

- 地图上只有印尼东部、马鲁古、西巴布亚一带可玩；大洋洲其余部分（密克罗尼西亚、美拉尼西亚、波利尼西亚、澳大利亚）乃至南美都**不在地图上**，RICE 用「远方来客」机制把这些文化/信仰作为离图人物带进游戏。主题包括比亚克（Biak）航海冒险者、雅浦石币、Sasi（马鲁古的资源休养禁令）、卡瓦酒与槟榔、会所（meeting house）、食火鸡/天堂鸟等风物。
- ID 段：0000-0019 setup，0020-0029 小决议，0030-0039 离图文化/信仰事件，0040-0049 Sasi，0050-0059 石币，0060-0069 比亚克冒险者，0080-0099 风味（`events/RICE_oceania_events.txt:1-14`）。

   → 来客事件：抽一个离图文化+信仰，用模板造人，随机给你一个修正；可花 50 金留他做廷臣，否则他「消失」
[决议] 招募比亚克冒险者（widget：武士/商人）→ 隐藏抽签事件 oceania.0060
   → 70% 顺利（武士：spawn_army 兵种；商人：贸易修正；可留首领为廷臣）
   → 30% 索要更多金钱或头衔 → 拒绝则 duel 谈判 → 失败则首领「出走」劫掠整个公爵领（发展度 -50、控制度 -15、10 年海盗修正）
[活动] Sasi：封禁（县修正 closed）→ 1~3 年后县级事件 → 当时的县主收到「解禁」→ 丰收修正

```

### 5. 人物个人故事
- **蒂多雷书签：一个人物 + 两个「备选扮演」**。1066 书签里蒂多雷开国传说君主 Sahjati 作为主角，下面挂两个子角色：邻国特尔纳特君主（`relation = "BOOKMARK_RELATION_RICE_NEIGHBOR"`）与比亚克冒险者 Raki（`relation = "BOOKMARK_RELATION_RICE_ADVENTURER"`，`common/bookmarks/bookmarks/RICE_1066_bookmarks.txt:1032-1054`），三人各有专属立绘文件。**书签的子角色不必是亲属，可以是「同一地区的另一种玩法」**。
- **传说君主的史料处理**：`history/characters/RICE_maluku.txt:12-18` 的注释列出 Sahjati 的三种矛盾记载（1081 年即位 / 特尔纳特传说里是 1245 年开国者的兄长 / 既称先知后裔又是伊斯兰化前君主），最后「为游戏起见，设为无亲属关系的异教君主」。
- **虚构冒险者每书签一位**：`RICE_biak_001/002/003` 分别对应 867/1066/1178（`history/characters/RICE_biak.txt:6-` 起），出生效果 `do_not_generate_starting_family`；无地冒险者头衔 `d_laamp_RICE_biak_867/1066/1178`（`common/landed_titles/00_RICE_oceania_titles.txt`）的持有记录写在 `history/titles/RICE_laamp_titles_1066.txt:661` 等处，规则 `RICE_adventurers_disable_fictitious/_all` 开启时对 AI 持有者 `destroy_title`（`common/scripted_effects/RICE__game_start_effects.txt:625-640`、`:711-718`）——**「虚构人物可关」的开关**值得借鉴。
- 东南亚杂项人物 `RICE_southeast_asian_miscellaneous_001` 阿拉文达赫拉达（1051 年反吴哥的叛乱者）：history 里 `1052.1.1 = { add_pressed_claim = title:k_funan }`，`1066.1.1 = { effect = { add_trait_xp = { trait = tourney_participant track = bow value = 100 } } }`（`history/characters/RICE_southeast_asian_miscellaneous.txt:9-40`）——**在 history 日期块里直接给宣称和特质 XP**，把「善射」「曾反叛」这类史料写成机制。

### 9. 写法亮点
- 离图来客的分层抽选：先 `RICE_choose_random_off_map_oceania_class_N_effect` 抽区域（`common/scripted_effects/RICE_oceania_effects.txt:1132-1163`），区域内再抽具体文化与信仰并 `save_scope_as = oceanic_culture/oceanic_faith`，事件里 `create_character = { template = RICE_oceania_random_gender_adjusted_character_template culture = scope:oceanic_culture faith = scope:oceanic_faith }`（`events/RICE_oceania_events.txt:595-606`），拒绝时 `death = { death_reason = death_vanished }` 清掉，`after` 里统一 `RICE_oceania_courtier_spawn_cleanup_effect`。
- 1.20 原版 `duel` 效果做谈判：`duel = { skills = { diplomacy martial intrigue prowess } target = scope:biak_leader ... }`（`events/RICE_oceania_events.txt:2096-2135`），后果落在整个法理公爵领的所有县并用列表通知受影响的县主。
- 计数器转特质：槟榔/卡瓦每次使用 50% 概率给变量 +1（`common/scripted_effects/RICE_oceania_effects.txt:936-959`、`:1011-1034`），到阈值给特质；卡瓦特质再用 `culture_modifier`/`rite_modifier` 按文化/信仰参数给额外加成（`common/traits/RICE_oceania_traits.txt:157-175`）。

- 频率规则三档实际无差别（见上）。

### 附：「Rajas of Asia」「After the End」本地化子文件夹与外部 mod 的关系
- `localization/english/` 下有两个以外部 mod 命名的子文件夹：`Rajas of Asia/`（17 个文件：大洋洲/澳洲文化、美拉尼西亚/密克罗尼西亚/波利尼西亚/西巴布亚宗教、东南亚各宗教……）与 `After the End/`（3 个：南美文化、安第斯宗教、Feyentun 宗教）。
- **它们是 RICE 自带内容的本地化，不是兼容补丁**：抽样检查这些文件的键在 RICE 的 `common/`/`history/`/`events/` 里大多有引用（例如 `RICE_religion_polynesian` 抽 40 键 39 个被引用，`RICE_cultures_south_america` 37 键 36 个被引用；`RICE_sea_religion_austronesian` 抽到的 40 键仅 2 个被引用，是例外）。对应的定义文件由 RICE 自己提供，且文件头写明来源：
  - `common/religion/religion_types/00_andean.txt:1-6`「ANDEAN RELIGION AND MOST FAITHS HERE BORROWED/ADAPTED FROM AFTER THE END WITH PERMISSION」；`00_feyentun.txt` 同；`common/culture/cultures/RICE_andean.txt:2-7` 同，并标注「RICE original」的条目；
  - `common/culture/cultures/RICE_sea_aslian.txt:1-6`「Partial adaptation of *some* cultures from the Rajas of Asia mod. Not all cultures have been adapted to reduce potential compatibility issues」；`common/religion/religion_types/sea_aslian_animism.txt:1`「reworked from ROA's older version」。
- 运行时兼容：`common/scripted_triggers/00000000_compatibility_triggers.txt:12-14` 定义 `roa_is_active = { always = no }`，文件名以多个 0 开头、排序最前，便于 ROA 自己用同名触发器 `always = yes` 覆盖；RICE 在开局 `RICE_setup_general_southeast_asian_culture_faith_effect`（`common/on_action/RICE_game_start.txt:71-76`）和蒂多雷授地（`common/scripted_effects/RICE_oceania_effects.txt:604-606`）等处检查它，ROA 在场时就不改写东南亚。介绍事件还会提示「检测到 ROA，请把 ROA 放在 RICE 下方」（`localization/english/rice_misc_l_english.yml:15`；TFE 的检测则是 `exists = culture:soissons`，`events/RICE__setup.txt:61-66`）。
- 南美内容（After the End 改编）在地图上不存在，只通过 `RICE_south_america` 规则下的第 5 区来客出现（`common/scripted_effects/RICE_oceania_effects.txt:1557-1705` 的安第斯/哥伦比亚/马普切抽选）。

### 本包可迁移的设计模式
1. **离图民族来客**：分层 `random_list` 抽区域→文化→信仰 + 统一模板 + 不收就 `death_vanished`。汉晋可用来做「大秦使者」「天竺沙门」「扶南商人」「倭国使」。
2. **县级延时事件**：长期效果挂在县上，到期发给届时县主，避免继承后丢失（屯田、水利岁修、封禁山泽）。
3. **widget 雇佣 + 抽签分支 + duel 谈判 + 区域性惩罚**：雇佣羌胡/乌桓突骑等「可能反噬」的外族武力。
4. **书签子角色 = 同区不同玩法**（邻国、冒险者）。
5. **虚构人物可关**：游戏规则 + 开局对 AI 持有的虚构冒险者头衔 `destroy_title`。
6. **兼容触发器桩**：`xxx_is_active = { always = no }` 放在最早加载的文件，由外部 mod 覆盖为 yes，再用它跳过改写。
7. **嗜好计数器**：变量累计 → 特质，比直接给特质更平滑（五石散、饮酒、清谈）。

### 3. 三套跨包框架

**(a) 历史志向（Historical Aspiration）——RICE 的「人物目标任务」系统**

组成部件（全部跨包共享）：
1. 标记：各包 setup 给特定史实人物 `set_variable = { name = RICE_historical_aspiration value = flag:<人名> }`（如巴·卢德 `common/scripted_effects/RICE_aslian_effects.txt:186-189`、卡乌尔德 `common/scripted_effects/RICE_yazd_effects.txt:373-376`），并挂一个只有图标的修正（`icon = RICE_aspiration_icon`，如 `common/modifiers/RICE_aslian_modifiers.txt:263-265`）。
2. 目标说明：修正的 `_desc` 本地化里写「主目标 / 奖励 / 附加目标」清单（`localization/english/rice_aslian_l_english.yml:62`、`rice_yazd_l_english.yml:30`），数值用 `[EmptyScope.ScriptValue('RICE_aspiration_medium_resource_bonus')]` 动态显示，保证文案与脚本一致。
3. 提醒：原版「重要行动」系统 `action_RICE_historical_aspiration`（`common/important_actions/RICE__misc_actions.txt:5-27`）——只要 `exists = var:RICE_historical_aspiration` 就在界面右侧提醒，点击打开角色界面；标题与描述用 custom_loc `RICE_historical_aspiration_action_title_name` / `_desc` 按 `var:RICE_historical_aspiration ?= flag:xxx` 分流到各人物的本地化（`common/customizable_localization/RICE_aspirations_custom_loc.txt:3`、`:287`、`:582`；`localization/english/rice_misc_l_english.yml:196-201`）。
4. 检测：`common/on_action/RICE_aspirations_on_actions.txt:1-18` 注释「"Completion" is calculated yearly in on actions to keep things simpler to code」，挂在 `yearly_global_pulse` 上，按书签分组逐人写 `if = { limit = { exists = character:X  character:X = { ...目标...  has_variable = RICE_historical_aspiration } } character:X = { trigger_event = 结算事件 } }`。
5. 结算：各包事件调用 `RICE_historical_aspiration_fulfilled_effect`（`common/scripted_effects/RICE__misc_effects.txt:1608-1614`）删变量（防止重复结算），再按旗子/条件发主奖励与附加奖励；奖励档位统一在 `common/script_values/RICE_misc_values.txt:8-15`（tiny 200 / small 500 / medium 1000 / large 2000 / huge 4000）。

这是一个**零 GUI 改动**的任务系统：图标修正当「任务卡」，重要行动当「任务提醒」，年度脉冲当「检测器」，事件当「结算界面」。

**(b) 地方朝圣（Local Pilgrimage）骨架**：共享阶段 `RICE_local_pilgrimage_pilgrimage_phase`、选项类别（供品/纪念方式/类型）、三个意图（`common/activities/intents/RICE__misc_pilgrimage_intents.txt`）、结算效果（上表），被 16 个包的朝圣活动复用（胡齐斯坦的但以理墓为例，见该节）。

**(c) 通用活动/旅行骨架**：
- 温泉 `activity_RICE_hot_springs_visit` 服务 9 个包的温泉巴罗尼（清单在 `common/scripted_triggers/RICE__misc_triggers.txt:235-261`，每行注释所属风味包），通用事件 `RICEmisc.0012`（`events/RICE_misc_events.txt:202-320`），个别地点（如图阿雷格的塔法戴克）有专属事件 `RICEmisc.0020/0021`——注释说明是「为兼容 BAP 从 tuareg.0012 挪来」（`:325-359`）。
- 通用旅行开场 `RICEmisc.0011`（`:87-195`）：`involved_activity` 是 20 多种 RICE 活动之一时播放原版 `mx_cue_travel_start` 并弹一个通用窗口，挂在 `on_travel_plan_start`（`common/on_action/RICE_travel_on_actions.txt:276`）。
- 所有活动共用的 AI 限制（不打仗 + `short_term_gold >= RICE_activity_cost`）、冷却 `RICE_standard_festival_cooldown_time`、花费 `RICE_activity_cost`/`RICE_major_activity_cost`（`common/script_values/RICE_misc_values.txt:91-180`，注释「Since the vanilla activity costs are unimmersively inflated at higher levels」——RICE 刻意压低高层级活动花费）。

### 5. 为「错误日志干净」写的代码
- `RICE_setup_no_modifier_or_variable_silliness_effect`（`common/scripted_effects/RICE__misc_effects.txt:7-104`）：注释「This is literally needed for the error log to not show a message, even though this effect literally does nothing」，在一个永不执行的 `if` 里 `has_character_modifier`/`has_global_variable`/`has_variable` 列出所有「只在 history 或间接引用中使用」的修正与变量，骗过引擎的「未使用」警告。
- `RICE_setup_have_to_set_variable_effect`（`:105-139`）：注释「Variables need to be set up somewhere or else they'll have an error」，对每个变量 `set_variable` 后立即 `remove_variable`。
- 这两个效果引用次数为 0~1，纯粹为了让 error.log 安静——**大型 mod 维护的实用技巧**，汉晋 mod 的日志审计也可以用。

### 6. 调试决议 `RICE__test_decisions.txt`
`RICE_test_decision`（`:13-46`）只在 `debug_only = yes` 时显示，内容是给小额金币。真正有价值的是文件头两行笔记（`:8-10`）：
- 「Adding new religions/faiths midway through doesn't work, won't show up」
- 「Adding new cultures midway through doesn't work, will cause mismatches for saves」

这正好解释了 emergence 一节的设计：**新宗教不能运行时创建，只能预先定义、开局隐藏、到点放出**。

### 7. `RICE__general_southeast_asian_effects.txt`（41 KB）
- 只有两个顶层效果：`RICE_setup_general_southeast_asian_culture_faith_effect`（`:2-1782`）和 `forget_austronesian_effect`（`:1783-1798`）。前者是开局的「东南亚世界观重写」：按字母顺序给几十个原版文化改语言柱/名单/传统（如 `culture:dayak` 改尚武民族精神并加海盗、诗歌、武士传统，每条带 `msl_note` 考据注释，`:41-52`），再按族群逐县改文化与信仰（蒙达、库伊、巴拿、佤、萨姆雷、巴塔克、楠榜、巽他、塞拉塔、帝汶、松巴、卡西、托拉基、哥伦打洛、古戴、比达友、卡达山、恩加朱……`:195-1587`），并把这些县主的配偶、近亲、廷臣一并改掉（如 `:226-260`）。
- 由开局 `RICE_game_start.txt:71-76` 在 `roa_is_active = no` 时调用——与 Rajas of Asia 同时加载时整段跳过，避免两套东南亚设定打架。

### 8. 可迁移的设计模式
1. **薄包装触发器**：自己的 `XXX_is_available_adult_trigger` 包一层原版触发器，将来原版改名或想全局调条件，只改一处。
2. **「清空特质再重写」两件套**：`remove_personality_traits` + `remove_education_traits`，setup 里逐条加回并写史料注释。
3. **历史志向五件套**：变量标记 + 图标修正 + 重要行动提醒 + 年度检测 + 结算事件；奖励档位放 script_values。
4. **通用活动骨架**：共享阶段/选项类别/意图/结算效果，各地只写地点与专属事件。
5. **复用原版变量/列表**：`cannot_be_converted_by_value`、`unavailable_unique_decisions`、`planning_an_activity`，直接接入原版逻辑。
6. **安静日志技巧**：永不执行的引用块、`set_variable`+`remove_variable` 预声明。

```

### 5. 设计要点（逐条带出处）
- **默认选项随信仰变化**：`RICE_venerate_ancestors_type_secular` 的 `default = { NOT = { rite = { rite_has_tenet = tenet_ancestor_worship } } }`，宗教型反之（`RICE_misc_ancestor_veneration.txt:145-170`）——没有祖先崇拜教义的人（如儒家式「慎终追远」）默认是世俗祭礼，有的则默认宗教祭礼。这一区分对汉晋很合用：**士大夫家祭（礼）与民间/道教祭祀（教）可以共用一个活动**。
- **只邀同宗**：`can_be_activity_guest` 要求成年、可用、在外交范围、`dynasty = scope:host.dynasty`（`:420-435`）；`allow_zero_guest_invites = yes`（`:400`）允许一个人祭祖；`guest_join_chance` 基础 0（`:447-453`），完全靠原版共享 AI 接受修正。
- **奖励随德行与家门浮动**：`RICE_ancestor_max_bonus_value` 基础 80，每有 1/2/3 个美德特质 +20、罪恶特质 -20，再加王朝威望等级×10，夹在 50~200（`common/script_values/RICE_misc_ancestor_worship_values.txt:2-50`）。事件里用 `add_piety = { 40 RICE_ancestor_max_bonus_value }` 这种**随机区间以脚本值为上界**的写法（`events/RICE_misc_ancestor_worship_events.txt:146-200`）。
- **地点与花费**：`province_score` 偏好教会领地（`:323-330`），花费块对教会领地减 25 金并显示专门说明 `activity_RICE_venerate_ancestors_temple_holding_reduced_cost`（`:334-353`），对应「在宗庙/寺观举行更省」。
- **教义差异化结算**：`RICE_venerate_ancestors_completed_log_entry_effect` 按 rite 的 `rice_west_papuan_ancestor_focus_gosimo/wor/wuon/matutuo` 分别给正统性 + 封臣好感 / 10 年海军修正 / 神秘修正 / 活动所在县的繁荣修正（`common/scripted_effects/RICE_misc_ancestor_worship_effects.txt:2-60`）。这四种教义定义在大洋洲教义文件（`common/religion/doctrine_types/RICE_doctrines__misc_oceania.txt`），**一个通用活动通过教义钩子与地区包衔接**。
- 邀请事件 `0001` 整段注释（`events/RICE_misc_ancestor_worship_events.txt:8-145`），其中「Children will not refuse to go because they must listen to their elders」的未成年人不得拒绝逻辑也随之失效；记忆在 `on_complete` 中同样被注释（`RICE_misc_ancestor_veneration.txt:455-470`）。
- 相关死亡原因 `death_sacrificed_to_ancestor`（`common/deathreasons/RICE_misc_deaths.txt`）实际被博佐包的人祭事件使用（`events/RICE_bozo_events.txt:420` 等），与本活动无关。

### 模板其余栏目
- **人物个人故事**：无。活动不绑定任何历史人物，也没有定向事件；「祖先」本身不以角色出现（没有像哈兰那样调用已故先祖做立绘），这是可以加强的地方——例如抽取王朝中已故的最高威望成员做右侧立绘。
- **目标任务**：无进度或多阶段链，只有 10 年冷却（`common/activities/activity_types/RICE_misc_ancestor_veneration.txt:367`）。
- **活动与意图**：见第 4、5 点；唯一意图 `RICE_venerate_ancestors_respect_intent` 为 `auto_complete` 型。
- **风味化资产**：见第 2 点表格（插画、头图、图标、音乐）。
- **写法亮点**：见第 5 点（默认选项随信仰切换、同宗限定宾客、德行+家门上限、教义钩子结算）。

### 6. 问题与局限
- 只有一个阶段、一个意图、主持人一个结算事件，过程事件为零，玩起来更像「带选项的决议」。
- 「次中华圈」触发器把汉、和、韩、越、通古斯、苗瑶一视同仁，未区分宗法差异；宗族（cadet house）层面也没有处理——只按 `dynasty` 邀请。

### 本包可迁移的设计模式
1. **一个活动服务多文化**：资格用「文化参数 OR 文化圈触发器 OR 教义」三路并列，地区包只需给自己的文化加参数即可接入。
2. **选项默认值随信仰切换**（`default = { 条件 }`），实现「礼」与「教」两种祭祀共用骨架。
3. **同宗限定宾客** + 允许零宾客。
4. **奖励上限 = 德行 + 家门声望**的脚本值，再配随机区间。
5. **教义钩子差异化结算**：通用活动在结算时按教义分流，让各地区宗教各有回报（汉晋：儒家宗法、天师道、佛教盂兰盆可各给不同奖励）。

## 本组共性小结

### 1. 接入本体的方式（本组 9 包一致）
- **只追加不覆盖**：开局效果挂 `on_game_start → RICE_setup_on_actions`（`common/on_action/RICE_game_start.txt:1-128`），需要知道游戏规则的放 `on_game_start_after_lobby`（`:132-158`）；年度/三年/五年事件挂原版 `yearly_playable_pulse` 等（`common/on_action/RICE_events_on_actions.txt:907-938`），全局逻辑挂 `yearly_global_pulse`（`:1-3`）；旅行挂 `on_travel_plan_*`，文化/信仰创建挂 `on_culture_created`/`on_faith_created`/`on_rite_created`。
- **大量复用原版积木**：`unavailable_unique_decisions` 全局列表、`planning_an_activity` 旗、`cannot_be_converted_by_value` 变量、`create_title_and_vassal_change` 一套、`create_legend_seed` 传奇系统、`add_activity_log_entry` 结算页、`duel`、`stress_and_fulfillment_impact`、`activity_system.03xx` 失效事件、`create_landless_adventurer_title_history_effect`、原版活动的 `base_activity_modifier`/`activity_guest_shared_ai_accept_modifier`、音乐提示 `mx_cue_epic_sacral_moment` 等。
- **每个包的固定骨架**：setup 效果（改文化/信仰/县/历史人物）→ 3~6 个决议 → 0~4 个活动 → 年度风味事件进加权池 → 若干修正与特殊建筑 → 自制事件背景/主题 → 音乐。

### 2. 人物个人故事的五种做法（按本组出现频率）
1. **改写原版人物**：setup 里 `RICE_remove_personality_traits_effect` 清空后逐条加回，每条写史料注释（亚兹德、卡库伊德等）。

3. **扮演邀请**：开局 `RICE_setup_character_picker_effect`（旧版 `RICEintro.0003` 已停用）或剧情点事件里 `set_player_character`（塔比、伊本·纳卜罕、雅兹迪米尔；萨法尔选角事件已孤儿化），以及书签子角色（蒂多雷）。
4. **CYOA / 人生取向事件**：把史料空白交给玩家选择（塔比的出生到婚姻、卡乌尔德三选一、卡库伊德性格二选一）。
5. **事件链 + 决议接力 + 旗子**：伊本·纳卜罕的信仰回归、巴·卢德的附加目标、雨安居修行。

### 4. 风味化的共同手法
- **史实注释可开关**：几乎每个决议/关键事件都有 `has_game_rule = RICE_historical_context_on` 时才显示的 context tooltip。
- **民俗禁忌 → 性格测验事件**（白菜、蓝衣、鸟叫、肉类混食、梦境）。
- **按教义/rite 而非信仰名门控**：活动、custom_loc、结算奖励都查 `rite_has_doctrine`/`rite_has_parameter`，自建信仰自动继承。
- **季节限定**：`current_month` 包在 `custom_description` 里。
- **widget 决议**：`decision_option_list_controller` + `scope:<option> = yes` + 变量记选择 + AI 单独随机（舒什塔尔、比亚克；斯里兰卡的印度赐地）。
- **县级/全局计时**：带 `days` 的全局变量当冷却，县 scope 延时事件防继承丢失。
