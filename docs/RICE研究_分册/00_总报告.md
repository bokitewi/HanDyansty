## 1. RICE 是什么：规模与 44 个风味包

### 1.1 一句话

RICE 是一个"**地区风味包合集**"：作者每隔几个月做一个以某个小地区为主题的"迷你 DLC"，每个包都包含开局改地图、新历史人物、决议、活动、事件、建筑、特质、音乐和插画。5 年多下来累计 44 个包，覆盖从冰岛到大洋洲的各个角落。欢迎事件写着"RICE currently includes 44 Flavor Packs"（`localization/english/rice_misc_l_english.yml:7-8`）。

## 2. 设计思路：RICE 的七条设计哲学

这些是从 44 个包里反复出现的做法归纳出来的，不是作者的自述。

1. **小地区、深挖掘**。不做全图系统，而是挑一块原版几乎没有内容的地方（锡瓦绿洲、索科特拉、帕米尔、格陵兰），把当地的宗教、节庆、物产、名人、史料逸事一次做透。每个包都像一篇"地方志"。

2. **一切叠加在原版之上，不改原版一个字**（§4）。开局用脚本改世界，运行时用钩子挂逻辑。这是 RICE 能连续跟进五年版本、又能和几乎所有大型 mod 共存的根本原因。

3. **史料优先，并且把史料和玩法分开**。人物、特质、建筑的注释里写出处和可靠度，虚构人物明确标 `# Fictitious`（分册 06 §12.2）。几乎每个决议和关键事件都附一段"Historical Context"史话，**由游戏规则 `RICE_historical_context` 控制，玩家可关**；全 mod 有 530 处检查（分册 10 §3.2）。

4. **原版机制做骨架，自己只写血肉**。后期大包都借原版机制：斗争（西西里、诺曼底、斯里兰卡、格陵兰）、局势（尼罗河、巴克特）、故事循环、活动、旅行、传奇、无地冒险者、贵族家族、`decision_option_list_controller` 多选决议、原版一次性决议列表 `unavailable_unique_decisions`。RICE 几乎没有自写的复杂 GUI。

5. **"可能发生"而不是"必定发生"**。史实大事用"随年份递增的每年概率"触发（分册 10 §2.3）；独特工程按开局日期预填"已发生"（分册 05 §0.5）；AI 的 `ai_will_do` 按年代逐档加值（分册 01 §6.9）。历史大体会按时间推进，但每局都有变数。

6. **一切可开关**。欢迎事件、史实背景、音乐（含"无人声"档）、新人物、事件频率、廷臣刷新、各族群和宗教的"出现时点"、四个斗争、各斗争难度，都有游戏规则（分册 10 §3）。

7. **对玩家友好的显性目标**。人物目标不是隐藏加成，而是写在修正描述里的"任务书"，右上角有提醒，完成时有专门的结算事件（§6.1）。

## 3. 代码语言与工程规范

### 3.1 命名

- **文件**：`RICE_<包>_<类型>.txt`（如 `common/scripted_effects/RICE_siwa_effects.txt`、`events/RICE_siwa_events.txt`、`localization/english/rice_siwa_l_english.yml`）。**双下划线 `RICE__` = 跨包核心**（`RICE__game_start_effects.txt`、`RICE__misc_effects.txt`），因为 `_` 排在小写字母前，核心文件总先加载（分册 10 §8.1）。
- **前缀控制排序**：`00000000_` 桩函数最先加载；`00_` 头衔、纹章、兼容桩；`000_` 遗产（界面靠前）；`zzz_` 旅行选项排在原版之后；`zzzzz_RICE_placeholder` 占位文化排在最后。
- **键名**：几乎都带 `RICE_`：效果/触发器 `RICE_<包>_*`、主题 `RICE_theme_*`、背景 `RICE_background_*`、人物 `RICE_<包>_NNN`、冒险者头衔 `d_laamp_RICE_*`。**例外是事件 namespace 直接用包名**（`siwa.0051`），只有核心用 `RICEintro / RICEmisc / RICEdebug`。

### 3.2 事件文件

51 个事件文件中 44 个在文件头写 ID 分段表，每段前再重复一个横幅并写 "reserved"（全 mod 102 处），例：

```
# hangzhou.0000-hangzhou.0019			Setup events, history events, miscellaneous events and decisions
# hangzhou.0020-hangzhou.0029			Minor decisions
# hangzhou.0030-hangzhou.0049			West Lake activity events/decisions
# hangzhou.0070-hangzhou.0079			Lu You flavor
# hangzhou.0080-hangzhou.0099			Poetry Gathering events
```
（`events/RICE_hangzhou_events.txt:1-13`）

每个事件上方一行英文概要，选项后注释意图，on_action 随机池里每个事件后注释内容。被放弃的代码整段保留并注释原因（"Superceded with the new situation"）。

### 3.3 典型脚本写法

| 写法 | 用途 | 例 |
|---|---|---|
| `character:X ?= { ... }` 安全取人 | 开局给历史人物授地，人物不存在也不报错 | `RICE_siwa_effects.txt:5-19`（分册 10 §1.3） |
| 全局变量（可带 `days`）当状态机和计时器 | 世界进程、一次性锁、冷却 | 八护法、雅兹迪出现、阿尔罕布拉施工 |
| 全局变量列表当"名册" | 角色槽位、谁做过 | `unavailable_unique_decisions`、"埃里克等价人" |
| 只活 1 天的全局变量 | 把随机结果传给本地化显示 | 尼罗河预报（分册 02）、北大西洋 §9.10 |
| 只带图标的空修正 | 任务书 UI | 所有 `*_aspiration_*` 修正 |
| 特质 `track` 经验 | 进度条、双向分支 | 哈芙萨、三轨"西西里领主"、石币四级 |
| `show_as_tooltip` | 决议页只显示预览，实际在事件里执行 | 分册 07 §9.4 |
| `random_list` 给 AI 单独兜底 | widget 决议里 AI 总选第一项（作者注释原话 "Not sure why AI is always picking first option"，`common/decisions/RICE_galicia_decisions.txt:1487`） | 加利西亚、格拉纳达、塔里木等 |

### 3.4 压 error.log 的手段

作者非常在意 error.log 干净（分册 10 §8.4）：

- 永不执行的分支里"登记"变量：`if = { limit = { always = no } RICE_setup_have_to_set_variable_effect = yes }`（`events/RICE__setup.txt:49-52`），被调用的效果把一批变量设了又删，注释写 "Variables need to be set up somewhere or else they'll have an error, which is dumb but oh well"。
- 一个从不被调用的效果，专门用 `has_character_modifier` 列出 60 多个修正，注释 "This is literally needed for the error log to not show a message"（`RICE__misc_effects.txt:7`）。
- 给外部 mod 的人物补王朝（`common/dynasties/00__RICE_other_mods.txt`）。
- 事件标 `orphan = yes` 压"未引用事件"警告。

### 3.5 存档兼容占位

`common/culture/cultures/zzzzz_RICE_placeholder.txt` 预先定义 10 个占位文化（注释 "ensure savegame compatibility w/ future updates"），名单、支柱、创新也有对应占位。测试决议的注释说明了原因："Adding new religions/faiths midway through doesn't work, won't show up. Adding new cultures midway through doesn't work, will cause mismatches for saves"（`common/decisions/RICE__test_decisions.txt:8-10`）。推断作者以后加文化时是"改占位条目"，以保持数据库条目数不变。

### 3.6 调试工具

调试决议只在 debug 模式显示（`RICE__test_decisions.txt:13-21`）；一键效果（造文兰殖民地、切斗争阶段）；**测试后门全局变量**：给随机史实事件加 `modifier = { add = 99999 has_global_variable = RICE_milarepa_testing_on_actions }`，控制台设变量后下个 1 月 1 日必触发（`common/on_action/RICE_events_on_actions.txt:802-805`）。

## 4. 怎样融入游戏本体

### 4.1 机械检查结论（主线程）

| 检查 | 结果 |
|---|---|
| 与原版同路径的文件（common/events/gui/history/localization/map_data/gfx/music） | **0 个** |
| `INJECT:` / `REPLACE:` / `TRY_INJECT:` 等前缀 | **0 处** |
| 数据库顶层键与原版重名 | 文化 219、传统 99、宗教 44、头衔 102、决议 292、效果 905、特质 32、建筑 155、互动 25、游戏概念 127、主题 199、背景 217、书签 18、王朝 217、故事循环 8、斗争 4、局势 2、活动 82……**全部 0 重名**；唯一例外是 6 个纹章 |
| 事件 namespace 与原版冲突 | **0** |

作为对照：汉晋春秋有 **628 个文件与原版同路径**（common 383、events 180、gui 25、history 22、localization 18）。汉晋是大型改制 mod，覆盖原版本来就难免，但这个差距正是 RICE 最值得学的地方（§9.1）。

### 4.2 三件事

分册 10 §0 的总结最精炼：**RICE 只做三件事**：

1. **用全新键名新增数据库条目**（与原版零重名）。
2. **把逻辑挂在原版 on_action 钩子上**，开局用脚本"改写"原版世界。原版文档 `_on_actions.info:106-119` 规定同一个 on_action 只能有一个 `trigger` 和一个 `effect`，RICE 严格照做：
   ```
   yearly_global_pulse = {
       on_actions = { RICE_yearly_global_pulse }
   }
   ```
   （`common/on_action/RICE_events_on_actions.txt:1-3`）不带 effect 的钩子则直接追加 `events` 列表（`on_title_gain = { events = { tuyuhun.0003 ... } }`，`RICE_title_on_actions.txt:7-18`），因为 events 列表跨文件合并。
3. **必须改原版文本的，一律放 `localization/replace/`**；要和别的大 mod 共存的，用"同名共享文件 + 桩函数 + 加载顺序金丝雀"。

### 4.3 两段式开局与包注册表

| 阶段 | 钩子 | 做什么 |
|---|---|---|
| 一 | `on_game_start` → `RICE_setup_on_actions`（`RICE_game_start.txt:1-129`） | 设"RICE 已加载"全局变量；TFE 古代开局开关；通用风味；**44 个包的 setup 效果，一行一个** |
| 二 | `on_game_start_after_lobby` → `RICE_setup_after_game_start_on_actions`（`:132-309`） | 需要知道"谁是玩家""开了什么规则"的事：人物开场事件、按规则删冒险者、加载顺序警告 |

作者注释第二段的理由："Good for anything where you need to know who the players are, or what the game rules are"（`RICE_game_start.txt:131`）。

开局脚本到底改了什么（分册 10 §1.3 脚本统计）：`set_culture` 322、`set_county_culture` 299、`get_title` 272、`set_character_faith` 261、`set_county_faith` 228、`add_trait` 179、`trigger_event` 129、`add_special_building(_slot)` 118、`destroy_title` 84……**RICE 没有 history/provinces，新文化全靠 `set_county_culture` 上地图**。

一个关键细节：给原版文化加传统会挂上冷却变量，RICE 每次都顺手 `remove_variable = tradition_cooldown`（`RICE__general_east_asian_effects.txt:12-27`），玩家开局就能正常改传统。

### 4.4 三层脉冲

| 层 | 钩子 | 作用 | 写法 |
|---|---|---|---|
| 世界导演 | `yearly_global_pulse`（无 root，每年 1 月 1 日） | 决定"历史大事什么时候发生" | `if + 全局变量 + random`，概率随年份递增，先设全局变量再发事件（保证只发生一次） |
| 个人维护 | `yearly_playable_pulse` 的第一个子项（不延迟） | AI 的年度选择、斗争数值、伏藏发现 | 纯 effect；AI 直接给结果，玩家走长事件链（注释 "for performance reasons"） |
| 随机风味 | 年 / 三年 / 五年 / 廷臣 / 史实池 | 地方小事件 | `random_events` + 巨大空权重，子池之间插 `delay = { days = { 8 288 } }` 打散 |

**随机池控频的诀窍**（分册 10 §2.4–2.5）：

```
RICE_events_yearly_pulse = {
	random_events = {
		chance_of_no_event = { value = 30 ... }   # 游戏规则 ±10/±20，战争中 +10
		20000 = 0                                  # 巨大空项
		100 = siwa.0051
		100 = siwa.0057
		...
```

每个地区事件自带地区 trigger，所以对任何一个角色，177 个年度事件里通常只有几个有效；20000 的空项保证"本地事件多的地区"和"本地事件少的地区"都不会被刷屏。估算：有 10 个有效事件时，默认每年约 3.3% 触发一次。频率规则只是把结果乘以 5/7~9/7，真正决定频率的是空项权重。

2. **检测标记**：探测外部 mod 独有的键（`exists = culture:soissons` 判断 TFE，75 处）或外部 mod 设的全局变量（`bap_is_loaded`、`CE_is_loaded`）；自己也设 `is_RICE_loaded_global_variable` 供别人检测。

5. **开局覆盖别人的开局**：CE 也在 `on_game_start` 改县信仰，RICE 检测到后在 after_lobby 再改回去（`RICE__game_start_effects.txt:2468-2573`）。

另外，帕米尔包应 Rajas of Asia 开发者要求，把"给史实人物授地/发志向"拆成单独的效果文件，方便对方整段覆盖（`RICE_pamir_ROA_compatch_effects.txt:2-3`）。

## 5. 人物个人故事是怎么做的

这是用户最关心的问题之一。RICE 没有一个统一的"人物故事系统"，而是有一套**七步流水线**加若干**专门技巧**。

### 5.1 史实人物的七步流水线（分册 07 §9.3 归纳，全 RICE 通用）

1. **history 写人物**：属性、特质附出处注释；传说人物配专属 DNA；`do_not_generate_starting_family` 防止引擎凭空生成家人。
2. **让人物可玩**：进书签（167 个书签头像），或做成无地冒险者（`d_laamp_*` 头衔 + title history + 营地宗旨；AI 控制时按规则 `destroy_title`，分册 05 §0.7）。
3. **开局 setup 校正**：封臣树、亲属、性格（`RICE_remove_personality_traits_effect` 清空再逐条加回，每条写史料注释）；挂志向变量和图标修正。
4. **大厅之后发介绍事件**：`RICE_setup_optional_flavor_events_effect`（受"新人物"规则控制）与 `RICE_setup_non_optional_flavor_events_effect`（有玩法效果，必跑），按 `current_date` 区间分书签（`RICE__game_start_effects.txt:67`、`:274`）。
5. **推进**：年度判定志向条件，或由事件 / 特质 track 推动。
6. **完成事件**：主奖励 + 附加奖励，有时还牵动第三方（拜占庭皇帝、地区内其他玩家）。
7. **死亡**：`on_death_RICE` 的定向事件延续剧情（陆游之死、纳赛尔·霍斯鲁之死）。

> **更正说明**：`events/RICE__setup.txt` 里的 `RICEintro.0003`（按日期分支的"扮演某人"邀请）已是孤儿事件，挂载它的 `RICE_game_start.txt:140` 被注释了。真正生效的"扮演某人"入口是 `RICE__game_start_effects.txt:25` 的 `RICE_setup_character_picker_effect`，而且只装了哈兰包的两位学者（分册 05 §0.2、分册 09）。RICE 现在主要靠**书签 + 冒险者头衔**让玩家扮演史实人物。

### 5.2 历史志向：个人故事的主干

### 5.4 关于 `set_player_character` 的警告

RICE 自己因为它崩溃过。塔里木张议潮"入质长安"整条链被注释掉，原因写在代码里："CAUSING CTDs for some reason due to set_player_character even though it worked fine before"（`events/RICE_tarim_basin_events.txt:7091-7092`），配套的敦煌七大族王朝修正和家族史文本也因此玩家看不到（分册 04 §5.1）。帕米尔、萨法尔的老式换人事件也都已孤儿化。哈兰包仍保留两处 `set_player_character`（`events/RICE_harran_events.txt:2123`、`:2971`）。**结论：要让玩家扮演某人，优先用书签、书签子角色或冒险者头衔，尽量不在事件里换人。**

> 分册 10 §9 第 5 条（"扮演某人……`set_player_character` 切换控制"）和分册 09「本组共性小结」§6 第 3 条（"CYOA 人物开局 + `set_player_character` 换号"）仍把事件换人列为可借鉴做法。两处与本节冲突时，**以本节为准**：CYOA 开局可以借，换人这一步不要借。

### 5.5 人物记忆与编年史：定义了，但几乎没用

RICE 定义了 120 种人物记忆，但全 mod **只有上埃及"祈求好泛滥"活动真正调用 `create_character_memory`**，其余调用全部被注释（分册 05 §10.5、06 §12.4、07 §9.5）。编年史只有十几个，多为原版传奇模板换皮。所以"RICE 靠记忆写人物故事"这个说法不成立。注释掉的原因文件里没写。

## 6. 目标任务是怎么做的

### 6.1 历史志向（Historical Aspiration）：RICE 的目标任务框架

文件头一句话说明了设计取舍："ASPIRATIONS SYSTEM. "Completion" is calculated yearly in on actions to keep things simpler to code."（`common/on_action/RICE_aspirations_on_actions.txt:1-7`）。年度结算文件里共有 37 处志向检查（分册 10 §2.7 脚本统计），分布在十几个包里。

**六个部件**（综合分册 05 §0.4、06 §0.3、10 §2.7）：

| # | 部件 | 实现 | 位置 |
|---|---|---|---|
| ① | 标记变量 | 开局 setup：`set_variable = { name = RICE_historical_aspiration value = flag:sawdan }` | `RICE_sicily_effects.txt:455-466` |
| ② | 任务书 | 一个**只有图标的空修正**（`icon = RICE_aspiration_icon`，数值被注释掉），desc 本地化写"主要目标 / 奖励 / 额外目标"，奖励数值用 `[EmptyScope.ScriptValue('RICE_aspiration_medium_resource_bonus')]` 动态显示 | `RICE_sicily_modifiers.txt:157-160`；`rice_sicily_l_english.yml:487,505` |
| ③ | 提醒入口 | 一个通用 important_action：`check_create_action` 只看 `exists = var:RICE_historical_aspiration`，点击打开人物界面 | `common/important_actions/RICE__misc_actions.txt:5-27` |
| ④ | 文案分派 | 提醒的标题/描述走 custom_loc，按 `var:RICE_historical_aspiration ?= flag:xxx` 分支取不同人物的文本 | `common/customizable_localization/RICE_aspirations_custom_loc.txt:3,287,582` |
| ⑤ | 年度结算 | `yearly_global_pulse → RICE_aspirations_pulse`，按书签分三段（867/1066/1178），对每个人写一个"完全达成"的大 limit，满足就发完成事件 | `RICE_aspirations_on_actions.txt:12-18`；萨乌丹条件 `:111-145` |
| ⑥ | 完成事件 | 调 `RICE_historical_aspiration_fulfilled_effect`（删变量、显示已完成）→ 移除图标修正 → 主奖励 → 逐条检查附加目标发附加奖励 → 通知同地区其他玩家 | `RICE__misc_effects.txt:1608-1614`；`events/RICE_sicily_events.txt:3314` |

**附加目标的记录法**很巧：完成某个附加目标的决议或事件里写

```
if = {
    limit = { has_character_modifier = <志向修正> }
    add_character_flag = <完成标记>
}
```

**只有正在执行该志向的人才会留下标记**，别人做同一决议不受影响（分册 06 §0.3）。

**奖励档位统一**：`RICE_aspiration_tiny/small/medium/large/huge_resource_bonus` = 200/500/1000/2000/4000（`common/script_values/RICE_misc_values.txt:8-15`）。

**任务条件全用原版状态**：陆游要求是宋臣、只持贵族家族头衔、有诗人经验、有压力；萨乌丹要求独立、持有阿普利亚、威望或虔诚等级≥3、南意大利至少 8 县、仍是穆斯林。不需要任何自建计数器。

**变体**：多人共享一个志向（Najah 三兄妹）；反派志向（耶律乙辛：杀死某人及其子女、让皇帝好感≥25，奖励永久钩子）；互斥路线（鲁埃德里）；还有"决议次数 + 特质轨经验 + 所在地"合成的约十年个人成长线（君士坦丁·阿非利加努斯）。

**缺点**：只在年初检测，最长延迟一年；**没有失败分支**（人物条件永久不可能达成时，任务书一直挂着，分册 08 §8）；每个人物的条件硬编码在一个大文件里（但也因此好维护）。

**这一套完全不碰原版野心系统，不改任何 GUI**，零成本就能给每位名人一张任务卡。

### 6.2 一次性决议表 + 开局按日期预填

所有"全图只能做一次"的决议用同一个全局列表 `unavailable_unique_decisions`：`is_shown` 判断不在表里，`effect` 把自己加进去。关键在于 **setup 会按开局日期预先把"史实上已经发生过"的项目写进表**：925 年后开局视为钱镠海塘已建，1089 年后视为苏堤已建（`RICE_hangzhou_effects.txt:225-255`）。同一个决议在不同书签里自动表现为"可做"或"已成历史"，不用为每个书签单独写条件。多阶段链也靠它串：嚈哒复国要求表里先有"收复故地"（`RICE_pamir_decisions.txt:27-30`）。原版自己也用这个列表，所以 RICE 能"监视"原版决议是否已完成（分册 06）。

### 6.3 故事循环做多段任务

北大西洋小型远征是标准模板（分册 01 §6.2）：

```
决议（多选项卡片）把参数写到人物变量
 → 创建故事循环，on_setup 把变量转存进故事、清理人物变量
 → effect_group 按节奏推进：出航 → 三段插曲 → 归来
 → 中途事件只记账（改故事变量）
 → 终点一次性结算发奖
 → 600 天自毁兜底 + 全局互斥锁（"天下只能有一个人先做成"）
```

另有：诺德塞图尔海象狩猎"预掷结果 + 计时器变量 + 季节门槛"；伏藏系统"全局时代节点 → 个人候选 → 年度掷骰 → 旅行 → 领主裁决 → 成长"的开放式循环（分册 05）。

### 6.4 斗争：借原版的壳

| | 西西里 | 诺曼底 | 斯里兰卡 | 格陵兰 |
|---|---|---|---|---|
| 阶段 | 2 常驻 + 2 终结，**可重启** | 3 阶段两两互通，一次性 | 3 阶段 | 4 阶段 |
| 特色 | 终结阶段 `save_progress` 慢慢攒，攒满在 `on_start` 自动结算，10 年后可用决议重启 | 罗洛扮演链以斗争开始为高潮 | 50 个自制催化剂，三寺声望进度条 | 斗争区域锚定在母邦，殖民地本身不在地图上 |

**通用技巧**（分册 03、04、10）：
- 列出原版通用催化剂，就能自动响应原版行为；自制机制用"只为显示"的阶段参数挂到原版斗争面板上，真实效果写在 script_value 里。
- 斗争作用域的隐藏事件每年给自己续期，把婚姻、技能、独立与否等持续状态折算成催化剂。
- 时间漂移只指向衰落，按"已发生的史实压力数"激活更高档，玩家靠行动往回顶（格陵兰）。
- 昂贵计算每年缓存一次成全局变量（西西里三世界支配度）。

### 6.5 局势：区域长期目标

尼罗河局势每年换一个水情阶段，当年抽到的预报用"只活 1 天的全局变量"传给通知事件；巴克特局势两个子区域各按"谁做的"累计催化剂（分册 02 §4）。

### 6.6 进度条与多选决议

**进度条链路**（分册 04 §6.4、10 §5.4）：`script_value` 算出当前值和剩余值 → 自定义 `progressbar` 类型（`gui/RICE_progressbar_types.gui`）用两块的 `layoutstretchfactor_horizontal` 之比画出进度 → 嵌进 `decision_view_widget` → 决议窗口显示。**完全不覆盖原版 GUI**。

**多选决议**：原版 `decision_option_list_controller` + 自制组件，玩家多选，AI 走专用项并在 effect 里 `random_list` 兜底。

### 6.7 工程模板与长周期编纂

- **莫高窟工程**（分册 04 §6.2）：开工时一次性预约 11 个各 20% 概率的途中事件，途中选择会改工程规模，到期按规模结算，之后还有回访事件。
- **CSM 编纂 / 突厥语词典**（分册 07、04）：计数门槛 + 计时器 + 编者死后由继承人接手 + 有限扩编；全局一次性工程有"本人 / 任何人 / 关闭"三态，适配多书签。

### 6.8 其他形态

繁荣度阶梯（苏斯西吉尔马萨：县修正 0~4 档 + 并列工程决议）；请愿决议 + 对方裁决事件（奥尼串珠王冠：被请愿的人可能是玩家）；可逆的地标争夺（阿斯旺三神庙）；全局唯一信物 + 回收出口；一次性国策三选一 + 百年计时 + 年度随机后果（回鹘教会）。

## 7. 各类风味化设计

### 7.1 视听

- **事件背景**：一个背景可以有多个 `background = {}`，按顺序取第一个 trigger 为真的；RICE 用约 44 处 trigger **按事件发生地点自动换图**（分册 10 §5.1）。每个包 2~3 张专属背景图，共 573 个插画文件。
- **事件主题**：组合背景、光照环境、环境音；199 个。
- **音乐**：每个包一份音乐表和音乐播放器封面，逐首注明作者、来源、授权；游戏规则四档：默认 / 不限地区 / 无人声 / 关闭（每首曲目的 `is_valid` 里检查，分册 10 §5.3）。
- **动画与服饰**：TGP 的拱手、摇扇动画；`portrait_modifiers` 按身份或特定人物强制换胡须、冠服。

### 7.2 文本

- **史实背景可开关**：530 处 `RICE_historical_context_on` 检查，正文以 "#emphasis Historical Context:#!" 开头，解释史实与艺术加工的边界。
- **术语注释**：原版 `[Glossary( '显示文字', 'LOC_KEY' )]`，解释文字放 `localization/english/gloss_tooltips/`（例：兰亭事件的"曲水流觞"`WINDING_STREAM_PARTY_GLOSS`）；反复出现的术语才做 game_concept。
- **custom_loc**：志向文案分派；按教义/礼仪（rite）而不是按信仰名分支，自建信仰自动继承（分册 09）。
- **trigger_localization**（44 个文件）与 effect_localization：条件文字和效果提示的显示。
- **民俗禁忌做成性格测验事件**：白菜、蓝衣、鸟叫、肉类混食、梦境（分册 09）。
- **改原版文本的唯一出口**：`localization/replace/`。

## 8. RICE 的通病与作者踩过的坑

### 8.1 作者在注释里写的引擎坑（最有参考价值）

| 坑 | 作者的绕法 | 出处 |
|---|---|---|
| 斗争 `on_start` 里 `trigger_event` 不生效 | 改到 `start_struggle` 调用处之后 | 分册 01 §10.4（struggles:36） |
| `start_struggle` 的 `start_phase` 只认定义里的起始阶段 | 再调用一次 `change_struggle_phase` | 分册 01 §10.4、03 §9.1 |
| 全局 on_action 的 effect 里发年度资源不正常 | 改成给每个人发隐藏事件 | 分册 01 §10.4 |
| 消息里的随机数显示与实际不一致 | 先存成变量再显示 | 同上 |
| `random` 的 `chance` 引用 script_value 失败 | 内联 modifier | 同上 |
| widget 决议 AI 总选第一项 | effect 里给 AI 单独 `random_list` | 多处 |

| 模板 `dynasty = generate` 未暂停时崩溃 | 注释掉 | `RICE_character_templates.txt` |

### 8.2 读代码发现的问题类型（各分册共 60 多条，详见各分册"问题与局限"）

1. **复制粘贴残留**：文件头写错包名（哈兰写 AACHEN、胡齐斯坦写 Niger Delta）；布列塔尼志向事件残留西西里包的 scope 和修正；完成奖励里残留别的包的军队。
2. **结局键 / 键名写错**：格陵兰三个结局都传融合结局的决议名；诺曼底"同化""外人之轭"都传"征服"的结局键（`events/RICE_normandy_events.txt:792`、`:832`）；朝圣 curiosity 意图判断写成了 model 意图，19 个朝圣的该项奖励全是死代码。
3. **单位写错**：格陵兰东聚落宽限计时器把天数写进 `years = 3650`，自然崩溃结局几乎不会触发。
4. **死催化剂 / 死规则**：催化剂只在阶段里登记、没有任何激活代码；斯里兰卡难度规则零引用；已删除的规则仍被检查。
5. **提示与代码不一致**：阶段参数本地化写 +50%，代码乘 1.2；诗会意图说明与实际不符。
6. **整段注释的空壳**：汉化改名 GUI、东亚行政头衔、7 个宣战理由文件、通用地方朝圣中枢、兼容头衔、势力。
7. **性能隐患**：发现格陵兰时对全欧洲统治者（含 AI）发可见事件；大量 `create_character` 的投奔事件。

**结论**：RICE 的设计和框架非常值得学，但**代码细节不能整段照抄**，每个借过来的片段都要对照分册里的问题清单检查。

## 9. 汉晋春秋借鉴清单

> 按"投入产出比 + 与本 mod 现有系统的契合度"排序。每条写清 RICE 的做法、对应到汉晋的哪个现有系统、要注意的坑。**这里只列清单，不改任何文件**；真要做哪一条，再逐项确认。

### 第一档：架构层面，越早做越省事

**1. 新系统一律走"零覆盖"路线**
- RICE：0 个同路径文件，靠新键 + on_action 追加 + replace 本地化（§4）。
- 汉晋现状：628 个文件与原版同路径。历次日志审计和原版同步里反复出现"旧副本遮蔽原版"的问题：文本重写时删掉了遮蔽原版的 `buildings_l` / `core_l` 旧副本；原版同步时删了 52 个与原版内容一致的文件；国库预算 gui 的旧副本要换回原版；出生事件 birth.1003 被禁用后照搬原版恢复。
- 建议：既有覆盖不必推倒，但**新做的系统**（剧本、历史线、导演层）尽量不再新增同路径文件；必须改原版行为时，优先找原版的钩子、全局列表、规则和变量接口（§4.5），找不到再覆盖，并在维护文档里登记"为什么覆盖"。

**2. 剧本开局用"包注册表 + 两段式"**
- RICE：`on_game_start` 一行一个 `RICE_setup_<包>_flavor_pack_effect`；需要知道玩家和规则的事放 `on_game_start_after_lobby`（§4.3）。
- 汉晋现状：`zz_hd_184_new_setup`、`zz_hd_190_startup`、`zz_hd_22_startup`、`zz_hd_218_startup`、`zz_hd_253_relay` 等十几个剧本开局各自挂钩子；剧本国号曾因执行顺序问题挪到 `on_game_start` 末尾。
- 建议：建一个总注册 on_action，按剧本日期分支、一行一个剧本 setup，注释写剧本名和最后修改日期。排查开局卡顿、执行顺序和"某剧本没跑"时，看一个文件就够了。
- 注意：**凡是要在书签界面或大厅里看得到的东西（国号、书签人物的头衔与领地）必须留在 `on_game_start`**，因为大厅在 `on_game_start_after_lobby` 之前显示（剧本国号就是为此挪到 `on_game_start` 末尾的）。只有"取决于谁是玩家 / 开了什么规则"的事才挪到 after_lobby。

**3. 一次性史实节点用 `unavailable_unique_decisions` + 开局按日期预填**
- RICE：同一个决议在不同书签里自动表现为"可做"或"已成历史"（§6.2）。
- 汉晋契合度：**极高**。本 mod 有 22、89、184/190、218、253、263、304、346、370、404、617 等十几个剧本，"某事在这个剧本开局时是否已经发生"是反复出现的问题（263 改库卒年、253 复原条目、89 两头不漏规则等）。
- 建议：太学兴办、迁都、禅代、称帝、汉化改制这类"全图一次"的节点统一进一个列表；每个剧本的 setup 按日期预填已发生项。原版也用这个列表，还能顺带监视原版决议是否已完成。

**4. 世界导演用"随年份递增的每年概率 + 一次性全局变量 + 测试后门"**
- RICE：`yearly_global_pulse` 里 `if + 全局变量 + random`，概率逐年加码，先设变量再发事件；每个大事件留一个 `+99999` 的测试变量（§4.4）。
- 汉晋对应：历史事件规则（`zz_hd_history_events_rules.txt`）、184 流程导演层 `hd184r_director`、历史入侵、天灾。
- 建议：把"固定日期必发"的史实事件改成"史实年份附近概率最高"；每个事件配一个测试后门全局变量，测试时控制台一设、下个月或下个年初必触发，省掉等待。

**5. 随机风味池用巨大空权重控频**
- RICE：`20000 = 0` + 每个事件 100 + 事件自带地区 trigger（§4.4）。
- 汉晋现状：部分池子是 `1000 = 0`。
- 建议：做"州郡风物事件"时照搬：各州郡事件自带 `geographical_region` trigger，空项权重按池子总量设，游戏规则只调 `chance_of_no_event`。这样事件多的州不会刷屏，事件少的州也不会冷清。

**6. 兼容层约定（汉晋 ↔ HanJin_Clothes / UUII / 子 mod）**
- RICE：`00000000_` 桩触发器、`is_RICE_loaded_global_variable`、同名共享文件、金丝雀（§4.6）。
- 建议：开局设 `is_HD_loaded_global_variable` 供子 mod 检测；给 HanJin_Clothes 这类依赖定义桩触发器（例如 `hd_hanjin_clothes_loaded = { always = no }`，由服装 mod 覆盖成 yes），缺依赖时自动降级而不是报错；对加载顺序敏感的地方埋一个金丝雀值，开局检测并提示。

### 第二档：人物故事与目标任务

**8. 把"天意青睐"改造成看得见的历史志向**

## 10. 未验证项

以下是各分册标注为"推断 / 未验证"、又会影响能否照搬的引擎语义问题，建议在实际借用某个模式前先在游戏里做最小测试：

1. 同键 scripted_trigger / effect 是否按文件名排序靠后者生效（桩函数手法的前提；RICE 注释支持，原版文档未明说）。
2. 同一头衔的历史块分在两个文件时，是合并还是后者覆盖（`k_nubia`）。
3. 6 个与原版重名的纹章，哪个生效。
4. `000_` 文件名前缀与执行先后是否有关。
5. 局势换阶段时积分是否清零；双子区域局势下 `situation_current_phase` 读哪个子区域。
6. 斗争"自指阶段"（边缘化阶段把自己列为下一阶段）引擎怎么处理。
7. 模板 `after_creation` 在 1.20 是否执行。
8. `create_artifact` 默认归属当前角色、artifact 描述随机文本是否每次重抽。
9. 给死人改文化是否可靠（假人锚点手法的前提）。
10. RICE 注释掉人物记忆的原因。

各分册的"问题与局限"一节另有约 60 条具体 bug（文件 + 行号），借用对应代码前请先对照。
