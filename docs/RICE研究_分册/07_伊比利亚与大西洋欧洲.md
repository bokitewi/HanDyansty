## 1. 加利西亚（Galicia / `galicia`）

### 1.1 主题与史实背景

包名「The Way of Saint James」（`common/on_action/RICE_game_start.txt:103`）。主题是西班牙西北部的加利西亚（不是罗斯的加利奇，后者是 `galicia2`，见第 2 节），包括以下内容：

- **圣雅各墓的发现（9 世纪）**：隐士佩拉约看见天火，找到罗马墓地和使徒墓（`localization/english/rice_galicia_l_english.yml:713`）。
- **迭戈·赫尔米雷斯改建祭坛（12 世纪初）与 1117 年圣地亚哥起义**：本地人认为拆毁使徒门徒所建的旧墓是亵渎，秘密兄弟会 *germanitas* 发动暴动（同文件 `:586`、`:748`、`:752`）。
- **圣地亚哥朝圣之路**：沿途基础设施建设与过路税。
- **加利西亚-葡萄牙语抒情诗**：cantigas de amor / de amigo / de escarnio。
- **阿方索十世的《圣母玛利亚歌集》**（Cantigas de Santa Maria，下文简称 CSM）。
- **地方风味**：皮科萨克罗山、奥伦塞 As Burgas 温泉、刀匠黑话 Barallete、摇石、hórreo 粮仓、mouros 传说、卢帕女王等。

**effects 文件为什么有 168KB？** 原因不是可变状态系统，而是组合枚举。真正的状态只有四样：

1. `var:RICE_cantiga_type`：体裁，取值 `flag:courtly_love`、`flag:romantic_love`、`flag:satire`；
2. `var:RICE_cantiga_quality`：品质，取值 `flag:acceptable`、`flag:good`、`flag:excellent`；
3. 主题槽 flag：`RICE_galicia_cantiga_theme_{1|2|3}_<主题>`，以及选中后的 `..._chosen_theme_<主题>`；
4. 计数 `var:RICE_num_of_cantigas_written`。

但作者把「25 个主题（5 技能各 5 个）× 3 个槽 × 3 种随机修正 × 普通/优秀两档 × 道具化」全部手写成 if/else，于是体积暴涨：

- 3 个抽主题效果各约 260 行（`:921`、`:1181`、`:1442`）；
- 品质判定（`:1763`）；
- 三档完成效果，每档对 25 个主题各做 3 选 1 的 random_list（`:2036`、`:2644`、`:3253`）；
- 75 分支的道具化效果（`:3362-4427`）；
- 75 分支的 tooltip 显示效果（`:4496-5552`）。

```

       └─ galicia.0013：用原版模板 mendicant_mystic_character 现场生成隐士"佩拉约" (events:591)
            └─ galicia.0014：邀请佩拉约入宫（-250 威望）/ 让他回荒野（death_vanished，events:659）
                 └─ galicia.0015：通知西欧、南意、西北非的所有玩家
                      └─ 解锁三个反复可做的决议：祈求圣雅各 / 支持朝圣路 / 征收过路税
  └─ 决议「改建圣雅各墓」(需圣地建筑 holy_site_basilica_santiago_01，decisions:161-166)
       └─ galicia.0020：把决议人存进全局列表 RICE_galicia_altar_alterer_list (events:966-967)

```

**B. 圣雅各之路：两种互斥身份，五档距离**

支持朝圣路的决议给 `RICE_galicia_way_of_saint_james_supporter`（10 年），征过路税给 `..._robber_baron`，两者互斥（`common/decisions/RICE_galicia_decisions.txt:610-613`）。实际效果按「县离加利西亚多远 × 控制度高低」分五档县修正，由五个 effect 依次执行（`events/RICE_galicia_events.txt:265` 起；`common/scripted_effects/RICE_galicia_effects.txt:82-455`）。费用和收益都用 script_value 按县数累加（`common/script_values/RICE_galicia_values.txt:2-55`：每个伊比利亚/奥克县 +10，下限 50，上限 150）。非基督徒也能做，给的是「非基督徒版」修正。

**C. 圣雅各代祷：结果随原版「伊比利亚之争」阶段变化**

`galicia.0011` 的描述和 `RICE_galicia_saint_james_prayer_warrior_effect`（`common/scripted_effects/RICE_galicia_effects.txt:456`）都读取原版 `struggle:iberian_struggle` 的当前阶段（`events/RICE_galicia_events.txt:297`）：

- 敌对阶段：圣雅各以「摩尔人杀手」战士形象显灵；
- 和解阶段：以传教者形象显灵；
- 妥协/机遇阶段：以朝圣者形象显灵；
- 如果 struggle 已经结束，就读结局全局变量 `fp2_struggle_*_ending`。

结果分四档：40% 无事，其余为 minor/major/great。权重受美德特质数、罪恶特质数、狂热/犬儒影响，结果用 `send_interface_toast` 弹出。

### 1.5 人物个人故事

- **「谁做谁就是历史人物」的角色化 scope**：本包几乎没有写死的事件主角。做改建决议的人被 `save_scope_as = diego_gelmirez`（`common/decisions/RICE_galicia_decisions.txt:202`），编纂 CSM 的人被命名为 `scope:alfonso_x`（`events/RICE_galicia_events.txt:3077` 起）。本地化用这些 scope 名来叙事。这样沙盒里任何满足条件的玩家都能「成为」赫尔米雷斯或阿方索十世，史实感和自由度兼得。
- **现场生成的配角**：隐士佩拉约用原版模板 `mendicant_mystic_character`（`[原版] common/scripted_character_templates/00_mystic_templates.txt:271`）在事件里生成（`events/RICE_galicia_events.txt:591`），他和宫廷牧师互加「共同发现圣墓」好感。玩家选择让他入宫还是让他消失。
- **史实诗人家族**：`history/characters/RICE_galicia.txt` 收录「第一位加利西亚-葡萄牙语诗人」若昂·索阿雷斯·德派瓦一家四口。父亲 `RICE_de_paiva_01`（`:19`）的妻子直接引用原版角色 `142145`；若昂本人 `RICE_de_paiva_02`（`:39`）有诗人、旅行者特质。注释里写明了史料来源和年代推断理由，这一点值得学。
- **可扮演**：若昂有冒险者头衔 `d_laamp_RICE_joao_poet`（定义 `common/landed_titles/00_RICE_galicia_titles.txt:5-18`，`dlc_feature = roads_to_power`，`ai_primary_priority` 设为 -1000，避免被 AI 当主头衔）。1178 书签用 title history 把他立为无地冒险者（`history/titles/RICE_laamp_titles_1178.txt:462-478`），写法见下：

```
d_laamp_RICE_joao_poet = {
	1178.1.1 = {
		liege = 0
		holder = RICE_de_paiva_02
		government = landless_adventurer_government
		succession_laws = { landless_adventurer_succession_law }
		effect = {
			create_landless_adventurer_title_history_effect = yes
			set_variable = { name = adventurer_creation_reason value = flag:historical }
		}
	}
```

- **编年史 / 传说**：`RICE_galicia_csm_legend` 定义了 `compiler`、`culture` 两个属性和五个章节，影响给持有者 `+2` 个人计谋成功率、`+5` 基督教好感（`common/legends/chronicles/RICE_galicia_chronicles.txt:1-27`）。CSM 完成时 `create_legend_seed` 把编纂人写进传说（`events/RICE_galicia_events.txt:3159-3170`）。这是本组里唯一接入原版传说系统的地方。
- 角色记忆、角色模板：本包没有自定义的。

### 1.6 目标任务

- **CSM 三段式项目**：先用计数门槛（写过 3 首 cantiga）把小系统和大项目串起来，再走 5 年计时，最后最多扩编 3 次。计时器用带 `days` 的全局变量，由历史池每年评估，到期后触发收尾事件。
- **一次性注册表**：发掘圣墓、改祭坛、建礼拜堂、CSM 编纂都往 `unavailable_unique_decisions` 塞 flag（例如 `common/decisions/RICE_galicia_decisions.txt:197-200`、`:356-360`），setup 再按开局年份预先登记。

### 1.10 问题与局限

1. **tooltip 复制粘贴错误**：`galicia.0030` 选项里第二个 `else_if` 又判断了一次 `courtly_love`（`events/RICE_galicia_events.txt:1402-1407`），所以 romantic_love 体裁永远没有 tooltip。
2. **flag 写在一个人身上，却去另一个人身上读**：`galicia.0023` 把伤情 flag 加在 root（圣地亚哥现任持有者）身上（`:1164`），`galicia.0024` 却从全局列表取「改祭坛的人」`scope:diego_gelmirez_ruler` 来读（`:1150`、`:1233-1249`）。改祭坛的人已死或换了人时，描述段落为空。
3. **人像 scope 可能不存在**：`galicia.0045` 的人像用 `scope:CSM_original_compiler`（`:3349` 起），这个 scope 只在死亡交接链里才有；正常从决议进来时人像为空。
4. **扩编产生多件道具**：每次扩编都新建一件 CSM 道具（`:3432-3443`），旧版本没有回收，宝库会越堆越多。
5. **组合爆炸**：305 个 `else_if`、150 个几乎只差数值的修正，维护成本极高。新增一个主题要改 3 个抽取效果、3 个完成效果、道具效果、显示效果，加上 6 个修正。
6. **宗教写死**：大量 `religion = religion:christianity_religion`，换成别的宗教体系时要逐条改。

### 本包可迁移的设计模式

1. **体裁 widget + 三随机主题 + 品质随机表**：可以做成汉晋的「诗赋 / 乐府 / 檄文创作」。按建安文学分体裁，主题按五技能分类，用计数当经验。实现时别学它的写法：主题存成一个 `flag` 变量，名称交给 customizable_localization 或 `switch` 处理，修正改用 script_value 参数化，体积能压到十分之一。
2. **计数门槛 → 长周期编纂 → 死亡由继承人接手 → 有限扩编**：几乎是为「班固著《汉书》、班昭续成」量身定做的模板。《东观汉记》、陈寿《三国志》、裴注也能套用。
3. **角色化 scope**（`diego_gelmirez`、`alfonso_x`）：不绑定具体人物 ID，谁满足条件谁就是那个「历史角色」。适合沙盒里的「董仲舒式献策」「蔡伦式改良」。
4. **阶段感知的风味**：同一个祈祷事件按原版 struggle 阶段分三种叙事。汉晋可以按你们的王朝周期阶段（`hd_cycle_phase_triggers`）给同一个决议分「治世 / 乱世 / 分裂」三种结果。
5. **一次性注册表 + 开局按年份预登记**：开局年份晚于某个史实事件时，直接把它登记为已发生，避免剧本开局后重复触发。
6. **全局变量阶段 + 0~365 天随机延迟**：用于「祸根已埋 → 一年内爆发」的史实危机，比如党锢、黄巾起事的前兆。
7. **legend seed**：重大文化成就自动生成传说，接入原版传说系统。

### 2.5 人物个人故事（重点）

本包是「史实人物定向剧本」写得最完整的一个，手法可以拆成六步：

### 2.10 问题与局限

1. **离婚对象可能不存在**：`galicia2.0033` 选项 a 无条件执行 `divorce_effect { DIVORCEE = scope:old_spouse }`（`events/RICE_galicia2_events.txt:1371`）。罗曼未婚或允许多配偶时 `old_spouse` 不存在，会刷报错。

4. **跨包依赖**：库帕拉借用 Normandy 包的本地化键。删掉 Normandy 本地化，库帕拉就会显示键名。

### 本包可迁移的设计模式

1. **历史志向套件**（变量 + 空图标修正 + 重要提醒 + 自定义本地化 + 年度判定 + 主/附加奖励）：直接对应汉晋的「刘备复兴汉室」「孙策平定江东」「曹操挟天子」。你们的 `project-historical-rise` 已有类似引擎，可以借它的 UI 呈现方式：图标修正当任务日志，重要提醒做入口。
2. **开局用 effect 校正封臣树和亲属关系**，而不是改 history 文件，更不易被编辑器保存冲掉。你们的 `project-e-han-holder-loss` 正是被编辑器坑过。
3. **定向死亡引爆继承危机**：互相获得已主张宣称，加一支事件军。可套用袁绍死后袁谭、袁尚相争，或刘表死后刘琦、刘琮相争。
4. **第三方裁决的结局**：先问皇帝、再问主角。适合「天子赐婚 / 赐九锡」。
5. **单 phase 节庆加事件链推进**：上巳修禊、重阳登高，都可以用这个最小活动骨架。

```
		limit = { is_available_ai_adult = yes religion = religion:judaism_religion }

	}
}
else = {
	create_character = {
		location = root.location

```

史实人物在场时用史实人物，不在场时用宫廷里的合适角色，再没有就现场生成。同一个历史事件因此能在任何时间线复现。

### 3.10 问题与局限

1. **AI 可能重建已有建筑**：Alhambra 的 AI random_list 没有排除已建的史实建筑（`common/decisions/RICE_granada_decisions.txt:221` 起，八个分支都没有 trigger），玩家用的 widget 却有 `is_shown` 过滤。
2. **结局判定晚一步**：哈芙萨的 upgrade 判定写在「加经验之前」（effect 先调 upgrade 再 `add_trait_xp`，`events/RICE_granada_events.txt:1771-1786`）。达到 100 点后要等下一次行动才会结局。
3. **死文件**：`decision_view_widget_RICE_granada_munya_decision.gui` 整个文件被注释掉，是早期「munya 决议」改成活动后的残留。
4. **记忆未启用**：munya 的三种记忆已定义（`common/character_memory_types/RICE_granada_character_memories.txt`），但 `create_character_memory` 全部注释掉了（`common/activities/activity_types/RICE_granada_munya_vacation_group.txt:682-690`；private `:676`）。
5. **屠杀效果过重**：直接杀掉宫廷 60% 的犹太人，对玩家宫廷冲击大，而且没有任何预警 tooltip。

### 本包可迁移的设计模式

1. **特质 track 双向进度条加两种结局**：最适合汉晋的「人物心路」，比如蔡文姬归汉（悲愤 / 释然）、嵇康（狂狷 / 隐逸）、诸葛亮出山前（躬耕 / 应聘）。
2. **县修正当状态**：危机的前、中、后都是县修正，后续事件（廷臣来投）读修正决定是否出现。可用于「党锢余波」「黄巾余党」在州郡留下的社会状态。
3. **受害者 / 主角三级回退**：保证史实事件在不同时间线都能复现。
4. **全局施工许可证加随机工期**：营建洛阳南宫、邺城铜雀台、建业宫城等，适合「天下只有一座」的营建项目。
5. **活动时长选项映射为事件延迟**：不用多写 phase，用 `days` 区间模拟「玩得久」。

### 5.9 写法亮点

- **传统参数解锁互动**：赠马互动的 `is_shown` 检查 `culture = { has_cultural_parameter = bao_horse_gift }`，或领地里有放牧建筑（`common/character_interactions/RICE_breton_character_interactions.txt:40-65`）。互动和文化传统、建筑形成一条「文化特色产业」链。
- **性格专属事件**：`weight_multiplier = { base = 0  modifier = { add = 0.5 has_trait = greedy } ... }`（`events/RICE_bao_events.txt:344-345` 起），只有贪婪、冷酷、虐待狂、草药师会被 korrigan 骚扰。

### 5.10 问题与局限

1. **复制粘贴错误（tooltip）**：`breton.0001` 的 tooltip 对 `scope:sawdan` 执行（`events/RICE_breton_events.txt:61`），这是 Sicily 包萨乌丹志向的残留，所以 tooltip 不显示。
2. **复制粘贴错误（志向修正）**：`breton.0002` 移除的是 `RICE_sicily_aspiration_establish_islam_in_southern_italy`（`:112-114`），不是布列塔尼的志向修正。康斯坦丝完成志向后图标会一直挂着。
3. **记忆未启用**：Tro Breizh 的记忆调用被注释掉（`common/activities/activity_types/RICE_breton_tro_breizh.txt:652-660`）。
4. **命名不统一**：BAO 用 `bao_` 前缀，与 RICE 其他部分的 `RICE_` 前缀混用，可读性差。

### 本包可迁移的设计模式

1. **单地点加连串站点事件的「虚拟巡游」**：秦皇汉武的东巡、封禅之路、司马迁游历、法显西行，都能这样做，不用处理真实行军路径。
2. **把社区子包整体吸收**：保留原作者前缀和署名，用 setup 统一接入。
3. **传统参数 → 互动 / 建筑**：例如「蜀锦」传统解锁赠锦互动。
4. **`base = 0` 的性格专属事件**：让风味事件有人设针对性。

### 6.10 问题与局限

1. **客人借旗会刷报错**：只有 host 有朝圣计数变量，客人却也拿到「完成朝圣」flag。客人去借旗时，旗帜效果读一个不存在的变量（`common/scripted_effects/RICE_yorkshire_effects.txt:168`），会刷报错，最后靠 failsafe 拿到 1 级旗。
2. **请愿不能拒绝**：letter_event 只有同意选项（`events/RICE_yorkshire_events.txt:1194-1220`），主君的态度对结果没有影响。
3. **头盔 3D 资源疑似占位**：用的是王座实体。
4. **记忆未启用**：奔牛和朝圣的记忆类型都已定义，但没有调用。
5. **旧代码残留**：被注释掉的旧结局事件还在调用原版 `pilgrimage_additional_reward_effect`（`events/RICE_yorkshire_events.txt:664`；`[原版] common/scripted_effects/00_pilgrimage_effects.txt:94`），说明早期版本直接复用原版朝圣奖励，后来改成 RICE 自己的通用奖励。

### 本包可迁移的设计模式

1. **多地收集目标加全部完成后整体升级**：汉晋可以做「关市 / 互市」，例如上谷、宁城、合浦、敦煌四处胡汉互市全开后升级。
2. **封臣自掏威望向主君请愿**：适合「州牧上表请封」。如果给主君加上拒绝选项，就是一个小型君臣博弈。
3. **全局唯一信物加三出口回收**：传国玉玺、节钺、虎符、天子剑都可以套用。
4. **活动次数决定后续奖励等级**：例如祭孔次数决定「孔子后裔礼遇」的等级。
5. **史实起源事件解锁年度节庆**：先发生一次史实起源，之后才允许每年举办。
6. **延时 1~10 年的个人道具事件**：比如诸葛亮的木牛流马、关羽的青龙刀。

- **场景图与主题**：`RICE_aachen_forest.dds`、`RICE_aachen_gatehouse.dds`；主题 `RICE_theme_aachen_forest/gatehouse`（`common/event_themes/RICE_event_themes.txt:383-395`）。
- **其他**：决议插图 `decision_RICE_charlemagne.dds`；音乐 `mx_amber_melancholy`、`mx_an_inadvertant_rift`、`mx_calm_before_the_storm`、`mx_end_of_shallow_thinking`；事件内点播原版 cue `mx_cue_sacredrite`（`events/RICE_aachen_events.txt:731`）。

### 7.9 写法亮点

- **先在 immediate 里随机定结果，再让描述按结果显示**：避免描述和结果脱节，是「随机奖励事件」的标准写法。
- **按年代加权的史实事件**：`aachen.0005` 的权重从 1100 年后逐步升高，到 1250~1350 年达到最高（`events/RICE_aachen_events.txt:166-190`），模拟「史实上大约在这时发生，但会有浮动」。约克郡奔牛起源的写法相同。

### 7.10 问题与局限

1. **记忆全部未启用**：五个记忆类型都没有调用（`events/RICE_aachen_events.txt:47, 107, 540` 处被注释）。
2. **没有人物**：`history/characters/RICE_aachen.txt` 是空壳，人物故事维度薄弱。
3. **注释意图不明**：宝库胸像分支的 `SHOULDNT HAPPEN` 注释（`:908`）与它的 trigger 不一致，作者意图不清。

### 本包可迁移的设计模式

1. **一次性决议改写活动的举办范围**：比如「迁都洛阳」后，太学 / 灵台类活动的举办范围随之改变。
2. **修正当软冷却**：不用写冷却变量，修正到期就是冷却结束。
3. **按性格加权的随机感召，描述按结果显示**：例如谒孔庙时，「见礼器 / 见遗书 / 见车服」三种感召按性格加权。
4. **按年代加权的史实事件**：例如黄河改道、地震、蝗灾在史实年份附近概率最高。

### 8.1 演化：从「一个中枢活动」拆成「每地一个克隆」

`common/activities/activity_types/RICE_local_pilgrimage.txt` 共 819 行，其中 736 行是注释。它原本是一个通用的「地方朝圣」活动，phase 里按目的地男爵领分派到达事件（被注释的 `:199-235`）：

```
# 				if = {
# 					limit = { this = scope:host }
# 					# Patmos Pilgrimage
# 					if = {
# 						limit = { involved_activity.activity_location.barony = title:b_samos }
# 						scope:host = { trigger_event = chios.0106 }
# 					}
# 					# Aachen Pilgrimage
# 					if = {
# 						limit = { involved_activity.activity_location.barony = title:b_aachen }
# 						scope:host = { trigger_event = aachen.0022 }
# 					}
# 					# Tomb of Daniel
# 					if = { …… trigger_event = khuzestan.0022 }
```

现在它被拆成 19 个独立活动，每个地点一个文件，但都共用 phase 键 `RICE_local_pilgrimage_pilgrimage_phase`：aachen、bamian、breton_tro_breizh、chios_patmos、两个科普特修院、khuzestan、mayo_croagh_patrick、normandy、nubia、pamir、sicily、siwa、两个斯里兰卡、两个塔里木、upper_egypt、yorkshire（逐一 grep 过 `RICE_local_pilgrimage_pilgrimage_phase`）。本组用 `diff` 比较了四个克隆，差异只有 131~161 行，集中在：

- 门槛（宗教、地点、距离、特殊 flag）；
- `is_location_valid` 的男爵领；
- phase 的入口事件；
- `province_score` 的加分地点；
- 少数选项的 `is_valid`（冒险者不能选「纪念碑」等）。

比如圣帕特里克山与亚琛：入口 `mayo.0031` 对 `aachen.0022`（克隆文件 `:472` 对 `:482`），地点 `b_castlebar` 对 `b_aachen`（`:526` 对 `:539`）。

**为什么拆开？** 推测有两个原因：

1. 每个地点要有独立的活动名、图标、头图、冷却和门槛，在活动列表里各占一格，玩家更容易发现；
2. 中枢写法的 `province_filter = all` 加上大量男爵领判定，选址性能差。温泉活动的注释就写着 `province_filter = domicile_realm # all # Causing performance issues`（`common/activities/activity_types/RICE_hot_springs_visit.txt:100`）。

### 8.3 事件链模板

```

   → 低概率的意外事件（雷击等）

               skip_activity_phase
```

### 8.4 通用奖励逻辑（`common/scripted_effects/RICE__misc_effects.txt:1285-1601`）

- **奉献**：小 / 中 / 大分别给 50 / 100 / 200 虔诚，大档还给首都发展度进度。
- **意图**：worship 给 +150 虔诚；model 给 +75 虔诚和 +75 威望。
- **参访类型**：
  - devotion：+100 虔诚，朝圣者特质经验 +10（没有特质就先给特质）；
  - observance：+100 威望，10 年「参与地方宗教」修正，朝圣者经验 +5；
  - vacation：大量减压，经验 +5；
  - performance：少量减压，经验 +5。
- **纪念**：按小 / 中 / 大给威望、王朝声望、正统性（`:1503-1600`）。
- **客人**：一律 +50 虔诚（`:1603-1605`）。

### 8.5 温泉与圣井：仍然是中枢式写法

**温泉**（`common/activities/activity_types/RICE_hot_springs_visit.txt`）：

- 不限宗教；选址用 `domicile_realm`；
- `province_description` 为 10 个温泉地写专属描述（`:103-170`）；
- phase `RICE_hot_springs_visit_leisure_phase` 按男爵领分派到 10 个包的到达事件，其他地方走通用的 `RICEmisc.0012`（`:244-331`）：

```
if = { limit = { involved_activity.activity_location.barony = title:b_siwa } scope:host = { trigger_event = siwa.0010 } }
else_if = { limit = { involved_activity.activity_location.barony = title:b_aachen } scope:host = { trigger_event = aachen.0011 } }

else_if = { limit = { involved_activity.activity_location.barony = title:b_ourense } scope:host = { trigger_event = galicia.0018 } }
else_if = { limit = { involved_activity.activity_location.barony = title:b_algeciras } scope:host = { trigger_event = granada.0006 } }
else = { trigger_event = RICEmisc.0012 }
```

- `is_location_valid`：有封地的角色可选最高主君领内任意省份，冒险者只能选驻地（`:396` 起）；
- `allow_zero_guest_invites = yes`（`:527`）；单一意图。

温泉适合中枢写法，因为「到处都能泡温泉，名泉只是加料」，与朝圣「必须去特定圣地」性质不同。

**圣井**（`common/activities/activity_types/RICE_visit_holy_well.txt`）：

- 需要文化有圣泉类传统（`RICE_is_holy_well_culture`）；`province_filter = domain`（`:139`）；
- `is_location_valid` 要求县上有 `TFE_holy_well_level_1/2/3` 修正（`:218-222`）。修正由梅奥的祝圣决议产生（`events/RICE_mayo_events.txt:678` 起）；
- phase 激活后发 `mayo.0021`（`:154-162`）。

圣井是「先用决议在地图上造出可去的地点，再用活动去拜访」的两段式，地点是玩家自己创造出来的。

### 8.7 框架的问题

1. **curiosity 意图的奖励是死代码，19 个朝圣全部受影响**：第三个意图分支又判断了一次 `RICE_local_pilgrimage_model_intent`（`common/scripted_effects/RICE__misc_effects.txt:1324, 1334, 1345`），本地化许诺的「获得生活方式经验」永远不会发放。
2. **performance 选项没有专属效果**：纪念奖励的 performance 分支和 else 分支内容完全相同（`:1503-1555` 对 `:1556-1600`），本地化却说正统性只在选 performance 时才有（`localization/english/rice_misc_l_english.yml` 中 `RICE_local_pilgrimage_type_performance_desc`）。
3. **记忆全部关闭**：本组所有活动的 `on_complete` 记忆代码都被注释掉（克隆文件 `on_complete` 段）。
4. **温泉的 AI 偏好漏了两处**：温泉 `province_score` 的名泉清单缺 Ourense 和 Algeciras（`common/activities/activity_types/RICE_hot_springs_visit.txt:430-440`）。这两处有专属描述和事件，AI 却不会优先选。
5. **维护成本高**：克隆写法要求每个文件改动都同步 19 份。

### 8.8 迁移到汉晋春秋的建议

- **专属地点用克隆，泛用地点用中枢**：泰山封禅、曲阜谒孔、长陵 / 原陵谒陵、白马寺、鹤鸣山适合各做一个克隆；温泉、游猎、访贤适合做一个中枢加地点分派。
- **共用三个选项类别**（参访类型、奉献、纪念）和三个意图，让玩家形成固定的操作习惯。纪念可以对应「刻石」「立碑」「建祠」，很有汉代味道。
- **先修掉上面两个 bug 再借用**：意图分支要逐个检查键名，选项描述和效果要一一对应。
- **出发事件集中登记在 `on_travel_plan_start`**，由事件自己做 trigger 过滤。好处是新增活动时不用改动任何已有文件。

### 9.3 人物故事套件

史实人物剧本的标准流水线：

1. history 文件写人物，属性特质附出处注释，用 `do_not_generate_starting_family` 防止乱生成家人；
2. 冒险者头衔加 title history，或直接进书签，让人物可以扮演；
3. setup 效果校正封臣树、亲属和性格，挂志向变量和图标修正；
4. after_lobby 时给人物发多人像介绍事件；
5. 年度判定志向条件，或者由事件 / 特质 track 推动；
6. 完成事件给主奖励加附加奖励，有时还牵动第三方（拜占庭皇帝、爱尔兰小君主）；
7. 人物死亡时用定向 on_death 事件延续剧情。

本组的 `RICE_setup_character_picker_effect`（`common/scripted_effects/RICE__game_start_effects.txt:25-66`）只处理哈兰包的两位学者，「扮演某人」完全靠书签加冒险者头衔实现。

### 9.4 共同的作者习惯

- **历史背景 tooltip**：几乎每个决议和事件结尾都有，受游戏规则 `RICE_historical_context_on` 控制。
- **按年代加权的史实事件**：`weight_multiplier` 随 `current_date` 递增，加一次性列表防重复。
- **AI 的 widget 补丁**：作者自己也不清楚原因（「Not sure why AI is always picking first option」），统一给 AI 走 random_list。
- **大量 `show_as_tooltip`**：把实际执行放在事件里，决议页只展示预览。
