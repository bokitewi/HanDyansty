## 1. 撒丁（Sardinia「Reign of the Judges」/ `sardinia`）

### 1.1 主题与史实背景
- **撒丁「法官」（judicati）时代**：岛上四个「法官区」名义上依附拜占庭，实际自治。决议说明写的就是这种处境：撒丁「在拉丁西方与希腊东方之间尴尬地摇摆」，现在该由 judicati 决定岛屿向谁靠拢（`localization/english/rice_sardinia_l_english.yml:200`）。
- **帕利奥赛马（Palio）**：意大利城市的传统赛马节，可以办成宗教节日、市民纪念或王朝庆典（`rice_sardinia_l_english.yml:51,62-66`）。史话提示写到，17 世纪前锡耶纳的帕利奥并不绕广场跑，而是从城门外穿城而过（`:464`）；1581 年有一位 12 岁牧羊女 Virginia Tacci 赢得锡耶纳帕利奥（`:477`）。
- **condaghe 文书**：撒丁关于教会财产和机构的行政文书（`:287`），两个风味事件直接取材于 condaghe 里记载的真实案例（`common/on_action/RICE_events_on_actions.txt:1704,1938` 的注释「based on an IRL case recorded in a condaghe」）。
- **德尼亚的穆贾希德家族**：穆贾希德 1015–1016 年进攻撒丁，被比萨和热那亚击败，幼子阿里被俘，带到神圣罗马皇帝宫廷（`history/characters/RICE_sardinia.txt:1-6`、`rice_sardinia_l_english.yml:133`）。
- **北非撒丁人、非洲罗曼人、阿尔盖罗的加泰罗尼亚移民、撒丁民俗**（bidemortos 预见死亡、阿拉迪亚之梦、马蛆奶酪 casu marzu、喉音合唱 cantu a tenore、努拉吉石塔、贾拉野马）。

### 1.4 机制循环
**A. 撒丁去向（全局一次的大决议）**
开局（非 TFE）给撒丁文化加传统 `tradition_RICE_judicati`，1000 年后开局再加 `innovation_RICE_condaghes`（`common/scripted_effects/RICE_sardinia_effects.txt:16-32`）→ 玩家满足条件后执行「Determine Sardinia's Orientation」，在通用 widget 里四选一（天主教 / 东正教 / 北非 / 都不靠）（`RICE_sardinia_decisions.txt:72-333`）→ 效果（`:343-664`）：
- 设全局结局变量（如 `RICE_sardinia_catholic_ending`，`:361-364`），并把 flag 加进 `unavailable_unique_decisions`（`:351-354`），全世界不能再做。
- 本人改宗（天主教或东正教分支，`:366-378`），对应信仰热忱 +10（`:383-388`）。
- 改写法理：`title:k_sardinia` 的法理上级改到 `e_italy` / `e_byzantium` / `e_maghreb`（`:390-401,464-475,512-523`）。
- 所有带 `tradition_RICE_judicati` 的文化换文化遗产支柱（拉丁 / 拜占庭 / 柏柏尔），并把传统换成对应的结局变体（`:416-427` 等）。
- 「都不靠」分支先发 sardinia.0005 让玩家再选「受哪边影响」（`:628-633`），其余分支直接向南欧、伊比利亚、北非、法兰西、小亚、耶路撒冷一带的所有统治者广播 sardinia.0004（`:634-662`）。sardinia.0004 让撒丁文化的统治者可以跟着改宗（`events:320-410`）。
→ 解锁对应的后续决议（每个都要求对应的全局结局变量，10 年冷却，可反复做，例：`decisions:705,716`）和对应的传统变体（变体的 `is_shown` 要求结局变量，例：`RICE_regional_traditions.txt:1805`）。
→ 1100 年后的开局直接视为已选天主教（`RICE_sardinia_effects.txt:268-295`），用开局日期模拟史实进度。

**B. 帕利奥赛马链**
拉丁文化获得创新 `innovation_RICE_palio_races`（1150 年后开局直接给，`RICE_sardinia_effects.txt:61-70`）→ 三个入口：
- 决议「投资赛马」：在自制 widget 里选三档 → 本家族（house）获得随机 5–15 年的投资修正，作为家族级冷却，并在赛马抽奖中加权（`decisions:1511-1748`、`effects:794-1035`）。
- 决议「开创大帕利奥」（大决议）：选宗教 / 市民 / 王朝三种 → 都城县获得永久的「著名帕利奥」修正、发展度 +1，同一法理公国只能有一个（`decisions:1082-1266`、`effects:456-509`）。之后在这里办帕利奥，地点评分更高、收益 ×1.5。
- 活动「帕利奥赛马」：四类选项（类型 / 锦旗大小 / 施舍 / 自家参赛准备）→ 14 天后开始 → 双轨事件链（主持人一套、其他有地宾客一套镜像事件）→ 抽出冠军 → 宴会 → 集市 → 结算 → 清理并结束阶段。

**C. 文书与移民**
- condaghe 决议（10 年冷却）→ sardinia.0018：威望、王朝声望、10 年修正，并按管理 + 学识（最高 50%）的概率生成一件「condaghe」文书宝物（`decisions:1416-1507`、`events:1739-1783`、`effects:1493-1578`、`values:300-312`）。

- 阿尔盖罗（伊比利亚文化、持有 c_logudoro，全局一次）→ 广播 sardinia.0006（`decisions:1752-1890`）。

### 1.6 目标任务
1. **四选一的「去向」大决议 → 全局结局 → 解锁一组可重复的后续决议和传统变体**（1.4 A）。门槛本身就是一道目标（`decisions:39-64`）：威望等级 ≥3、文化有 judicati 传统、有 condaghe 创新或已进入盛期中世纪，再加三选一——完全控制并持有撒丁公国 / 是文化领袖 / 威望等级 ≥5。AI 的选项权重按地缘写：信西方基督教、领地里有西方基督教县、对教宗好感为正、身在神圣罗马或教宗体系内，都给天主教加分（`:88-124`），其他三个选项同理（`:136-331`）。AI 还按日期压低意愿，三档累加（1150 年前 −10、1100 年前再 −20、1000 年前再 −30，即 1000 年前共 −60，基础值 30），注释说「Give player a chance to do it」（`:666-687`）。
2. **帕利奥三件套**：创新 → 投资赛马（家族级状态）→ 开创大帕利奥（永久县修正）→ 反复举办活动。三者互相加成：投资修正提高冠军权重，大帕利奥修正提高地点评分和收益。
3. **一次性移民决议**（萨达尼亚、阿尔盖罗）放进全局唯一列表，完成后才解锁后续廷臣事件。
4. **condaghe 决议**：10 年冷却的「整理家族文书」，产出带随机属性的文书宝物。

### 1.10 问题与局限
1. **注释残留**：帕利奥事件段的头部注释写成「magadha.0020-magadha.0049」（`events:1864`），从摩揭陀包复制而来；「都不靠」后续决议的效果显示的是北非分支的史话提示（`effects:776`）。
2. **变量存取不一致**：集市事件把县修正类型设在主持人角色身上（`events:2923-2926`），清理事件和 `on_complete` 却在 `scope:activity` 上找这个变量（`events:3027-3032`、`activity:907-912`）。靠 `days = 3` 的自动过期兜底，功能不受影响，但清理代码是无效的。
3. **冠军候选可能为空**：抽中「参赛者」但没有人选择基本或充分准备时，`random_in_list` 列表为空，`scope:palio_winner` 不存在，变量却已设成 `flag:ruler`（`events:2433-2492`）。描述会落到「另一家族获胜」，日志的 character 也指向空 scope（读代码推断，未实测）。

6. **未完成的系统**：撒丁疟疾（`events:37-139` 整段注释，修正 `RICE_sardinia_malaria_modifier` 也注释，`modifiers` 疟疾段；但消息类型 `common/messages/RICE_messages.txt:63` 和效果本地化 `common/effect_localization/RICE_misc_effect_loc.txt:601` 还留着）；`RICE_setup_afro_roman_counties_effect` 定义了 155 行却没有调用（`effects:73,300`）。

### 本包可迁移的设计模式
1. **「去向」大决议**：四选一 → 全局结局变量 + 全局唯一列表 → 同时改信仰、法理归属、文化遗产、传统变体 → 解锁一组可重复的后续决议 → 广播给周边统治者，同文化者可跟随。汉晋可做「辽东公孙氏：附魏 / 通吴 / 自立」「交州士氏：附吴 / 附蜀 / 自守」「河西：附中原 / 附羌胡 / 自立」。AI 权重按地缘写，并按年份压低 AI 意愿，给玩家留出时间。
2. **后续决议带「引狼入室」的副作用**：奖励之外，有概率让外部势力获得宣称或把柄。汉晋：「求援于吴」→ 东吴对你一个郡获得宣称；「纳质于魏」→ 曹魏获得把柄。
3. **竞技类活动的主宾双轨事件链**：一个预定义阶段，主持人事件的 `after` 同时给其他宾客发镜像事件；胜负在主持人事件里一次性抽出，存成 scope，镜像事件只展示。适合汉代都试（秋季校阅）、魏晋击鞠、射礼、斗鸡。
4. **冠军抽签加权 = 场外强者 + 投入 + 主角光环**：先按类别抽（场外世家占一半），再在参赛者里按「准备档次 + 家族长期投资 + 玩家/主持人加成」加权。既让投入有回报，又不保证赢。
5. **家族（house）级长期投资**：投资修正挂在 house 上，随机持续 5–15 年，兼作冷却和后续竞赛的加权。汉晋：「蓄养名马」「延揽宾客」「经营坞堡」这类门第资本。
6. **把举办地变成「名胜」**：决议给县加永久修正，之后在此办活动评分更高、收益 ×1.5，同一法理公国只能有一个。汉晋：兰亭曲水、洛阳太学、首阳山。
7. **给原版人物补身世而不覆盖原版文件**：开局用效果清性格、按史实加性格（注释写明史料）、加身份修正（desc 写小传）、加宣称；缺失的亲属在自己的 history 文件里新建，再用 `set_mother` / `father =` 挂上去。汉晋春秋人物多、改原版风险大，这种做法尤其合适。
8. **民俗预兆的二段式事件**：先挂标记修正，玩家的选择决定第二段触发概率，第二段检查目标还活着再执行。汉晋：望气者言「某人有死气」、谶语、童谣。

### 2.10 问题与局限
- **疑似 bug：虔诚扣减恒为 −200**。`RICE_roman_kalends_piety_loss = { value = minor_piety_loss  max = -200 }`（`RICE_lesbos_values.txt:7-10`）。原版 `minor_piety_loss` 是 −50（原版 game/`common/script_values/00_basic_values.txt:1132`），`max` 是上限，结果总是 −200，比虔敬意图的收益大得多，很可能把 min 写成了 max。

### 本包可迁移的设计模式
1. **节日日历锁**：10–11 月允许发起 → 阶段激活 → `trigger_on_next_date` 定到节日当天。汉代正旦大朝会、腊日（12 月）、上巳祓禊（3.3）都能这样做。
2. **意图只做结算分支**：意图 `auto_complete`，结算时按意图拆奖励，再叠加「上级是异族则翻倍」这类局势条件。汉晋版：大傩、社祭在胡人政权下举行时，「守礼」意图收益翻倍。
3. **一个通用活动 + 地点分发**：共享活动按男爵领 `else_if` 分发专属事件，`province_description` 加 `province_score +100` 让名胜排前面。适合「名山巡游」（泰山、嵩山、华山）和「温汤」（骊山汤泉）。
4. **地下势力生命周期**：决议生成不可自建的特殊建筑 → 可升级 → 周期性多选项决议 → 「背弃」拆除并留永久标记。适合豪强坞堡、盐枭、海贼（如张伯路）。
5. **原版人物加 laamp 外壳**：头衔历史挂营地 + 书签条目 + 开局设营地用途 + `do_not_generate_starting_family` + 规则开关。可给张燕黑山军、甘宁锦帆贼做可玩营地。
6. **风味事件触发范围放宽**：「持有本郡，或首都/当前位置在大区内」，让周边玩家也读到地方典故。

### 3.10 问题与局限
- **重复生效**：重建拔摩岛的效果执行了两次。决议效果直接调用 `RICE_chios_repopulate_patmos_effect`（`RICE_chios_decisions.txt:197`），chios.0100 的选项又调用一次（`events:2780`），虔诚 +300 和热忱 +3 实际翻倍（主笔已核对）。
- **共享朝圣效果的死分支**：`RICE__misc_effects.txt:1334` 和 `:1345` 两处 else_if 都判断 `RICE_local_pilgrimage_model_intent`，curiosity 意图主持人的奖励永远不会发放。
- **异象概率**：`random_list` 权重是 50 + 4×10 = 90（`events:3075-3076`），每种异象约 11.1%，合计约 44%。
- **本地化键错用**：chios.0102 的选项用了已注释事件的键 `chios.0103.a`（`events:2849-2851`）；Mostra 的月份提示借用 pamir 包的键（`RICE_chios_mostra_of_thymiana.txt:34`），自己定义的 `RICE_decision_mostra_month_requirement` 没用上；注释写「Nov to Jan」（`:32`），代码是 10–12 月（`:35-36`）。
- **数值可疑**：需求下跌修正用了 `economy_positive` 图标（`modifiers:182`）；`RICE_chios_recent_piracy` 的控制力衰减系数是 −0.1（`modifiers:186`）；三档「堡垒型」乳香村 `fort_level` 都是 1（`modifiers:98-118`）。
- 主持人 10 月发起要等到次年 3 月才进入事件，被占用很久。海上风暴分支 chios.0103–0105、旧收尾 0109–0110 大量注释残留（`events:2855-3264`）。

### 本包可迁移的设计模式
1. **「侧重 × 规模」两步组合决议**：例如「屯田」，侧重选军屯 / 民屯 / 商屯，规模选小 / 中 / 大，组合出 9 种 20 年郡修正，一生一次。
2. **全局唯一功业 + 区域通报 + 解锁活动**：「重建太学 / 修复孔庙」首个完成者全服通报，之后解锁「谒孔林」活动。
3. **开局日期决定史实进度**：≥某年开局直接给全局变量（某寺已建、某道已通），早期开局要玩家自己完成。
4. **建筑的信仰门槛**：`is_enabled` + `show_disabled`。淫祠或道观只在道教、民间信仰持有者手里生效，儒家持有者看到灰显。
5. **四选一谶纬异象**：toast 加活动日志双记录，各给不同属性的修正。
6. **改信即作废**：直接复用原版 `starting_faith` 模式，适合佛寺巡礼、道教斋醮。

### 本包可迁移的设计模式
1. **标签修正 + 死亡钩子**：史实人物出生时挂唯一修正；on_death 事件按修正识别人物 → 设全局变量、`make_unprunable`、区域通报 → 解锁「修墓 / 立祠」决议 → 事件里用 `character:ID` 取肖像。适合郑玄、蔡邕、管宁这类「死后有祠」的人物，也绕开了「开局后 history death 不执行」的限制。
2. **雇主 + 衰老特质预埋**：用 `employer` 安置到对应宫廷，晚年给 infirm，让自然死亡大致落在史实年份附近。

### 5.4 机制循环
- **主线 A（1066 宿敌）**：开局 setup 设宿敌、志向修正和 `var:RICE_historical_aspiration` → 大厅后发开场事件 0010（只给 Budivoj，真正建立与萨克森 Ordulf/Magnus 的同盟）和 0011（只给 Krutoj，纯展示）→ 每年 1 月 1 日检查：

### 本包可迁移的设计模式
1. **对立双志向 + 宿敌关系**：开局给双方各设志向变量、任务书修正和宿敌关系，每年检查一次，完成后按结局分支写叙事。汉晋可用于孙策对刘繇（丹阳）、曹操对袁绍（官渡）、刘备对吕布（徐州）：条件写「完全控制某州郡、对方已死或无地」，奖励目标写「亲手斩杀」（判断 `killer`）、「保持汉室正朔」。
2. **全局变量做「年景」**：每年 1 月 1 日掷一次全局吉凶（`days = 365`），玩家的献祭在固定日期统一揭晓，所有人共享结果。可做太史令奏报天象、郊祀封禅的吉凶。
3. **决议 + 选项 widget**：照抄原版 commission_artifact 的 gui，分档说明写在 `<value>_tooltip`，AI 另写 `random_list` 兜底。可用于郊祀太庙的规格、赈灾钱粮档位、征辟名士的礼聘规格。
4. **单阶段活动 + 事件链推进**：一个 `is_predefined` 阶段 + `after` 串 3–4 个事件，结局事件真结算，最后 `skip_activity_phase`。凶兆概率随虔诚下降的写法，可换成「礼法」或「名望」。适合上巳祓禊、腊祭、寒食。
5. **两方争夺的圣地开关**：一个全局变量表示状态，拆毁和修复两个决议互为反向；广播事件只让行动者执行。可做太学石经、洛阳宗庙存废、传国玉玺归属。
6. **开局事件分开真改动和展示**：真正的外交改动放一方事件的 `hidden_effect`，双方事件都用 `show_as_tooltip` 展示，共用一段描述。讨董联军这类多方开场可照此避免重复执行。
7. **新文化随开局日期逐段同化**：按 `current_date` 分段 `set_county_culture`，配 `get_all_innovations_from` 补创新。可用于各剧本中五胡、越人县的汉化程度。
8. **同一神祇按文化和时代换名**：custom_loc 的 `has_cultural_pillar` + `has_cultural_era_or_later`，`fallback = yes` 兜底。可用于官称古今之别。

### 本包可迁移的设计模式
1. **特殊教义 = 功能开关**：给汉地礼制设 `doctrine_jiaosi`（郊祀），活动和决议只检查 `rite_has_doctrine`，在 `on_faith_created`、`on_rite_created` 里继承。以后加五斗米道、太平道分支时不用改活动本身。
2. **widget 选项决议 + AI 专用项**：「进贡方物」选蜀锦、交趾香料、辽东人参，每项配图标和 tooltip；AI 单独给一个随机项；扣钱用 `minimum_cost` 加事件内扣除。
3. **互动「只展示 / 真执行」拆分 + 书信通知**：适合「赐书、赐剑」这类单向馈赠。
4. **意图到结算才生效**：意图写成空壳，在日志 effect 里按 `has_activity_intent` 分支发奖。乡饮酒礼的「敬老、结交、宴乐」。
5. **长活动散点小事件**：开幕后排 N 个约 20% 的小事件，闭幕固定排最后。上巳、腊祭这类多日节庆。
6. **修正兼作冷却锁**：「加征口赋」时角色和郡同挂 10 年负面修正，`is_valid` 检查角色修正，省一个变量。

**写法要点**
1. **追加不覆盖**：直接写原版 on_action 名并附加 `on_actions = {}`，引擎会合并。原版注释说这三个 pulse 每年 / 三年 / 五年对可游玩（伯爵以上）角色调用，root 为该角色（原版 game/`common/on_action/yearly_on_actions.txt:979-981,2462-2464,2758-2760`）。
2. **为什么注释掉 `yearly_global_pulse`**（`:1-3`）：原版写明它「Root does not exist」（原版 `yearly_on_actions.txt:2`），没有角色 root 就没法跑面向角色的 `random_events`。文件里 `RICE_finno_ugric_shared_yearly_global_pulse` 和 `..._historical_pulse` 只出现在注释中，是没实现的脚手架。
3. **`delay = { days = { 8 288 } }`**：把事件随机推迟到一年中的某一天，分散 CPU 负载，也不让事件都挤在年初。原版说明这类延迟事件「入队时和延迟结束时都必须有效才触发」（原版 game/`common/on_action/_on_actions.info:49-51`）。
4. **为什么写 `2000 = 0`**：原版说明「"0" 条目让即使有其他合格事件也可能不触发，避免稀有事件因为其他事件都不合格而必然触发」（`_on_actions.info:69`）。池里只有 1–3 条事件，没有大空权重的话，合格角色每次过了 `chance_of_no_event` 就必中一条。

**实际触发概率**：P(某事件) = (1 − 25%) × w·m ÷ (2000 + Σ 有效事件的 w·m)。年度池三条都有效、m=1 时，任一事件约 0.75 × 30 / 2030 ≈ 1.1%/年，单条约 0.37%/年；30 年统治期内至少触发一次约 28%。五年池只有一条，约 0.37%/次。

| 项目 | 共享池 | 主池（`RICE_events_on_actions.txt`） |

| `chance_of_no_event` | 固定 25 | 基础 30，随游戏规则 ±10/20，战时 +10（`:1178-1210`） |

- **塞外旅人**：廷臣池或开局 → 0001：选文化、生成角色 → 雇用（钱付给他本人，收为廷臣）或拒绝（让他「失踪」死亡）→ 之后每 5 年掷一次骰 → 0002 隐藏抽签：选老师、选学生 → 0003（领主自学）或 0004（别的廷臣学）→ 学生得到永久课程修正。
- **埃文基课程的回报**：领主有埃文基课程修正时，即使文化不符也能看到驯鹿群决议（`decisions:34-35`），扩张结果偏向中、大档（`events:1316-1323,1396-1403`）。
- **驯鹿群**：决议花中等金额，要求金 ≥50、直辖有针叶林省份 → 0010 选一个 taiga 郡（首都优先）→ 0011 按权重给小、中、大郡修正 3650 天（`:1241-1415`）→ 决议冷却 7300 天（`decisions:15`）。
- **驯鹿祭**：筹备选「健康 / 国土 / 神灵」三类问事之一 → 0020 选倒计时方式（刻痕或绳结）→ 0021 选址 → 0022 营地社交三选一 → 0023 占卜，选项由筹备时的选择决定 → 0024 有人入神（无人 / 自己 / 廷臣），得到对应类别 1–3 档建议修正 → 0025 前往祭坛 → 0026 献祭，15% 概率另接 0027「怀胎母鹿」→ 0028 鹿肉宴 → 0029 收尾：host +100 虔诚、+50 威望、5 年修正，宾客 +25 虔诚，skip phase → on_complete 写日志。

### 7.9 写法亮点
- **一个模板 + 覆盖参数**：5 种文化和信仰共用一个模板（7.5 摘录）。
- **修正兼作身份标签**：旅人修正和课程修正都无期限，各种 trigger 直接检查它们（`triggers:23-75`），省掉变量和 flag。
- **领主多事件之间用 flag 传参，每个事件的 after 清理**：0003 after（`:813-823`）、0004 after（`:1177-1187`）、0024 after（`:1757-1765`）。
- **开局预先放置**：setup 里 5 次 `random_ruler` + `trigger_event` 给 AI 宫廷放人（`RICE_siberia_effects.txt:136-205`）。
- **人物知识解锁经济行动**：`decisions:34-35`（埃文基课程修正）把「人物学到的知识」变成「可以执行的决议」。

### 7.10 问题与局限
1. **siberia.0024 的 else_if 用错 flag**（`events:1660-1676`，主笔已核对）：第二个条件和第一个一样都是 `RICE_siberia_reindeer_divination_you_are_chosen`，应为 courtier 版。被选中的廷臣永远拿不到 +50，领主落到 else 只得 +15，描述却写廷臣入神。
2. **音乐课 flag 没清**：0003 和 0004 的 after 漏了 `remove_character_flag = RICE_siberia_music_lesson`（`:813-823,1177-1187`），按代码顺序推断，触发过一次音乐课后，0004 以后授课的狩猎、采集以外课程都会被误判成音乐课（读代码推断，未实测）。
3. siberia.0011 疑似把管理条件写反：`stewardship < high/decent/medium_skill_rating` 每条给中、大扩张 +1（`:1287-1298,1367-1378`），管理越低结果越好。
4. siberia.0002 声明 `scope = none`（`:250`），但 trigger 和 immediate 都直接用隐式 root（`any_courtier`、`random_vassal`）。若 `scope = none` 真的生效，整条传艺链就是死的（未核实）。
5. 复制痕迹：驯鹿祭阶段描述写成 "The New Yam festival…"（`rice_siberia_l_english.yml:50`，抄自尼日尔三角洲包）；宾客描述承诺威望和减压（`:37`），实际只给 25 虔诚（`events:1902-1906`）；`heritage_siberian.txt` 文件头写着 `#Permians #Ostyaks`（`:1-2`）。
6. 0001 两个选项都没写 `ai_chance`，开局批量发给 AI 统治者时，AI 可能选「拒绝」，旅人随即死亡。

### 本包可迁移的设计模式
1. **「塞外来客」廷臣链**：鲜卑、乌桓、氐羌游士，或西域胡商、方士。一个模板 + `random_list` 覆盖文化信仰；无期限身份修正当标签；雇用付钱给本人、拒绝让他失踪；每 5 年隐藏抽签，由他向主君或廷臣传授「骑射、胡商货殖、方术」课程修正。
2. **学到的知识解锁决议**：学过「屯田法」的角色才能看到某个屯田决议，并提高好结果权重。
3. **活动特殊选项驱动事件选项**：「封禅、郊祀、雩祭」三选一，后续卜筮事件只出现对应问事。
4. **按性格换窗口动画**：宴饮类活动的窗口人物按性格显示不同反应。
5. **开局预先放置**：setup 里给 N 个 AI 宫廷先发一次生成事件。
6. **游戏概念**：给「客卿、门客、方士」做 game_concept，本地化写 `[menke|E]`。

## 8. RICE「历史人物志向」框架：全 RICE 通用的目标任务系统

本组只有波拉布用到它，但它是 RICE 唯一成体系的「目标任务」写法，而且 RICE 自己就有中国题材的例子（867 剧本的曹议金、杭州包的陆游），所以单列一节。

**1. 数据层（开局 setup 里写）**：对指定历史人物做两件事——`set_variable = { name = RICE_historical_aspiration value = flag:<人物标识> }`（全 RICE 共用一个变量名，靠 flag 值区分任务），以及 `add_character_modifier = <包>_aspiration_<任务>`（这个修正只有图标 `RICE_aspiration_icon`，没有属性，例 `common/modifiers/RICE_normandy_modifiers.txt:382-384`）。曹议金的设置在 `common/scripted_effects/RICE_tarim_basin_effects.txt:421-435`，波拉布的在 `RICE_polabian_effect.txt:266-299`。

**2. 界面层（三处）**
- **角色界面的修正**：修正 desc 就是任务书，格式统一为「斜体背景 + 主要目标列表 + 奖励 + 奖励目标（每项写明奖励）」，数值用 `[EmptyScope.ScriptValue('RICE_aspiration_medium_resource_bonus')]` 动态显示（`rice_polabian_l_english.yml:25,122-125`）。
- **右上角提醒（important action）**（`common/important_actions/RICE__misc_actions.txt:5-26`）：只要角色有这个变量就生成提醒，点击打开角色界面：
```
action_RICE_historical_aspiration = {
	type = alert

	check_create_action = {
		if = {
			limit = {
				exists = var:RICE_historical_aspiration
			}
			try_create_important_action = {
				important_action_type = action_RICE_historical_aspiration
				actor = root
			}
		}
	}

	effect = {
		scope:actor = {
			open_view_data = {
				view = character
			}
		}
	}
}
```
  提醒的标题和说明是 `[GetPlayer.Custom('RICE_historical_aspiration_action_title_name')]` 等（`localization/english/rice_misc_l_english.yml:196-202`），说明末尾固定写「通常在年初结算」。（这个文件开头的注释还是「Suggestion for you to establish a Greenland estate」，`:4`，从格陵兰包复制来的。）
- **custom_loc 按变量值分发文本**：`common/customizable_localization/RICE_aspirations_custom_loc.txt` 有三大块：提醒标题（`:3`）、提醒说明（`:287`）、修正说明（`:582`），按剧本分节，每个人物一条 `var:RICE_historical_aspiration ?= flag:xxx`（例 `:96-108`）。另有游戏概念「historical_aspirations / 主要目标 / 奖励目标 / 路线」（`common/game_concepts/RICE_misc_game_concepts.txt:13-34`）。

**3. 检查层（集中在一个文件）**：`common/on_action/RICE_aspirations_on_actions.txt`，文件头写明「"Completion" is calculated yearly in on actions to keep things simpler to code.」（`:1-7`），每年 1 月 1 日挂到原版 `yearly_global_pulse`（`:10-16`，注释「Root does not exist」）。先按 `game_start_date = 867.1.1 / 1066.9.15 / 1178.10.1` 分节（`:27,407,891`），每个人物一个 `if`：`exists` → `is_alive` → 具体条件 → `has_variable = RICE_historical_aspiration` → `trigger_event` 完成事件。没有 `is_ai` 限制，AI 也能完成。曹议金的例子（`:29-46`）：
```
			# Cao Yijin
			# Pacify the Guiyi Circuit
			if = {
				limit = {
					exists = character:1059714
					character:1059714 = {
						is_alive = yes
						is_landed = yes
						has_title = title:k_hexi
						completely_controls = title:d_guasha
						completely_controls = title:d_gansu
						has_variable = RICE_historical_aspiration
					}
				}
				character:1059714 = {
					trigger_event = tarim_basin.0060
				}
			}
```

**4. 完成层**：完成事件标题统一用 `$RICE_historical_aspiration_fulfilled_title$`（例 `rice_polabian_l_english.yml:241`）。`immediate` 里依次：调 `RICE_historical_aspiration_fulfilled_effect`（显示一条提示并删变量，防止重复触发，`common/scripted_effects/RICE__misc_effects.txt:1608-1614`）→ `hidden_effect` 里移除任务修正 → 发主奖励（统一用 `RICE_aspiration_small/medium/large/massive_resource_bonus` = 500/1000/2000/4000，`RICE_misc_values.txt:9-12`）→ 逐项判断奖励目标。奖励目标只在完成那一刻判断，概念说明里写明「事后满足不补发」（`rice_misc_l_english.yml:345`）。

**5. 变体**：多路线（Rory O'Connor 有「称臣」和「独立」两套主要目标，分别发两个事件，`RICE_aspirations_on_actions.txt:1086-1144`）；即时结算（Hafsa 靠特质经验满 100 立即发事件，不走年度检查，`common/scripted_effects/RICE_granada_effects.txt:1727-1745`）；手动放弃（Rollo 的剧情选项可删变量和修正，`events/RICE_normandy_events.txt:8714-8719`）。**框架本身没有通用的失败判定**，变量随人物死亡失效，否则一直保留（波拉布 5.10 第 2、3 条就是这个缺口的后果）。

**6. 中国题材的现成例子：陆游「归隐」**：条件是身为天朝（h_china）的封臣、只持有家族头衔、诗人特质经验满 100、威望等级 ≥3、压力低于阈值（`RICE_aspirations_on_actions.txt:1056-1084`）；开局 setup 先把他的压力调高，让他「先疲惫，再归隐」（`RICE_hangzhou_effects.txt:165-170`）；完成事件 hangzhou.0071 的主奖励里有 `set_appointment_timeout = { years = 150 }`，即永久辞谢任命（`events/RICE_hangzhou_events.txt:1706`），8–15 年后再接一个追忆唐婉的后续事件（`:1748-1749`），已故的唐婉开局 `make_unprunable = yes` 留着做立绘（`RICE_hangzhou_effects.txt:19-21`）。这条和汉晋春秋已有的「历史人物辞谢任命」「隐士故事线」可以直接对接。

**7. 新增一个任务要改的地方**：setup 里设变量和修正 → 修正定义和本地化（任务书）→ custom_loc 三处各加一条 → 检查文件加一个 `if` → 写一个完成事件。

**给汉晋春秋的建议**：这套框架最值得照搬的是「一个变量名 + flag 值 + 只有图标的修正当任务书 + important action 提醒 + 年度集中检查」。建议补上 RICE 缺的两块：(a) 在同一个年度检查里写失败分支（人物失地、改投、死亡时删变量、修正，发一个「志向落空」事件）；(b) 对立双方各自的完成事件都要清理对方的变量。

### 9.2 统一骨架（RICE 的活动「模板」）
1. **只有一个 `is_predefined` 阶段**，`on_phase_active` 里只对 `scope:host` 发首个事件（例 `RICE_sardinia_palio_race.txt:516-523`）。`pulse_actions` 全部为空。节奏完全交给事件链：每个事件 `after` 里 `trigger_event = { days = {…} }` 排下一个，最后一个事件 `hidden_effect = { skip_activity_phase = yes }` 结束活动（例 `events/RICE_sardinia_events.txt:3033`）。好处是作者能精确控制叙事顺序；代价是原版活动「每个阶段按 pulse 抽事件」那种随机性要自己用「开幕时排 N 个 x% 插曲」补（莫尔多瓦 6.9 (c)、莱斯沃斯 2.7）。
2. **失效处理整套照搬原版**：`is_valid` + `on_invalidated` 按「主持人失地 / 失能 / 无人到场」分别发原版 `activity_system.0320 / 0330 / 0331 / 0100`，`on_host_death` 设 `activity_invalidated`（结构同原版 `common/activities/activity_types/tour.txt`）。宗教类活动再加原版朝圣的 `starting_faith` 改信作废（原版 `pilgrimage.txt:145-151,2777-2781`）。
3. **公共参数**：费用 `RICE_activity_cost`，冷却 `RICE_standard_festival_cooldown_time`，`on_enter_active_state` 统一调原版 `surveyor_no_stone_unturned_perk_effect`（`RICE_sardinia_palio_race.txt:811-813`），邀请规则全用原版 `activity_invite_rule_*`，加入概率用原版 `base_activity_modifier` + `activity_guest_shared_ai_accept_modifier`。
4. **旅行开场**：要么在 `RICE_travel_on_actions.txt` 的 `on_travel_plan_start_RICE` 事件表里放一个专属事件（撒丁、希俄斯、莱斯沃斯），要么由通用事件 RICEmisc.0011 按活动类型白名单处理（罗德岛、莫尔多瓦、西伯利亚；白名单在 `events/RICE_misc_events.txt:115-136`）。

### 9.4 决议 widget 的三层绑定（撒丁、波拉布、莫尔多瓦、莱斯沃斯通用）
这是本组决议最常用的技术，四个包写法一致，讲一次：
1. **决议层**：`widget = { gui = "<gui 名>" controller = decision_option_list_controller … item = { value = <选项键> is_valid = {…} current_description = … localization = … icon = "…" ai_chance = {…} } }`（撒丁 `RICE_sardinia_decisions.txt:1577-1628`）。`decision_option_list_controller` 是原版控件（原版 `00_artifact_decisions.txt` 委托宝物决议也用它）。
2. **gui 层**：根 vbox 的 `name` 必须等于决议里写的 gui 名；列表数据源是 `datamodel = "[DecisionViewWidgetOptionList.GetEntries]"`；每一项用自定义 type 渲染，按钮绑定 `OnSelect(Entry.Self)`、`IsEnabled`（来自 item 的 `is_valid`，钱不够时变灰）、`GetTooltip`、`GetIcon`、`GetName`（撒丁 `gui/decision_view_widgets/decision_view_widget_RICE_sardinia_invest_in_palio_horses.gui:3-37,40-60`）：
```
	type RICE_sardinia_invest_in_palio_horses = button_standard {
		size = { 450 85 }
		margin = { 10 10 }
		#tintcolor = { 0.73 0.95 0.94 0.8 } # Ice blue
		#tintcolor = "[TooltipInfo.GetTintColor]"

		onclick = "[DecisionViewWidgetOptionList.OnSelect(Entry.Self)]"
		enabled = "[Entry.IsEnabled]"
		tooltip = "[Entry.GetTooltip]"
		down = "[Entry.IsSelected]"

		hbox = {
			layoutpolicy_horizontal = expanding
			layoutpolicy_vertical = expanding
			spacing = 10
			margin_left = 10

			icon = {
				name = "RICE_sardinia_invest_in_palio_horses_icon"
				size = { 50 50 } # size = { 30 30 }
				texture = "[Entry.GetIcon]"
			}
```
   三个包的 gui 几乎逐行照抄原版 `gui/decision_view_widgets/decision_view_widget_commission_artifact.gui`，只改尺寸和名字。悬停提示的本地化键是「`<value>_tooltip`」（推断，见第 10.3 节）。如果不需要大图标，直接用原版通用 widget `decision_view_widget_generic_multichoice_with_effects` 即可（撒丁去向决议，`RICE_sardinia_decisions.txt:72-76`）。
3. **效果层**：玩家选中的 item 的 `value` 在 effect 里变成布尔 scope，`scope:<value> = yes` 判断（撒丁 `:1679-1705`）。通常把选择存成角色变量（`flag:small/medium/large`），再交给后续事件结算，事件 `after` 里删变量。
4. **AI 不走 widget**：原版说明写明 AI 只选分数最高的 item、不随机（原版 game/`common/decisions/_decisions.info:324-328`）。RICE 的三种对策：effect 里 `if = { limit = { is_ai = yes } random_list = {…} }` 替 AI 随机（撒丁 `:1650-1678`、波拉布）；或把真实选项设 `is_ai = no`、另加一个 AI 专用项（莫尔多瓦）；或按局势分流（莱斯沃斯海盗：没人脉先建交）。

### 9.5 奖励放在「事件」还是「日志」
RICE 有两种写法，同一个包里有时混用：
- **日志块里放真效果**（Kalends、Ine Ozks、拔摩岛、帕利奥主持人）：`add_activity_log_entry = { … show_in_conclusion = yes  scope:host = { add_prestige = … } }`，效果在写日志时执行，结算界面自动列出。仿原版 hajj 完成日志（原版 game/`common/scripted_effects/00_pilgrimage_effects.txt:59-70`）。
- **事件里真执行，日志只用 `show_as_tooltip` 展示**（Mostra、巨像、溺马佐娜、马祭、驯鹿祭）：更安全，不会因为日志效果被调用两次而重复发奖。
- 无论哪种，宾客镜像事件都只用 `show_as_tooltip` 展示主效果（帕利奥 0029）。**常见错误**：阶段只对主持人发事件，却在事件里写了给宾客的分支（马祭），宾客永远拿不到。

### 9.6 意图、选项与画面
- **意图大多是空壳**：`auto_complete = yes`，只带一个动画（`intents/RICE_sardinia_intents.txt:1-21`），在结算 effect 里用 `has_activity_intent` 分支。好处是不用写原版那种意图目标和意图事件；坏处是意图对过程毫无影响。
- **选项有两种用法**：普通选项类别（带 `cost`，决定档次）和 `special_option_category = special_type`（决定活动「性质」，会显示为活动类型的大图标和插图，图标按 `<选项>_icon.dds` 命名放在 `gfx/interface/icons/activity_types/`）。后者可以驱动后续事件的描述和选项：驯鹿祭的占卜选项只出现筹备时选的那类（7.7），帕利奥的抵达描述按类型四选一（`events:2034-2087`）。
- **画面**：旅行背景按地形写 18–20 条，全借原版插图（帕利奥 `:977-1233`、马祭 `:478-734`）；`window_characters` 按身份和性格换动画（帕利奥旅途主持人 `jockey_walk`，驯鹿祭按狂热 / 愤世换动作）；事件主题和背景大量复用原版宴会、比武的主题。

### 9.7 给汉晋春秋的落地草图：以「都试」（秋季校阅比武）为例
1. 活动键 `activity_hd_dushi`，`is_shown` 要求郡守以上、实行郡国制；`special_option_category` 三选一：校阅骑射 / 校阅材官 / 校阅楼船（不同县修正方向）。
2. 选项类别：赏赐（3 档，决定冠军奖励）、犒军（3 档，决定宾客好感）、本家子弟参试（不参 / 参 / 精心准备）。
3. 单阶段；主持人事件 `after` 给有地宾客发镜像事件：入营 → 前夜宴饮 → 开试 → 宣布魁首 → 劳军 → 清理。
4. 判定照帕利奥：魁首类别先抽（营中无名材官 50% / 豪强子弟 25% / 参试者 25%），参试者按「准备档次 + 家族『蓄养名马』投资修正 + 武艺档次」加权。魁首可写入历史人物（例如同场有吕布、马超这类 `character:` 时额外加权）。
5. 结算：主持人威望 / 军事声望，冠军家族 10 年修正；用「日志只展示、事件真执行」的写法；`on_complete` 记一条人物记忆（RICE 恰恰把记忆都注释掉了，汉晋可以补上，让魁首在后续事件里被提起）。
6. 「名胜」：决议「设都试之场」给县永久修正，之后在此办都试评分和收益更高。

## 10. 本组共性小结

### 10.1 共性
1. **完全不碰原版文件**：所有接入都是在原版 on_action 上追加（开局、年度、三年、五年、旅行、死亡），或者走原版能自动发现的数据库（决议、活动、互动、建筑、传统、创新）。和汉晋春秋现在大量「整文件覆盖原版」相比，RICE 的方式几乎不会和原版更新冲突。
2. **随机事件靠「大空权重」控频**：主池单事件 100 对空权重 20000–28000，共享池 10 对 2000，比例都是约 1:200，再叠 `chance_of_no_event` 和游戏规则（`RICE_events_on_actions.txt:1178-1212`）。大多数风味事件没写 `cooldown`，全靠这个比例限频。
3. **「全局唯一 + 全局变量」是 RICE 的进度语言**：一次性决议都进 `unavailable_unique_decisions` 列表；世界状态（神庙存废、撒丁去向、拔摩岛修道院、卡西亚之死）都用全局变量表示，并用开局日期直接设定，模拟史实进度。
4. **「展示 / 执行」分离贯穿全组**：广播事件只让行动者执行（波拉布 0055、撒丁 0010），互动和赠礼把对方的效果放进 `show_as_tooltip`（罗德岛、莫尔多瓦），开场事件只展示开局已执行的效果（波拉布 0010/0011）。
5. **人物故事的四种写法**：(a) 原版人物 + 开局效果改性格、加身份修正、加宣称、补亲属（撒丁阿里）；(b) 新建人物 + 出生挂标签修正 + 死亡钩子 + `make_unprunable`（罗德岛卡西亚）；(c) 历史人物志向（波拉布，框架见第 8 节）；(d) 模板批量生成「来投奔的人」（西伯利亚旅人、撒丁北非廷臣、决议附带的修士/官员/商人）。RICE 的「扮演某人」邀请 `RICE_setup_character_picker_effect`（`common/scripted_effects/RICE__game_start_effects.txt:25-66`）只给哈兰包的 Thabit ibn Qurra 和 Ibn Nabhan 用，本组七个包都没有用到；波拉布的开场事件走的是另一个效果 `RICE_setup_optional_flavor_events_effect`。本组**没有任何 story_cycle、编年史**。记忆类型定义了 21 个（希俄斯 5、罗德岛 4、波拉布 4、莫尔多瓦 4、西伯利亚 4），却**全部没有被调用**；撒丁和莱斯沃斯连记忆类型都没定义，活动里的记忆调用同样是注释状态（`RICE_sardinia_palio_race.txt:926-942`、`RICE_lesbos_kalends.txt:430,438`）。
6. **大量复制粘贴，残留明显**：magadha / Niger Delta / Monte Cassino / New Yam / Greenland estate 等注释，借用别包的本地化键，`xxxxx` 占位本地化（撒丁 185 行、波拉布 217 行）。这既说明 RICE 有一套内部模板，也说明它的 QA 主要靠玩家反馈。
7. **史实考据写进游戏**：`RICE_historical_context_on` 规则控制的「Historical Context」史话、修正 desc 里的小传、性格旁边的史料注释，是 RICE 风味化最有辨识度的地方。

### 10.2 外来前缀来历（结论）
- **brus_** = 并入 galicia2 包（Borderlands of the Red Rus）的「Baptism of Rus」mod 内容，证据是 `brus_slavic_decisions.txt:1-5` 的文件头和 galicia2 文件里的多处「Adapted / Borrowed from Baptism of Rus」注释；「brus」是这个 mod 名的缩写，这一点由注释推断，文件里没有明写。
- **EEE_** = 经 msl229（Rajas of Asia 团队成员）授权改编的内容，并入波拉布包，证据是三个 EEE 文件头的「Adapted from msl229 with permission」和 `RICE_red_sea_effects.txt:377` 的致谢。**EEE 的全称和对应的具体 mod 在 RICE 里查不到**。
- 两者都是新增键（新决议、新文化 sorbian、新传统），不覆盖原版。
- `mpo_` 不是外来 mod，是原版 Khans of the Steppe 的内部前缀。
