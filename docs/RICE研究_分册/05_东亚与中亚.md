### 0.4 "历史志向"（Historical Aspiration）——RICE 做个人目标任务的通用框架

本组有 5 个用例：陆游、末代祖尔比勒 Firuz、回鹘 Bokut、陈平山、耶律乙辛（耶律乙辛的结局事件在塔里木包）。框架由 6 个部件组成：

1. **标记变量**：开局 setup 里给人物设 `RICE_historical_aspiration = flag:xxx`，再加一个仅作显示用的"志向修正"。
   - 陆游：`common/scripted_effects/RICE_hangzhou_effects.txt:157-164`
   - Firuz：`common/scripted_effects/RICE_pamir_ROA_compatch_effects.txt:25-31`
   - Bokut / 陈平山：`common/scripted_effects/RICE_manichean_effects.txt:165`、`:183`
2. **显示用修正**：例如 `RICE_hangzhou_aspiration_retire_into_seclusion`（`common/modifiers/RICE_hangzhou_modifiers.txt:276`）。它只有图标 `icon = RICE_aspiration_icon`，没有数值。本地化 desc 写着"主目标 / 奖励"清单（`localization/english/rice_hangzhou_l_english.yml:252`、`:257-258`），玩家把鼠标悬停在人物修正上就能看到任务书。
3. **提醒按钮**：`common/important_actions/RICE__misc_actions.txt:5-27` 的 `action_RICE_historical_aspiration`（`type = alert`），只要人物有 `var:RICE_historical_aspiration` 就在右上角挂提醒，点击会打开人物界面。标题和描述用 `[GetPlayer.Custom('RICE_historical_aspiration_action_title_name')]` 动态取（`localization/english/rice_misc_l_english.yml:196-200`）。
4. **按 flag 分支的自定义本地化**：`common/customizable_localization/RICE_aspirations_custom_loc.txt` 里有三套：`:3` 标题、`:287` 描述、`:582` 修正描述。每套里按 `var:RICE_historical_aspiration ?= flag:lu_you` 分支，陆游分别在 `:265`、`:557`、`:859`。
5. **完成判定**：`common/on_action/RICE_aspirations_on_actions.txt:12-16` 挂原版 `yearly_global_pulse`，`RICE_aspirations_pulse`（`:18`）里先按 `game_start_date` 分书签，再对每个人硬编码检查条件，满足就 `trigger_event`。文件头注释直说"完成度每年算一次，图省事"（`:1-6`）。各人的位置：Firuz `:89-110`、Bokut 结尾 `:174`、陈平山 `:667-671`、耶律乙辛 `:678-703`、陆游 `:1060-1084`。
6. **达成事件**：开头调用 `RICE_historical_aspiration_fulfilled_effect`（`common/scripted_effects/RICE__misc_effects.txt:1608`，作用是删变量、显示"已完成"），移除志向修正，然后分两段发奖：`# Main Objective Reward`（主目标奖励）和 `# Bonus Objective Reward(s)`（额外目标奖励）。奖励数值用统一的脚本值 `RICE_aspiration_medium/large_resource_bonus = 1000/2000`（`common/script_values/RICE_misc_values.txt:10-15`）。

本组最完整的例子是陆游，见 2.5 节。

### 0.5 "一次性决议"全局表 + 开局按日期预填

所有"全图只能做一次"的决议都用同一个全局列表 `unavailable_unique_decisions`：

- `is_shown` 里判 `NOT = { is_target_in_global_variable_list = { name = unavailable_unique_decisions target = flag:xxx } }`
- `effect` 里 `add_to_global_variable_list` 把自己加进去

关键在于 setup 会按开局日期预先把"史实上已经发生过的"项目写进这个表。例如：

- `RICE_hangzhou_effects.txt:225-255`：925 年后开局视为钱镠海塘已建，1089 年后视为苏堤已建，1221 年后视为岳王庙已建。
- `RICE_manichean_effects.txt:99`（908 年后视为摩尼教已遭迫害）、`:110`（980 年后视为回鹘已改宗）。

这样同一个决议在不同书签里自动表现为"可做"或"已成历史"，不用为每个书签单独写条件。多阶段链也靠它串起来：例如 `RICE_pamir_restore_hephthalite_empire` 要求表里先有 `flag:RICE_pamir_reclaim_hephthalite_homeland_done`（`common/decisions/RICE_pamir_decisions.txt:27-30`）。

### 0.6 兼容层：怎么和 Dharmachakra、Rajas of Asia（ROA）、TFE、Paganism Plus 共存

- **兼容桩触发器**：`common/scripted_triggers/00000000_compatibility_triggers.txt:8/:12/:16` 定义 `is_dharmachakra_loaded`、`roa_is_active`、`paganism_plus_is_loaded`，全部是 `always = no`。文件名用一串 0 开头，保证最先加载，别的 mod 用同名触发器写 `always = yes` 就能覆盖。帕米尔 setup 里到处是 `is_dharmachakra_loaded = no` / `paganism_plus_is_loaded = no`（`common/scripted_effects/RICE_pamir_effects.txt:25/63/77/80/119/120/171`）。
- **按键名探测别的 mod**：`RICE_pamir_effects.txt:150`、`:161` 用 `exists = culture:soissons` 判断是否装了 TFE，装了就把嚈哒文化的 heritage 改成吐火罗系。
- **故意与别的 mod 同名**：`common/scripted_effects/00_dharmachakra_compatibility_effects.txt:1` 注释写"和 ROA 或 Dharmachakra 同用时会被覆盖"。它定义的 `set_yidam_effect`（`:5`）和 `set_nat_effect`（`:172`）与那两个 mod 同名，装了它们就自动让位；对应决议再用 `is_dharmachakra_loaded = no` + `roa_is_active = no` 隐藏 RICE 版本（`common/decisions/RICE_zhangzhung_decisions.txt:1840` 的 `RICE_select_personal_deity_buddhist_decision`）。
- **拆文件方便别人覆盖**：帕米尔把"给史实人物授地/发志向"和"给县加修正"拆成两个独立的 scripted effect 文件，注释写"应 ROA 开发者要求挪到单独文件，方便兼容"（`common/scripted_effects/RICE_pamir_ROA_compatch_effects.txt:2-3`、`common/scripted_effects/RICE_pamir_modifier_effects.txt:2-3`）。ROA 只需覆盖 `RICE_ROA_compatch_pamir_flavor_pack_effect` 这一个键，就能整段替换。调用链是：`RICE_pamir_effects.txt:1196` → `RICE_modifiers_pamir_flavor_pack_effect`（`RICE_pamir_modifier_effects.txt:6`）→ 末尾调用 `RICE_ROA_compatch_pamir_flavor_pack_effect`（`:130`）。
- 摩尼教 setup 里回鹘残余的布置也加了 `roa_is_active = no`（`RICE_manichean_effects.txt:34`），注释写"ROA 有自己的布置"。

### 0.7 史实冒险者（d_laamp_*）+ 规则控制

RICE 大量使用 Roads to Power 的无地冒险者（LAAMP）政体，把史实上没有封地的名人放成可玩冒险者，例如裴头陀、王建、陈平山、Khutsa Dawo、娘热·尼玛沃色、纳赛尔·霍斯鲁、末代慕容。实现分四步：

1. 头衔定义：`landless = yes`、`destroy_if_invalid_heir = yes`、`dlc_feature = roads_to_power`、`ai_primary_priority = { add = @never_primary_score }`。例如 `common/landed_titles/00_RICE_hangzhou_titles.txt` 的 `d_laamp_RICE_pei_toutuo`（capital 设为镇江 `c_runzhou`，注释说那里有金山寺）、`d_laamp_RICE_wang_jian`（capital `c_yingchuan`，注释说王建是许昌人）。
2. 头衔历史：`history/titles/RICE_laamp_titles_867.txt:385`（裴头陀）、`:439`（王建 han_3879）、`RICE_laamp_titles_1066.txt:378`（陈平山）。写法是 `holder = X`、`government = landless_adventurer_government`、`succession_laws = { landless_adventurer_succession_law }`，再加 `effect = { create_landless_adventurer_title_history_effect = yes set_variable = { name = adventurer_creation_reason value = flag:historical } }`。
3. 营地宗旨：开局后按人设设定营地宗旨（`common/scripted_effects/RICE__game_start_effects.txt:1499` 起），裴头陀是 `camp_purpose_scholars`，王建是 `camp_purpose_brigands`（王建早年以贩私盐、为盗出身，这个设定很贴切）。
4. 规则销毁：游戏规则 `RICE_adventurers_disable_fictitious` / `_all`（`common/game_rules/RICE_game_rules.txt:322/:330`）控制，对 AI 持有的冒险者头衔执行 `destroy_title`（`RICE__game_start_effects.txt:625` 起，裴头陀 `:941`、王建 `:965`、陈平山 `:1114`、娘热 `:1271`、布库里雍顺 `:1322`）。

另外，杭州 setup 给王建加了 `do_not_generate_starting_family`（`RICE_hangzhou_effects.txt:24-32`），防止引擎给冒险者凭空生成一家子。

  - 狭义汉字圈文化 `RICE_is_even_lesser_sinosphere_culture_trigger`（`:65`，heritage 为 chinese / japonic / korean / buyeo / viet）

- `RICE_potential_literate_east_asian_scholar_gentry_trigger`（`:451`），"识字的士绅"：外交或学识至少为 medium，或者有诗人生活方式特质；同时两项都不能是 low；再叠加上一个触发器。

宾客条件 `can_be_activity_guest`（`:434-439`）用的是同一个"识字士绅"触发器，再加 `in_diplomatic_range = scope:host`。效果是不会写诗的人收不到邀请。这是"用技能门槛定义阶层"的做法，很适合拿来写"清流 / 名士"类活动。

另外 RICE 定义了三档汉字圈触发器（`:22` greater、`:41` lesser、`:65` even lesser），外加 `:75` 一档排除日本的版本，供不同内容按需取用：

- 广义（greater）：含整个东亚 + 中亚 heritage，以及粟特、塞种、女真
- 狭义（lesser）：含 tungusic、hmongic、契丹、女真
- 最狭义（even lesser）：只有汉、日、朝、扶余、越

#### (8) 对汉晋 mod 的参考价值

这是 RICE 唯一一个针对"东亚士人文化"做的系统性玩法。几条可以直接借用的思路：

- 用"技能 + 文化/信仰/政体 flag"三层门槛筛选出"士"这个阶层；
- 竞赛结果用加权随机，并留一条"本地无名文人夺魁"的路，制造意外感；
- 诗作按魁首的教育类型分 5 类，每类 30 个题目的 custom loc，组合出大量文本变化；
- 结算接到原版 merit / influence / treasury 上，在天朝政体下自然生效；
- 招揽事件就是一条"发现人才"的渠道。

对汉晋来说，它几乎可以原样改造成"清谈 / 雅集 / 兰亭会"。杭州包的 `hangzhou.0107`（兰亭集会，见 2.8）本身就把这个典故当风味写进去了。

### 2.9 写法亮点（代码摘录）

**(a) 用 TGP 王朝循环阶段做门槛**（`RICE_hangzhou_decisions.txt:57-72`）：

```
	is_valid = {
		highest_held_title_tier >= tier_kingdom
		religion = religion:buddhism_religion
		trigger_if = {
			limit = { has_tgp_dlc_trigger = yes }
			OR = {
				situation:dynastic_cycle ?= { situation_current_phase = situation_dynastic_cycle_phase_chaos }
				situation:dynastic_cycle ?= { situation_current_phase = situation_dynastic_cycle_phase_instability }
				situation:dynastic_cycle ?= { situation_current_phase = situation_dynastic_cycle_phase_instability_conquest }
			}
		}
		trigger_if = { limit = { government_has_flag = government_has_influence } influence_level >= 3 }
		trigger_else = { prestige_level >= 3 }
		piety_level >= 3
	}
```

**(b) "臣子加 merit、君主加正统性"二分**（`RICE_hangzhou_effects.txt:260-289`，同样的写法在杭州包里重复了 6 次）：

```
RICE_hangzhou_improve_west_lake_dredging_effect = {
	add_prestige = minor_prestige_gain
	if = {
		limit = { government_has_flag = government_has_merit  top_liege = root }
		add_legitimacy = miniscule_legitimacy_gain
	}
	else = {
		add_merit_if_relevant_effect = { MERIT = miniscule_merit_value }
	}
	title:c_hangzhou = { add_county_modifier = { modifier = RICE_hangzhou_west_lake_dredging_modifier years = 10 } }
	if = { limit = { has_treasury = yes } remove_treasury = 75 }
	else = { remove_short_term_gold = 75 }
}
```

决议的 cost 也按同样思路写成两套：`gold = { if has_treasury = no add 500 }` 加 `treasury = { if has_treasury = yes add 500 }`，再加 `influence`（`RICE_hangzhou_decisions.txt:222-250`）。

**(c) widget 二级选单 + AI 兜底随机**：widget 里的 `ai_chance` 实际上不起作用，作者在 effect 开头注释"Not sure why AI can't pick one option or another"，然后给 AI 单独写了一个 `random_list`（`RICE_hangzhou_decisions.txt:785-827`）。玩家走 `scope:RICE_hangzhou_improve_west_lake_dredge_silt = yes` 这类分支（`:829-889`）。选择结果存进只保留 1 天的变量 `RICE_west_lake_improvement_type`，由事件 0021 读取。GUI 是一个通用的选项列表（`gui/decision_view_widgets/decision_view_widget_RICE_hangzhou_improve_west_lake.gui:5-84`，`datamodel = "[DecisionViewWidgetOptionList.GetEntries]"`）。

**(d) 两件 artifact 二选一，没选的销毁**（`events/RICE_hangzhou_events.txt:989-1051`）：immediate 里同时创建"十景画轴"和"十景诗卷"；选项 a 用 tooltip 显示"诗卷归你"，同时 `destroy_artifact` 画轴；选项 b 反过来。0041 里再用 `any_character_artifact = { has_variable = ... }` 判断推广者手里是哪一件，决定在事件窗口展示哪件（`:1105-1130`）。

**(e) artifact 描述随世界状态改变**（`:1844-1855`）：中原已收复时，用 `set_artifact_description` 把《示儿》换成另一段描述。

### 本包可迁移的设计模式

1. **"人物志向 + 原版政体机制"做任务条件**：陆游的任务条件全部是原版 TGP 状态（是谁的臣子、贵族家族头衔、压力、威望），不需要新造进度系统。汉晋可以照搬，比如"竹林七贤式归隐"、"诸葛亮北伐"的条件。
2. **史实遗憾 + 世界状态分支**：《示儿》描述随"是否收复中原"切换。汉晋可以做"出师表 / 北伐未竟"一类。
3. **游玩计数器做隐形进度条**，再配合 `custom_description` 在决议界面显示进度。
4. **按开局日期在"已建 / 建筑位"之间切换的特殊建筑**，以及按日期预填一次性决议表。
5. **两件 artifact 二选一、没选的销毁**，让玩家在事件里挑奖励。
6. **"臣子加 merit、君主加正统性"+"有国库扣国库、没国库扣金钱"** 的双轨奖惩，在汉晋这种天朝 / 封建混用的环境里非常实用。
7. **观点选择型小事件 + Glossary 注释**，用极低成本铺开大量典故。

### 3.9 写法亮点

**(a) 延时事件 + `on_trigger_fail` 处理中途变故**（`events/RICE_manichean_events.txt:1866-1873`）：

```
	trigger = {
		rite = { rite_has_doctrine = rice_light_purification_doctrine }
	}

	#Trigger if converted to another faith
	on_trigger_fail = { 
		trigger_event = manichean.0059
	}
```

抄经要等 30~365 天，期间如果改宗，结果事件的 trigger 不成立，就转去收尾事件。这是长延时事件链里清理状态的标准写法。

**(b) 技能门槛选项灰显**（`:1721-1729`）：

```
	option = { # Ok
		name = manichean.0050.b
		trigger = {
			learning >= RICE_manichean_manuscript_learning_req_value # 有特殊教义时 8，否则 12
		}
		skill = learning
		show_as_unavailable = {
			learning < RICE_manichean_manuscript_learning_req_value
		}
```

**(c) 用"运行时添加的特殊教义"记录世界状态**（`RICE_manichean_effects.txt:225-234`）：`religion:dualism_religion = { every_faith = { limit = {...} every_faith_rite = { add_rite_doctrine = special_doctrine_rice_doctrine_late_manicheism_support } } }`。玩家打开信仰界面就能看到"本教在回鹘的命运"，脚本里也可以用 `rite_has_doctrine` 读取。门槛脚本值据此调整，例如抄经学识要求从 12 降到 8（见上一段注释）。

### 3.10 问题与局限

1. `RICE_manichean_uyghur_church_abandoned_yearly_effect` 把 `every_in_list`（`RICE_manichean_effects.txt:1414`）嵌套在 `every_county_in_region`（`:1404`）里面，另外两个版本都写在外面（`:1365`、`:1390`）。后果是统治者每多一个县，整个列表就被多掷一轮 10%，"放弃"路线的年度负面事件会远多于设计值。
2. widget 里的 `ai_chance` 写了但实际无效，AI 的选择完全靠 effect 里的 `random_list`（`RICE_manichean_decisions.txt:185-204`）。这和杭州包是同一个坑。
3. "明教徒"决议注释写"将来要限定在福建"（`:1590`），目前任何汉文化 + 光明净化教义的人都能用。
4. 陈平山的志向要求"子女有林瞪特质"，前提是 `manichean.0008` 的继承规则能触发，而这个规则本身没有在本册展开核对。

### 本包可迁移的设计模式

1. **师承型志向**：要求本人特质经验达标，并且子女继承了这个特质。适合汉晋的经学家法、道教传箓、门生故吏。
2. **奖励生活方式点**，而不是给资源，营造"修成正果"的感觉。
3. **一次性国策三选一 + 百年计时变量 + 年度随机后果**，适合做汉晋"罢黜百家 / 崇佛 / 灭佛"一类的长期国策。
4. **运行时特殊教义作为信仰界面里看得见的世界状态记录。**
5. **`on_trigger_fail` 给长延时事件兜底。**
6. **按特质数量叠加招兵**（明教徒决议），把人物特质换算成起义规模。可以用于黄巾 / 五斗米道。

### 4.5 人物个人故事

吐谷浑包没有给个人写故事。它利用原版已有的吐谷浑王系人物，做了两件事：

- 王国史 `history/titles/k_tuyuhun_restored.txt` 从 284 年的 247346 一直写到 670 年的 `holder = 0`，注释是"被吐蕃攻灭，国王逃往唐朝"（`:75-77`）。这样早期开局就有一个"历史上存在过、现已覆灭"的王国，复兴决议才有史实依据。汉晋可以照这个办法给"已亡之国"写历史持有者，例如两汉之间的诸侯国、五胡各国。
- 末代慕容（247407）做成 867 年的冒险者，开局带有对吐谷浑公国的已主张宣称。

### 4.10 问题与局限

1. **旅行选项的提示和代码不一致**：提示说每进一个男爵领有 `RICE_tuyuhun_qinghaicong_option_bonus_chance` 的概率（按外交 ×1.5、勇武 ×0.5 再除以 2，上限 30），见 `localization/english/rice_tuyuhun_l_english.yml:13` 和 `common/script_values/RICE_tuyuhun_values.txt:2`。但代码 `RICE_travel_on_actions.txt:57` 用的是 `chance = RICE_tuyuhun_qinghaicong_option_max_value`，也就是固定 50%（`RICE_tuyuhun_values.txt:18`）。前者定义了却没有被用到。
2. 3 个记忆类型都没有被创建。那达慕 `on_complete` 里的 `create_character_memory` 被注释（`RICE_tuyuhun_nadun_festival.txt:276-290`），复兴王国的记忆也没有调用方。
3. 结算效果里 `if 感恩意图 ... else 加 50 威望虔诚`，这个 else 挂在感恩分支上（`RICE_tuyuhun_effects.txt:199-212`）。所以欢庆意图会同时拿到减压和那份基础奖励，可能不是原意。
4. 大量事件 ID 只有占位本地化（`rice_tuyuhun_l_english.yml:121-319` 中的 xxxxx 段落），说明预留了扩展空间，但没有写完。

### 本包可迁移的设计模式

1. **"历史上存在过的已亡王国"**：在头衔 history 里写完历代持有者，最后 `holder = 0`。复兴决议因此有据可依，界面上也能看到这个王国的历史。
2. **一个县修正衍生出角色修正、互动和旅行选项**的资源链。适合汉晋的"西凉马 / 蜀锦 / 吴盐"一类地方特产。
3. **日历月份限制节庆活动**（`current_month`）。
4. **三国戏式"观点选择"小事件**：选项是"你最欣赏哪位历史人物"，同时影响资源和与性格冲突的压力。这在汉晋 mod 里几乎可以照搬，换成"品评人物 / 月旦评"即可。
5. **AI 建国不转移玩家领地法理**的过滤写法。

**(a) 伏藏师外出寻宝：原版旅行系统 + 到达事件**（`events/RICE_zhangzhung_events.txt:1599-1620`）：

```
				modifier = RICE_zhangzhung_discovering_termas
				years = 1
			}
			# To prevent them from somehow leaving your court while they're on the trip
			add_character_flag = {
				flag = blocked_from_leaving
				years = 1
			}
			start_travel_plan = {

			}
		}
```

**(b) 特质名称随特质经验分级**（`common/traits/RICE_zhangzhung_traits.txt:38-63`），一个特质就做出了三档称号：

```

			# Terton King
			triggered_desc = {
				trigger = {
					exists = this
					has_trait_xp = { trait = RICE_terton value >= 100 }
				}
				desc = trait_RICE_terton_3
			}
			# Major Terton
			triggered_desc = {
				trigger = {
					exists = this
					has_trait_xp = { trait = RICE_terton value >= 50 }
				}
				desc = trait_RICE_terton_2
			}
			desc = trait_RICE_terton
		}
	}
```

2. AI 直接跳到伏藏结果事件，不走旅行（注释说是为了性能）。这样 AI 的伏藏师不会真正离开宫廷，和玩家的体验不对称，但能避免全图大量旅行计划。
3. 0031 的旅行取消事件 `on_travel_planner_cancel_event` 被注释（`:1618`）。中途取消时只有 `blocked_from_leaving` 那一年的 flag 会自然到期，没有专门的处理。
4. Losar 和本尊决议在装了 Dharmachakra / ROA 时会让位，这是有意为之。但也说明这部分属于"兼容替身"，内容深度有限。

### 本包可迁移的设计模式

1. **"全局时代节点 → 个人候选 → 年度掷骰 → 旅行寻宝 → 领主裁决 → 特质成长"** 的完整故事循环。对汉晋，可以直接改写成"访贤 / 寻求谶纬 / 采药炼丹 / 寻访古碑"。
2. **原版旅行系统做"派人外出办事"**：`start_travel_plan` 加 `on_arrival_event` 加 `blocked_from_leaving`。
3. **特质名称随特质经验分级**，一个特质做出三档称号。
4. **"人物在就用、不在就造"** 的史实人物兜底。
5. **史料稀少的人物让玩家自选生平**（三连事件分配性格、家室、技能）。汉晋有大量只有一句列传的人物，可以借用。
6. **多段随机自定义本地化拼接叙事**，花很少的文本量换取大量变化。
7. **调试 flag**：`add = 1000` 的强制分支，加 `add = 99999` 的测试全局变量。
8. **只活 1 天的跨事件变量**。

4. 嚈哒南北路线用的是**全局变量**，不是存在头衔或人物身上。整局游戏只能有一种路线，而且只要变量在，任何人拿到帝国都得到同一种特质。从设计上看这是故意的，但可扩展性有限。

### 本包可迁移的设计模式

1. **"历史上随机出现"的人物：模板 + 固定名字键生成，存进全局列表，所有引用写两路解析。** 汉晋的"按年出场"人物可以借鉴这个做法，例如在某人从未出生的开局里，让他在条件满足时现身。
2. **延时任务：随机等待 + 完成前检查存活 + 书信体结果事件。**
3. **两段式复兴决议 + 中间路线分叉 + 随头衔转移的特质。**
4. **历史文化演变：`reset_culture_creation_date` + `get_all_innovations_from` + 原版换文化 effect，并给玩家保留拒绝的选项。**
5. **一个公共活动挂多个地区的专属事件**（温泉）。
6. **把兼容敏感的部分拆进独立的 scripted effect 文件**，方便其他 mod 覆盖。
7. **童年和成年钩子挂宗教习俗修正**（0011 / 0012）。

**(a) 同一选项按条件换名字**（`events/RICE_khwarezm_events.txt:296-319`）：

```
		name = {
			trigger = { rite = { rite_has_parameter = rice_yazata_pay_for_modifier_upgrade } }
			text = khwarezm.0020.b.sassanian

			trigger = { rite = { rite_has_parameter = rice_unlock_yazata_cult_center }	}
```

**(c) 地标建筑随史实时间消失**：开局按日期放建筑，然后由全局节点按递增概率 `remove_building`，并通知玩家。

### 8.10 问题与局限

1. 文件头注释错写成 "Niger Delta"（`:3`），是从别的包复制来的模板。
2. TFE 版 Al-Fir 的"坍为废墟"节点有逻辑错误：限制条件是 `current_date <= 550.1.1`（`RICE_events_on_actions.txt:228`），但概率加成写在 `>= 600 / 650 / 700 / 750`（`:235/:239/:243/:247`），这些加成永远不会生效。
3. setup 里有一段"疯狂之河"区域修正被注释，作者注释是"不知为何不生效"（setup 的 BUILDING 段）。
4. 20 位神祇的选择逻辑用 `else_if` 链手写了好几遍：决议、普通修正效果、强化修正效果、崇拜中心效果各一遍。维护成本高。

### 本包可迁移的设计模式

1. **"个人守护神 + 地方崇拜中心"双层结构**：个人得修正，有中心的才得强化版。
2. **用教义 / rite 参数切换同一机制的两种玩法。**
3. **同一选项按条件换名字。**
4. **地标随史实时间消失，并按递增概率触发。**

## 10. 本组共性小结

### 10.1 RICE 地区包的统一骨架（本组 7 个有效包都遵守）

1. **一个包 = 一个 setup 效果**，挂在原版 `on_game_start` 上，按开局日期分支，负责：
   - 改文化传统和县文化 / 信仰；
   - 放特殊建筑，或按日期只放建筑位；
   - 给史实人物授地、重写特质；
   - 预填一次性决议表；
   - 发志向。
2. **大厅之后**才跑的人物开场事件，分"可选"和"必跑"两类，由游戏规则控制。
3. **随机事件**一律挂在 `RICE_events_on_actions.txt` 的几个公共脉冲上，每个脉冲之间插 8~288 天的随机延迟；史实池用空权重压低频率。
4. **一次性大工程**统一用 `unavailable_unique_decisions` 全局列表控制。
5. **历史志向**是个人目标的统一框架：变量 flag、显示用修正、important_action 提醒、按 flag 分支的 custom_loc、每年硬编码检查、主奖励 + 额外奖励。
6. **活动**采用原版活动框架：`is_location_valid` 锁地点、`current_month` 锁季节、结算写进活动日志 `add_activity_log_entry`。
7. **兼容**：`00000000_` 前缀的桩触发器、故意与其他 mod 同名的 effect、把兼容敏感部分拆成独立文件、用 `exists = culture:xxx` 探测其他 mod。

### 10.2 人物个人故事的五种写法（按对汉晋的参考价值排序）

| 写法 | 本组例子 | 对汉晋的用法 |
|---|---|---|
| 历史志向：原版状态做条件，主奖励 + 额外奖励 | 陆游归隐、陈平山继承林瞪遗志、Firuz 保持独立 | 诸葛亮北伐、竹林名士、经学传家 |
| 开局重塑人设 + 高压力 / 遗像 / 不可清理 | 陆游 200 压力 + 唐琬遗像；林瞪、莲花生 `make_unprunable` | 让已故人物在事件里露面，例如孔融、祢衡 |
| 史料稀少者让玩家自选生平 | Dpal Dus Sgra 三连事件；Azur Jamshid 自选宗教 | 列传只有一两句的人物 |
| 人物在就用、不在就造；随机出现的存进全局列表 | 米拉日巴、纳赛尔·霍斯鲁 | 和用户已有的"按年出场"生成器互补：没有固定 ID 的人物也能被后续事件引用 |
| 虚构后裔连接家族，"两种观点都保留" | 仁钦桑波家族 9~11、象雄王 Likmigyal 双版本 | 门阀世系延续到后期开局 |

补充手段：

- 专属 DNA，例如陆游、唐琬、林瞪、陈平山、米拉日巴；
- portrait_modifier 强制换胡须或冠服；
- 书签用"导师 / 前妻"关系把已故人物放进书签；唐琬的书签出生年份故意写成 1150 年，让她"显得年轻"（`RICE_1178_bookmarks.txt:938-945`）；
- 历史效果里设好友、宿敌、灵魂伴侣。

### 10.3 目标任务的形式

1. **历史志向**：每年检查条件，完成后一次性发奖。
2. **一次性决议链**：两段式决议，中间加路线分叉（嚈哒），前置条件用全局表串联。
3. **隐形进度条**：用计数变量，在决议界面用 `custom_description` 显示进度（西湖十景"游湖 3 次"）。
4. **特质经验分级**：特质名称随经验变化（伏藏师、林瞪弟子）。
5. **一次性国策三选一 + 百年计时 + 年度随机后果**（回鹘教会）。
6. **开放式故事循环**：全局时代节点 → 个人候选 → 年度掷骰 → 旅行 → 领主裁决 → 成长（伏藏系统）。

### 10.5 本组共性问题（读代码得出，未进游戏验证）

1. **人物记忆系统只定义、没有启用**：帕米尔 14 个、吐谷浑 3 个、巴米扬整体被注释、诗会 `on_complete` 被注释。整个 mod 里还在实际创建记忆的只有上埃及包。所以不能说"RICE 用记忆来写人物故事"。
2. **大量 `"xxxxx"` 占位本地化**：杭州编年史 4 章、`hangzhou.0083`、吐谷浑大段预留 ID。
3. **widget 决议里的 `ai_chance` 实际无效**：杭州、摩尼教、象雄三处都靠 effect 里给 AI 单独写 `random_list` 兜底。
4. **作用域和名字的笔误**：诗会 `scope:local`、0082 的空 `every_attending_character`、摩尼教年度效果嵌套错位、象雄重复授予 `c_zhongba`、花剌子模 Al-Fir 的条件和加成互相矛盾。
5. **提示文字和实际代码不一致**：诗会的意图说明、吐谷浑旅行选项的概率、诗作归属。
6. **东亚共用里的空壳**：汉化改名 GUI、东亚行政头衔、朝鲜和日本文化文件全部是注释。

### 10.6 对汉晋 mod 的落地建议（按投入产出排序）

1. **诗会 → "雅集 / 清谈"活动**：门槛直接用原版政体 flag 加技能阈值；诗题改成"清谈题目"；魁首可以接用户已有的"清议 / 月旦评"系统。改造时注意避开 1.1 (7) 里的四个 bug。

3. **汉化改名**：按 1.2 的接线复活，用于刘渊、石勒、拓跋改姓元等"改汉名 / 赐姓"事件。
4. **历史文化演变 + 玩家可以拒绝**（哈拉吉文化形成）：可以用于五胡内附后的汉化、衣冠南渡后的南方文化变迁。
5. **"随机出现"人物的全局列表兜底**：补足用户的按年出场生成器，处理"某开局里根本没生成、但事件要引用"的人物。

7. **特殊建筑按开局日期在"已建 / 建筑位"之间切换**：太学、鸿都门学这类建筑可以直接套用。
8. **portrait_modifier 按身份强制换装**：可以和 HanJIn_Clothes 的规则池互相补充。
9. **"人物在就用、不在就造"、三连自选生平、虚构后裔连接家族**：用于大量史料稀少的汉晋人物。
