# 斯里兰卡（Sri Lanka / sri_lanka）

## 1. 主题与史实背景

**地区**：斗争区域只含岛上三个公国 `d_dakhina_desa d_ruhunu d_sinhala`（`map_data/geographical_regions/RICE_sri_lanka_geographical_region.txt:15-20`）。作者另外造了两个区域：
- `RICE_sri_lanka_alt_region`（`:22-27`），注释写明"For naming purposes"，内容就是包一层上面那个区域。本地化里大量使用 `[GetGeographicalRegion('RICE_sri_lanka_alt_region').GetName]` 显示岛名（例：`localization/english/rice_sri_lanka_l_english.yml:1005`）。**【可借鉴】**用"只为取名的区域"把地名做成可替换的本地化键。
- `RICE_tamilakam_and_lanka`（`:29-37`），给朱罗/泰米尔方向的 Velakkara 雇佣兵用。

**史实主题**：阿努拉德普勒时代以来，斯里兰卡上座部僧团分裂为三大寺——大寺 Mahavihara、无畏山寺 Abhayagiri、祇园寺 Jetavana，三寺争信徒、地位、土地和王室供养，王公贵族各有所偏，使教派之争变成政治问题（`rice_sri_lanka_l_english.yml:1005` 介绍文、`:1021` 结局导语）。斗争三阶段是作者对"僧团兴衰循环"的抽象：**堕落 Degeneration / 积累 Accumulation / 净化 Purification**。结局以"统一僧团"为主线，原型是 12 世纪帕拉克拉马巴胡一世召集结集、独尊大寺；作者在开局代码注释里专门说明，近年学界质疑这次改革是否真正终结了派系（`common/scripted_effects/RICE_sri_lanka_effects.txt:924-925`），所以 1150 年以后开局不直接结束斗争，而是从"净化"阶段开始。

**适用开局**：
- 867：给原版 Sena II 时代的官员分县（Kutthaka、Mahasattana、Utur Pandirad、Senal Madabi、Kitambava），并补两位王后作为母亲（`RICE_sri_lanka_effects.txt:190-242`）。
- 1066：维阇耶巴忽一世（原版 `character:189029`，原版名 "Kitti"，`原版:history/characters/sinhala.txt:417`）抗击朱罗王朝；书签 `common/bookmarks/bookmarks/RICE_1066_bookmarks.txt:903-932`，含新人物布达尔为附属可选角色（`:920-932`）。
- 1178：帕拉克拉马巴胡一世（原版 `217366`，书签 `RICE_1178_bookmarks.txt:546-557`）。
- ≥990 年开局：阿努拉德普勒县加 150 年"衰落"修正并换成古城遗址特殊建筑（`RICE_sri_lanka_effects.txt:313-327`）；≥1070 年开局：首都已迁至波隆纳鲁瓦（`:1260-1282`）。

**区域包当"文化圈修正入口"**：setup 效果前 180 行几乎都不是斯里兰卡本身，而是对整个南亚、印度洋文化圈的历史修正：给维达人加 `tradition_RICE_cave_dwellers`（`:20-25`），给僧伽罗人重配传统（`:27-38`），所有印欧—雅利安和达罗毗荼遗产文化拿到"灌溉水库"创新（`:117-126`），航海文化拿到"季风贸易路线"创新（`:128-158`），还修正缅甸骠人、阿拉干、孟加拉的宗教文化（`:336-757`）。修正都加了 `roa_is_active`、`is_dharmachakra_loaded`、`MBP_is_loaded` 等兼容判断（例 `:251-263`、`:337-341`）。

## 3. 触发入口

**(1) 开局一次性：`on_game_start` → `RICE_setup_sri_lanka_flavor_pack_effect`**（`RICE_game_start.txt:112`，效果定义 `RICE_sri_lanka_effects.txt:3-852`）。做文化宗教修正、书签授地、随机给岛上 2~3 位统治者塞维达人廷臣（`:807-842`，触发隐藏事件 `sri_lanka.0018`），并设一个只活 1 天的全局变量 `RICE_sri_lanka_initial_start_catalyst_timer`（`:844-849`），用来压住开局第一天的年度催化剂结算。

**(2) 大厅结束后：`on_game_start_after_lobby` → `RICE_setup_sri_lanka_after_game_start_effect`**（`RICE_game_start.txt:152`，定义 `RICE_sri_lanka_effects.txt:856-1285`）。斗争在这里才启动，因为要读游戏规则。关键片段：

```
if = {
    limit = { has_game_rule = RICE_struggle_sri_lanka_toggle_on }
    if = {
        limit = { has_game_rule = RICE_sri_lanka_starting_phase_accumulation }
        start_struggle = {
            struggle_type = RICE_sri_lanka_struggle
            start_phase = struggle_RICE_sri_lanka_phase_degeneration
        }
        # Won't start on any other phase but the predefined starting phase
        struggle:RICE_sri_lanka_struggle ?= {
            change_struggle_phase = struggle_RICE_sri_lanka_phase_accumulation
        }
    }
    ...
    struggle:RICE_sri_lanka_struggle ?= {
        trigger_event = { on_action = RICE_sri_lanka_struggle_starting_events }
    }
}
```
（`RICE_sri_lanka_effects.txt:859-874, 960-962`）

要点：`start_struggle` 只能从斗争定义里的 `start_phase` 开始，想从别的阶段开局，只能先启动再 `change_struggle_phase`（注释 `:870`）。启动后立刻在斗争作用域触发 on_action `RICE_sri_lanka_struggle_starting_events`（`common/on_action/RICE_sri_lanka_struggle_on_actions.txt:23-27`），它只装了 `sri_lanka.0003`，即年度维护事件。作者在斗争文件里注释说 `on_start` 里触发事件"不知为何不生效"，所以挪到了启动斗争的地方（`RICE_sri_lanka_struggle.txt:35-39`）。

**(3) 年度全局脉冲：`yearly_global_pulse` → `RICE_sri_lanka_maintenance_yearly_global_pulse`**（`RICE_sri_lanka_struggle_on_actions.txt:1-20`）。只要没有走到"摧毁僧团"结局，每年依次执行四个效果：补全缺失的声望变量 → 按阶段随机漂移 → 截断到 0~1000 → 给相关统治者发通知。

**(4) 斗争年度事件 `sri_lanka.0003`**（`events/RICE_sri_lanka_events.txt:217-384`）：作用域是 struggle，每年激活原版 `catalyst_passing_of_time` 和一组"按全岛状况结算"的催化剂（见 6.1），最后 `trigger_event = { id = sri_lanka.0003 years = 1 }` 自我重排（`:379-382`）。

## 5. 人物个人故事

### 5.1 维阇耶巴忽一世（`character:189029`，1066 书签）——"历史志向"全流程

这是本包唯一一条完整的人物任务线，也是 RICE 全 mod 通用的"historical aspiration"框架的标准用例（框架拆解见 6.6）。

1. **开局装备**（`RICE_sri_lanka_effects.txt:269-302`）：
   - 加标记修正 `RICE_sri_lanka_aspiration_rule_sri_lanka`（`:270-272`）。这个修正没有数值，只有志向图标（`RICE_sri_lanka_modifiers.txt:771` 起），它的描述就是任务说明；
   - 设变量 `RICE_historical_aspiration = flag:vijayabahu`（`:273-276`）；
   - 在指定省份刷出一支 Velakkara 卫队（4 队 Velakkara + 2 队 paiks + 2 队轻步兵 + 1 队长枪，`:277-301`）；
   - 补设家庭关系：`character:189030` 的母亲设为新人物莉拉瓦蒂（`:304-310`）。注释承认这在时间线上并不严格成立（`:307`）。
2. **大厅后补 flag**：`add_character_flag = RICE_is_vijayabahu`（`:1249-1257`）。后续决议用 flag 认人，不直接写 `character:189029`，见第 9 节亮点 7。

## 10. 问题与局限

1. **【缺陷】亚当峰完成日志用错键**：`RICE_sri_lanka_sri_pada_pilgrimage_completed_log_entry_effect` 写的是 `key = RICE_sri_lanka_ramasetu_pilgrimage_completed_log`（`effects:3664`），所以活动结算界面会显示"完成了前往罗摩桥的朝圣"；正确的键 `RICE_sri_lanka_sri_pada_pilgrimage_completed_log` 已写好但没被使用（`rice_sri_lanka_l_english.yml:543`）。
2. **【缺陷】规则重复**：初始声望"high"与"balanced"同为 100（`effects:968-986` 对比 `1006-1024`）。
3. **【缺陷】难度规则无消费者**：`RICE_sri_lanka_difficulty` 四个选项（`RICE_sri_lanka_game_rules.txt:2-26`）全 mod 没有任何 `has_game_rule` 引用。
4. **【缺陷】承诺了不存在的决议**：选圣物事件提示"现在可以采取重新供奉圣物的决议"（`rice_sri_lanka_l_english.yml:1035`），但该决议整段被注释（`decisions:2036-2258`），对应的组件文件 `decision_view_widget_RICE_sri_lanka_enshrine_relic.gui` 成了孤儿。
5. **【缺陷】important action 点击无效**：见 6.7。
6. **进度条基础类型的默认值**：基础类型的 `block` 默认读大寺数值，并用 `FixedPointToFloat`（`progressbar_types.gui:95-97, 104-106`），派生类型用 `FixedPointToInt`。派生类型都已覆盖这两个 block，所以运行无误，但如果有人直接用基础类型，会默认显示大寺数据。
7. **斗争原生钩子不可用**：`on_start` 和 `on_change_phase` 都是空的（`RICE_sri_lanka_struggle.txt:35-47`），作者用"启动后立刻改阶段 + 手动触发 on_action"绕开。另外 `sri_lanka.0003` 先后写了两次 `scope =`（`events:219-220`），以后一个 `scope = struggle` 为准，属于残留写法。
8. **结局规则前后不一致**：异国复兴决议仍可用，但从斗争面板的结局列表里注释掉了（`RICE_sri_lanka_struggle.txt:276, 496, 711`），玩家在斗争 UI 里看不到这条路线。
9. **大量停用代码**：两个 CB 文件约 53KB 全部注释；9 个记忆类型从未调用；0011~0013"寺院消亡"事件注释；ID 段 0090-0099 只有本地化占位，没有事件。
10. **硬编码人物 ID 不一致**：决议里刻意不用 `character:189029`（亮点 5），但 `sri_lanka.0014` 的描述触发器和 `immediate` 仍直接写了 `character:189029`（`events:1505, 1554`）。王朝继承者在非 1066 开局执行决议时可能在 error.log 留记录。
11. **未使用效果**：`RICE_sri_lanka_monastery_prominence_gain_all_minor_effect` 名为 minor，实际加 massive 数值，且没有调用点（`effects:4485-4525`）。
12. **数值节奏**：结局条件绑定"≥900"这一个硬阈值，而年度漂移在积累阶段只有 0~3。实际推进主要靠反复供养（5 年冷却，`decisions:1219`，每次 +5~+15）。AI 的选寺/供养权重在首都不在南亚或缅甸时减到 0 以下，在印度大陆也会因不在岛上而减半（`decisions:706-728, 1642-1664`）。结局决议虽然 AI 权重 100、每 120 个月检查一次（`decisions:145-156`），但我判断 AI 很难自己把某寺从 100~150 推到 900，结局基本要靠玩家推动（这是推断，没有实测）。

## 本包可迁移的设计模式

1. **"多方声望 + 斗争阶段"双层结构**：底层用 N 个全局变量表示各派实力，上层借原版斗争系统表示时代气候；结局判定看"某派≥阈值 + 玩家站队"。对应汉末清流、浊流（外戚、宦官）党争，或魏晋玄学、佛教、道教诸派之争，可以直接套用。
2. **"只显示不执行"的自定义斗争参数**：机制写在年度脉冲里，用 `struggle_parameter_<自定义键>` 本地化把说明塞进原版斗争面板，零 GUI 成本。
3. **身份分流催化剂**：同一行为按执行者宗教/文化激活不同催化剂，在不同阶段指向不同方向，让"谁来做"比"做什么"更重要（例如：清议士人与宦官同样"禁锢党人"，效果相反）。
4. **人格即催化剂**：年度遍历卷入者的罪孽/美德数量自动推动局势，无需玩家操作也能演化。
5. **选项列表决议 + 内嵌进度条 + flag 变量 + 单一结果事件**：决议负责选择，事件负责叙事和结算；进度条同时放在决议面板和事件窗口里。记得给 AI 写 `random_list` 兜底。
6. **历史志向框架**（6.6）：变量身份 + 空数值标记修正承载任务描述 + important action 提醒 + 年度集中判定 + 行为埋点副目标 + 奖励事件清理。可直接替代你那边"天意青睐"的隐形加成，把目标做成显性任务。
7. **通知事件兼执行事件**：全屏结局只写一个事件，`root = scope:当事人` 时执行，否则 `show_as_tooltip`。
8. **结局写入宗教教义（special 组 + `is_available_on_create`）**，作为不可逆的历史烙印。对应"罢黜百家""佛教东传"之类的定局，可写进信仰。
9. **史料细节做成机制**：铜版铭文写成"永久钩子 + 收回权降级 + 不衰减文物 + 王朝特权修正"。正史里的"赐铁券""免死"可以照此翻译。
10. **flag 认人、王朝接班**：只在正确书签给历史人物打 flag，后续都检查 flag；本人死后允许同王朝成员继承任务。

## 4. 机制循环

```

  决议（一生一次，有 perk/传统可重复）→ 七选一（按区域限制）→ 修正
        ├→ 每年 70%（有 perk 90%）抽 15 种赠礼事件之一

## 9. 写法亮点

**亮点 1：头衔易手时移交"地方守护"修正**（`events/RICE_tarim_basin_events.txt:10435-10459`）
```
tarim_basin.0170 = {
    hidden = yes
    trigger = {
        scope:title = title:c_khotan
        NOT = { has_global_variable = RICE_tarim_basin_khotan_eight_protectors_abandoned }
    }
    immediate = {
        if = {
            limit = {
                religion = religion:buddhism_religion
                scope:previous_holder = {
                    is_alive = yes
                    has_character_modifier = RICE_tarim_basin_khotan_eight_protectors
                    NOT = { has_title = title:c_khotan }
                }
            }
            scope:previous_holder = { remove_character_modifier = RICE_tarim_basin_khotan_eight_protectors }
            add_character_modifier = { modifier = RICE_tarim_basin_khotan_eight_protectors }
        }
        else_if = { ... RICE_tarim_basin_eight_protectors_abandoned_effect = yes ... }
```
巧处：挂在 `on_title_gain` 三个钩子上，用 `scope:title` 精确过滤到一个县，开销极小；"守护者修正"跟着头衔走，跟人无关。对应你的"汉家冠带""天子名分"之类附在特定地点或头衔上的身份，可以照此做。

...

ordered_in_global_list = {

```
巧处：`saved scope` 跨不了"数年后由别的脉冲触发的事件"，作者用全局变量列表存人物，再用 `ordered_in_global_list` 取出。注意列表需要手动清理（恢复效果里有清理，`effects:2556-2566`）。用单值全局变量 `set_global_variable = { name = X value = scope:人 }` 也能达到同样目的。

## 10. 问题与局限

1. **【已停用】张议潮整条主线**：入质选择、年度死亡、唐廷赏赐、通知事件全部注释，原因是 `set_player_character` 崩溃（`events:7091-7092`）。结果是 867 年敦煌开局对玩家只剩人物重配和修正，没有剧情推进。
2. **【已停用】敦煌大族系统**：7 个王朝修正和 11 段家族历史背景（`rice_tarim_basin_l_english.yml:91-102`）对玩家完全不可见（5.1）。
3. **【已停用】记忆类型**：8 个全部没有调用点（活动 `on_complete` 里的调用都被注释，例 `RICE_tarim_basin_crescent_lake_visit.txt:329-337`）。
4. **【缺陷】八护法加持概率方向疑似写反**：`num_virtuous_traits <= 1/2/3` 时分别 +6（`effects:1955-1966`），美德越少加得越多，和前面"罪孽越多越减"的方向不一致，原意应是 `>=`（推断）。
5. **【缺陷】修正重复键**：`RICE_tarim_basin_eight_protectors_blessing_1~4` 每个都写了两次 `monthly_piety_gain_mult`（`RICE_tarim_basin_modifiers.txt:284-307`）；`built_mogao_cave_normal` 写了两次 `icon`（`:172-180`）。引擎会合并或覆盖，实际数值和作者设想可能不同。
6. **【缺陷】复制残留**：喀什噶里志向事件 `0208` 的 `after` 在清曹议金的莫高窟变量（`events:11769-11772`）。通知事件 `0017` 在 `immediate` 里对每个收到通知的玩家都重新执行一次罗布泊效果（`:718-723`），效果是幂等的所以无害，但写法上应放进 `show_as_tooltip`。
7. **跨包耦合**：莫高窟朝圣借用诺曼底包的概率脚本值；四座石窟的提示文本借用巴米扬包；事件背景借用西藏包。如果单独拆出某个包会报错，迁移时要连同依赖一起带走。
8. **AI 与选项列表**：莫高窟、丝路社群两个决议都需要 AI 兜底（`decisions:135, 834`），注释写"AI 总是选第一个或总选东亚"。
9. **硬编码 ID 依赖书签窗口**：setup 里大量直接写 `character:206811`、`character:1059714` 等（`effects:350, 400` 等），没有 `?=` 保护，依赖日期窗口和 `hmi_immersion_pack_loaded` 之类的兼容开关（`:333`）。和其他改人物的 mod 同开时容易在 error.log 里报错。
10. **永久状态缺少"软回滚"**：八护法被弃以后只能靠一个门槛很高的决议恢复（公爵级、持有于阗、虔诚 3 级），1050 年后开局默认就是被弃状态。

## 本包可迁移的设计模式

1. **地点守护修正 + 头衔/改宗钩子 + 永久失守 + 收复决议**：把"某城的神圣地位"做成全局状态机（八护法）。对应洛阳、长安的"天子之都"、曲阜孔庙、五斗米道汉中治所，可以做"失陷 → 士人/道众流亡 → 收复后重建"。
2. **"首个做到者"继承史实角色名分**（阿里·阿尔斯兰等价者）：用全局名单记人，去世后解锁纪念性决议和节庆。适合"首个迎天子者""首个称帝者"。
3. **工程决议模板**（莫高窟）：决议 → 项目变量 → 一次性预约 N 个独立概率的途中事件（可改项目变量）→ 定时完工按变量结算 → 后续回访事件。直接适用于太学、修长城、修《汉书》、开凿石窟（云冈、龙门）。
4. **全局唯一工程的死亡兜底**（突厥语词典）：继承人续完，或重新开放；配合三态开放（本人 / 任何人 / 关闭）适配多书签。
5. **侨民社群系统**：一次选择 → 长期修正 → 赠礼事件池（描述按社群切换）→ 社群专属决议。可改成"胡商、羌胡、南匈奴、西域僧侣"等汉晋时期的侨居群体。
6. **反派历史志向**（耶律乙辛）：把"杀死某人及其子女""让皇帝对你好感≥25"写进主目标，奖励永久钩子。适合董卓、梁冀、司马懿等权臣线。
7. **大族王朝修正 + 家族史卡片**（虽已停用，设计完整）：每个门阀一个小王朝修正，开局按王朝弹出一段历史背景。几乎可以原样用于汉末世家，而且不需要换人代码。
8. **书签专用头衔**（`holder = 0` 次年清空）：在多剧本 mod 里放只属于某个剧本的家族或流亡政权。
9. **日历锚定节庆活动**：月份门槛 + `trigger_on_next_date`，加随机插入的地方传说短事件（于阗 8 个传说），用很低的成本讲完一地的神话。
10. **按开局日期切换地理状态**：罗布泊在早期开局是旱期，之后某年变为波动期；这和《汉晋春秋》的时代完全重合，可以直接借来写楼兰衰落、河西绿洲变迁。

## 附：两包对《汉晋春秋》的落地要点（跨包归纳）

- **任务显性化**：两包的人物线都用"空数值标记修正 + 描述里写任务清单 + 年度集中判定"的历史志向框架（斯里兰卡 6.6）。你现在的"天意青睐"是隐形加成，可以按这个框架改造成玩家看得见的目标；年度判定写在一个文件里，便于维护。
- **避免换人崩溃**：RICE 自己因为 `set_player_character` 崩溃，砍掉了整条张议潮剧情（塔里木 5.1）。需要"扮演某人"时，优先用书签可选角色、附属可选角色（`relation = ...`），或书签专用头衔，不在事件里调用 `set_player_character`。
- **选项列表决议必须给 AI 兜底**（两包共 3 处 `random_list`）。
- **斗争系统可以"借壳"**：自定义斗争只要列出原版通用催化剂就能自动响应原版行为，自制机制再用"只显示的阶段参数"挂到原版斗争面板上（斯里兰卡 6.1、6.2）。如果要做"清议与宦官之争"或"三玄与佛道之争"，这是成本最低的路线。
- **小心可能不执行的写法**：模板 `after_creation`（你的笔记里记录过不执行的情况）、struggle 的 `on_start`（RICE 注释说不生效）都需要实测或绕开。
