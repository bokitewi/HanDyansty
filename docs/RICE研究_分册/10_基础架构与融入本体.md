## 0. 一句话总结：RICE 是怎么融入本体的

**RICE 不覆盖原版任何一个文件，也不用 `INJECT/REPLACE`；它只做三件事：①用全新键名新增数据库条目（文化、宗教、头衔、事件、效果……与原版零重名）；②把自己的逻辑「挂」在原版 on_action 钩子上（`原版钩子 = { on_actions = { RICE_xxx } }`），在开局时用一大串脚本效果去「改写」原版世界（改县文化/信仰、给人物头衔、加建筑、改原版文化的传统）；③凡是必须改原版文本的，一律放进 `localization/replace/`，凡是要和别的大 mod 共存的，用「同名共享文件 + 桩函数 + 加载顺序金丝雀检测」解决。**

换句话说：原版的地图、人物、历史文件一个字没动，RICE 的 44 个地区包全部是「开局脚本 + 定时脉冲 + 事件/决议」在运行时叠上去的。这是它能和几乎所有大型 mod 共存、又能每个 CK3 版本快速跟进的根本原因。

下面这些机械检查结论是主线程已确认的（本分册直接引用，并在相应章节补充细节）：
- events/gui/history/localization/map_data/gfx/music 中**零文件与原版同路径**；全 mod 无 `INJECT:/REPLACE:/TRY_INJECT:`。
- cultures(219)、traditions(99)、religion_types(44)、landed_titles(102 顶层)、decisions(292)、scripted_effects(905) 等数据库顶层键与原版零重名，唯一例外是 6 个纹章（见 §6.7）。
- 我补查的数据库（脚本统计，原版对照）同样零重名：faith_types 103、rite_types 106、holy_site_types 41、doctrine_types 48、pillars 117、innovations 45、name_lists 82、ethnicities 24、character_memory_types 120、legends 26、scripted_character_templates 111、scripted_triggers 184、script_values 398、opinion_modifiers 140、artifacts 65、men_at_arms 17、important_actions 6、travel 15。

## 1. 启动与开局

### 1.1 两段式开局：`on_game_start` 改世界，`on_game_start_after_lobby` 处理玩家与规则

RICE 的开局分成两个钩子，分工非常清楚：

| 阶段 | 钩子 | RICE on_action | 位置 | 干什么 |
|---|---|---|---|---|
| 一 | `on_game_start` | `RICE_setup_on_actions` | `common/on_action/RICE_game_start.txt:1-129` | 改地图、改原版文化/信仰、给人物发头衔，44 个风味包的 setup 效果 |
| 二 | `on_game_start_after_lobby` | `RICE_setup_after_game_start_on_actions` | `common/on_action/RICE_game_start.txt:132-309` | 需要知道「谁是玩家」「开了什么规则」的东西：开局邀请事件、按规则删冒险者、警告事件 |
| 二' | `on_game_start_after_lobby` | `RICE_setup_after_game_start_on_actions_after` | `common/on_action/000_RICE_game_start_after.txt:5-15` | 只调用一个效果 `RICE_upper_egypt_admin_egypt_after_game_start_effect` |

作者在注释里写明了第二段的理由：「called once the host … exits the lobby. Good for anything where you need to know who the players are, or what the game rules are」（`common/on_action/RICE_game_start.txt:131`）。原版自己也是这样分工的：原版 `on_game_start_after_lobby` 定义在 `原版 common/on_action/game_start.txt:2553`。

`000_RICE_game_start_after.txt` 文件头注释写的是「Game start effects put here that need to run after vanilla effects」（`000_RICE_game_start_after.txt:1`）。它处理的是原版规则 `historicity_extra_admin_egypt_historic_always`（原版定义在 `原版 common/game_rules/00_game_rules.txt:1405`，原版在 `原版 common/scripted_effects/00_ep3_decision_effects.txt:254` 使用）。**推断/未验证**：文件名 `000_` 前缀与执行先后的关系我无法从代码确认；更可能的解释是「after_lobby 本身就在原版 on_game_start 之后」，文件名只是作者习惯。

### 1.2 第一段：`RICE_setup_on_actions` 的内容

`common/on_action/RICE_game_start.txt:7-129` 的 effect 依次做了：

1. **全局「RICE 已加载」标记**：`set_global_variable = { name = is_RICE_loaded_global_variable value = yes }`（:16-19）。（推断）这是给别的 mod 检测 RICE 用的——RICE 自己从不读取它，全 mod 只在 :16 设置、在 `RICE__misc_effects.txt:80` 的防报错列表里出现。
2. **时代开关**：若 `current_date < 700.1.1`（即在 TFE 的古代开局上运行），设 `RICE_game_started_on_TFE_start_date`（:39-47）。这个全局变量随后被传统、决议、活动、模板大量读取，例如 `common/culture/traditions/RICE_regional_traditions.txt:293`、`common/decisions/RICE_aachen_decisions.txt:17`、`common/activities/activity_types/RICE_rhodes_visit_to_the_colossus.txt:22`。
3. **小彩蛋**：给 `c_lycia` 加圣诞老人修正 `RICE_misc_myra_santa_claus`（:50-54）。
4. **通用风味**（:66-76）：DNA 复制、非洲通用、东亚通用、`RICE_crabs_start_up_effect`；东南亚通用效果**只在 `roa_is_active = no` 时**执行（:71-76），因为 ROA 有自己的东南亚设定。
5. **44 个风味包的 setup 效果**（:84-127），按发布时间排列，每行后面注释包名与发布日期，例如：

```
RICE_setup_siwa_flavor_pack_effect = yes			# Oases of the Western Desert		10/31/20
RICE_setup_chios_flavor_pack_effect = yes			# Isle of Mastic					10/31/20
...
RICE_setup_hangzhou_flavor_pack_effect = yes 		# Splendor of the Song Dynasty		12/09/25
RICE_setup_aslian_flavor_pack_effect = yes 			# The Jungle Pacifists				12/09/25
RICE_setup_mayo_flavor_pack_effect = yes 			# Heather and Yew 					02/02/26
RICE_setup_oceania_flavor_pack_effect = yes 		# The Final Frontier				XX/XX/26
```
（`common/on_action/RICE_game_start.txt:84-85,124-127`）

每个包的 setup 效果都定义在自己的 `common/scripted_effects/RICE_<包>_effects.txt` 第 1~3 行，命名统一为 `RICE_setup_<包>_flavor_pack_effect`。**这就是 RICE 的「包注册表」：新加一个包 = 新建一个 effects 文件 + 在这里加一行。**

			limit = { has_cultural_tradition = tradition_court_eunuchs }

		}

			limit = {
				has_tgp_dlc_trigger = yes
			}

（`RICE__general_east_asian_effects.txt:12-27`）

## 2. on_action 总架构

### 2.1 原版规则与 RICE 的两种挂法

原版文档 `原版 common/on_action/_on_actions.info:106-119` 写明：同名 on_action 可以分散在多个文件，但**同一个 on_action 只能有一个 `trigger`、一个 `effect` 块**；想给原版 on_action 追加效果，应该写成 `原版钩子 = { on_actions = { 我的 } }`，再在「我的」里写 effect。

RICE 两种写法都用：

1. **标准挂法**（绝大多数）：`yearly_global_pulse = { on_actions = { RICE_yearly_global_pulse } }`（`common/on_action/RICE_events_on_actions.txt:1-3`）+ 自己的 `RICE_yearly_global_pulse = { effect = {...} }`（:5-898）。

### 2.3 三层脉冲：世界导演 / 个人维护 / 随机风味

**第一层：`yearly_global_pulse` 的「世界导演」**（`RICE_events_on_actions.txt:5-898`）。无 root，每年 1 月 1 日跑一次，全是 `if + 全局变量 + random`，负责「历史大事什么时候发生」：于阗八护法被弃、格拉纳达犹太人冲突、阿尔罕布拉宫完工、花剌子模城堡毁坏、罗洛的预言梦、雅兹迪/雅尔桑派出现、嚈哒后裔转为哈拉吉文化、米拉日巴挑战苯教、伏藏师机制触发……典型写法：

```
		# Turco-Hephthalite -> Khalaj culture shift
		if = {
			limit = {
				current_date <= 1066.1.1 # No need to check this in later starts
				NOT = { has_global_variable = khalaj_culture_creation }
				current_date >= 800.1.1
				...
			}
			random = {
				chance = 0 # No chance the first year of play if starting in 867
				modifier = {
					add = 1 # 1% chance per year
					current_date >= 925.1.1
				}
				...
				set_global_variable = { name = khalaj_culture_creation value = yes }
				trigger_event = { id = pamir.0116 days = { 60 300 } }
			}
		}
```
（`RICE_events_on_actions.txt:706-777` 节选）

要点：**用「随年份递增的每年概率」代替固定日期**，历史大事既大致按时发生又有变数；**先设全局变量再发事件**，保证只发生一次。还有一个调试后门：

```
				modifier = {
					add = 99999
					has_global_variable = RICE_milarepa_testing_on_actions
				}
```
（`RICE_events_on_actions.txt:802-805`；伏藏师同理 :835-838、:878-881）

测试时在控制台设这个全局变量，下个 1 月 1 日事件必定触发。这些测试变量在 `RICE_setup_have_to_set_variable_effect`（`RICE__misc_effects.txt:106-137`）里被「设了又删」，以免 error.log 报「从未设置」。

**第二层：个人维护脉冲** `RICE_events_yearly_maintenance_pulse`（`RICE_events_on_actions.txt:941-1170`），是 `yearly_playable_pulse` 里**唯一没有延迟**的子项（:909），纯 effect：例如 AI 每年有概率选择支持斯里兰卡某座寺院（:943-...）、伏藏发现机制（:1095-1168，玩家走长事件链，AI 直接给结果，注释「Don't trigger the longer travel event chain for AI for performance reasons」:1110）。

**第三层：随机风味池**（`random_events`）：yearly（:1173）177 个事件、tri（:1475）175 个、five（:1773）91 个、courtier（:1983）46 个、historical（:2102）14 个随机 + 3 个必发、silk road（:2176）15 个、cultural / irregular 各 1 个（脚本统计）。

### 2.4 `events`、`random_events`、`effect` 各怎么用

- **`events = { }`**：列表里每个事件只要自己的 trigger 为真就**必定**触发。RICE 用于「事件自己判断该不该发」的场合：死亡后续 `on_death_RICE` 的 11 个事件（`RICE_death_on_actions.txt:32-45`）、历史 pulse 里 3 个「编纂完成」类事件（`RICE_events_on_actions.txt:2104-2109`）、旅行开始时 48 个活动开场事件（`RICE_travel_on_actions.txt:256-327`，每个事件内部检查是不是自己对应的活动）。
- **`random_events = { }`**：按权重**只挑一个**。RICE 的标准结构是「有效事件各 100 权重 + 一个巨大的 `N = 0` 空项」：

```
RICE_events_yearly_pulse = {
	trigger = {
		RICE_basic_is_available_adult_trigger = yes
	}
	random_events = {
		chance_of_no_event = {
			value = 30
			if = { limit = { has_game_rule = RICE_event_frequency_low } add = 10 }
			...
			if = { limit = { is_at_war = yes # Won't get spammed while at war
				} add = 10 }
		}
		20000 = 0
		# SIWA OASIS
		100 = siwa.0051		# Buy a well in the Western Desert?
		100 = siwa.0057		# Pass by Infidel Rock
```
（`RICE_events_on_actions.txt:1173-1216`，中间 if 块有压缩）

原版文档说明 `0` 项的作用：「Having a "0" entry means that there is a chance no event fires, even if there are other valid events」（`原版 common/on_action/_on_actions.info:69`）。地区事件都带地区 trigger（例如 `siwa.0051` 要求 `RICE_is_in_western_desert_trigger = yes`，`events/RICE_siwa_events.txt:13-18`），所以对任何一个角色，177 个里通常只有几个有效——**20000 的空项保证「本地事件少的人和本地事件多的人」都不会被刷屏**，有效事件越多触发率越高，但始终是小概率。事件自身的 `weight_multiplier` 再按性格微调（`events/RICE_siwa_events.txt:20-45`）。
- **`effect = { }`**：无条件跑脚本，用来做「判断 + 设变量 + 定向发事件」。注意原版文档提醒 effect 与同一 on_action 的 events 是并行的（`_on_actions.info:95`），所以 RICE 的 effect 型 on_action 基本不同时写 events（例外是 `on_death_RICE` 和 `on_travel_plan_start_RICE`，两者的 effect 与 events 互不依赖）。
- **`random_on_action`**：旅行事件三档抽签 `RICE_travel_random_event_tombola`（`RICE_travel_on_actions.txt:433-439`），6:4:2 选「常见/少见/罕见」三个子 on_action，每档又有自己的 `chance_of_no_event = 65` 和空项 3000/5000/7000（:487、:554、:617）。

### 2.5 事件频率规则 `RICE_event_frequency` 怎样作用到概率

**没有专门的 script_value 或 scripted_trigger**——规则直接内联在各个 pulse 的 `chance_of_no_event` 里。全部生效位置（`grep` 确认）：

- `RICE_events_on_actions.txt:1178-1210`（yearly）、:1480-1508（tri）、:1778-1806（five）；
- `RICE_travel_on_actions.txt:453-485`（common）、:520-552（uncommon）、:583-615（rare）。

默认 `chance_of_no_event = 30`；low +10、very_low +20、high −10、very_high −20；年度 pulse 另有「在战争中 +10」。

**概率估算**（以年度 pulse 为例，设有效事件权重和为 ΣW，事件 weight_multiplier ≈ 1）：

P(今年触发一个 RICE 年度事件) ≈ (1 − c/100) × ΣW / (20000 + ΣW)

| 有效事件数（各 100） | 默认 c=30 | very_low c=50 | very_high c=10 |
|---|---|---|---|
| 3 | ≈1.0% | ≈0.7% | ≈1.3% |
| 10 | ≈3.3% | ≈2.4% | ≈4.3% |
| 20 | ≈6.4% | ≈4.5% | ≈8.2% |

三年 pulse 的空项是 24000（`RICE_events_on_actions.txt:1514`，注释「1100 before」说明作者调过），五年 pulse 是 28000（:1812）。可见**频率规则只是把结果乘以 6/7、5/7、8/7、9/7**，真正决定频率的是空项权重。规则本地化里作者也提醒「Due to the way RNG works, you may still see many events at once」（`localization/english/rice_misc_l_english.yml:57`）。

### 2.6 廷臣刷新规则 `RICE_courtier_spawn_frequency`

同样内联，只出现在两处：`RICE_events_on_actions.txt:1988-2014`（`RICE_events_courtier_yearly_pulse`）和 `RICE_BAP_shared_events_on_actions.txt:292` 起的 `RICE_BAP_events_courtier_yearly_pulse`（high 在 :313）。挂在**五年 pulse** 上（`RICE_events_on_actions.txt:931-938`），空项只有 1000（:2016），各刷新事件权重 5~200（例如大洋洲按距离递减：100/65/40/20/5，:2091-2095）。估算：西西里统治者有 2 个有效刷新事件（各 100）时，每 5 年 ≈ 0.7×200/1200 ≈ 11.7%。

### 2.7 历史志向系统（`RICE_aspirations_on_actions.txt` + `RICE_aspirations_custom_loc.txt`）——RICE 的「目标任务」框架

文件头：「ASPIRATIONS SYSTEM. "Completion" is calculated yearly in on actions to keep things simpler to code.」（`common/on_action/RICE_aspirations_on_actions.txt:1-7`）。这是跨包通用的**历史人物个人目标**框架，由四件套组成：

**① 开局设定（在各包 setup 效果里）**：给人物加一个**只有图标的修正** + 设变量 `RICE_historical_aspiration = flag:<人物>`。萨夫丹例：

```
		character:163094 = {
			make_siqilli_culture_effect = yes
			add_character_modifier = {
				modifier = RICE_sicily_aspiration_establish_islam_in_southern_italy
			}
			set_variable = {
				name = RICE_historical_aspiration
				value = flag:sawdan
			}
			spawn_army = { ... }
```
（`common/scripted_effects/RICE_sicily_effects.txt:455-466`）

修正本身只有图标（`common/modifiers/RICE_sicily_modifiers.txt:157-160`：`icon = RICE_aspiration_icon`，`#learning = 1` 被注释掉）。**目标与奖励全部写在修正的 desc 本地化里**：`RICE_sicily_aspiration_establish_islam_in_southern_italy_desc` 引用 `$RICE_sicily_aspiration_sawdan_desc$`（`localization/english/rice_sicily_l_english.yml:505`），后者列出「主要目标 / 奖励 / 额外目标（各自的奖励）」，并用 `[EmptyScope.ScriptValue('RICE_aspiration_medium_resource_bonus')]` 把奖励数值从 script_value 动态显示出来（:487）。奖励档位统一定义在 `common/script_values/RICE_misc_values.txt:8-15`（tiny 200 / small 500 / medium 1000 / large 2000 / huge 4000）。

**② 界面提醒**：重要行动 `action_RICE_historical_aspiration`（`common/important_actions/RICE__misc_actions.txt:5-27`），只要角色有这个变量就在右上角出提醒，点击打开角色界面：

```
	check_create_action = {
		if = {
			limit = {
				exists = var:RICE_historical_aspiration
			}
			try_create_important_action = {
				important_action_type = action_RICE_historical_aspiration
				actor = root
			}
		}
	}
```

提醒的标题/描述走自定义本地化：`action_RICE_historical_aspiration:0 "[GetPlayer.Custom('RICE_historical_aspiration_action_title_name')]"`（`localization/english/rice_misc_l_english.yml:196-199`），三个自定义本地化 `RICE_historical_aspiration_action_title_name / _action_desc / _modifier_desc`（`common/customizable_localization/RICE_aspirations_custom_loc.txt:3,287,582`）按 `var:RICE_historical_aspiration ?= flag:xxx` 分支取不同人物的文本：

```
	text = {
		trigger = {
			var:RICE_historical_aspiration ?= flag:sawdan
		}
		localization_key = RICE_sicily_aspiration_establish_islam_in_southern_italy
	}
```
（`RICE_aspirations_custom_loc.txt:40-45`）

术语用游戏概念 `historical_aspirations`（含别名 `RICE_aspiration` 等）和子概念「主要目标/额外目标/路线」（`common/game_concepts/RICE_misc_game_concepts.txt:13-35`）。

**③ 年度结算**：`yearly_global_pulse → RICE_aspirations_pulse`（`RICE_aspirations_on_actions.txt:12-18`），按书签分三段（867 在 :22、1066 在 :401、1178 在 :886），对每个人物写一个「完全达成条件」的大 limit，满足就发奖励事件。共 37 处 `has_variable = RICE_historical_aspiration` 检查（脚本统计）。萨夫丹的条件：独立、持有 `d_apulia`、威望或虔诚等级≥3、拿过某决议的标记、南意大利至少 8 县、仍是穆斯林（:111-145，最后 `trigger_event = sicily.0065`）。

**④ 奖励事件与清理**：`sicily.0065`（`events/RICE_sicily_events.txt:3314` 起，至 `sicily.0066` 的 :3461 之前）在 immediate 里：调用 `RICE_historical_aspiration_fulfilled_effect`（定义在 `RICE__misc_effects.txt:1608-1614`，显示「已达成」提示并删除变量）→ 移除图标修正 → 发主奖励 → 逐个检查额外目标发额外奖励 → `after` 里通知地中海区域的其他玩家（`sicily.0066`）。

## 3. 游戏规则（`common/game_rules/` 全部 4 个文件）

### 3.1 写法特征

- 每个设置都写 `flag = GG_can_change_rule`（例如 `common/game_rules/RICE_game_rules.txt:11`）。**这不是原版 flag**：原版文档列出的 flag 只有 `blocks_achievements / no_end_date / ...`（`原版 common/game_rules/_game_rules.info`），原版 game 目录里也搜不到这个字符串。**推断**：留给第三方「游戏中途修改规则」类 mod 识别「这个规则可以中途改」；对原版无作用。四个斗争开关规则（:379-421）没有这个 flag，意味着作者不希望中途改。
- `categories` 同时写自定义类别和原版类别，例如 `categories = { RICE setup flavor }`（:4-6）。`RICE / greenland / vinland / sri_lanka` 的类别名本地化在 `localization/english/rice_misc_l_english.yml:167-170`；`setup / flavor / historicity / tweaks / faith / culture / game_modes / difficulty` 是原版已有类别（原版本地化 `game_rule_category_setup` 等）。**结果是 RICE 的规则既出现在「RICE」页，也混进原版对应页**。
- 规则只负责存一个状态，**所有效果都靠脚本里 `has_game_rule` 实现**；默认值多数不显式检查（「不是其他几档」即默认）。

## 4. 兼容层

RICE 的兼容策略可以概括成五种手段：**桩函数（stub）、检测标记、同名共享文件、金丝雀检测加载顺序、开局覆盖其他 mod 的开局效果**。

### 4.1 桩函数：先定义一个「什么都不做」的版本，让外部 mod 覆盖

`common/scripted_triggers/00000000_compatibility_triggers.txt` 全文只有 7 个恒为假的 trigger：

```
is_tip_trigger = {
	always = no
}

is_dharmachakra_loaded = {
	always = no
}

roa_is_active = {
	always = no
}
...
ME_is_loaded = {
	always = no
}
```
（`00000000_compatibility_triggers.txt:4-30`，中间还有 `paganism_plus_is_loaded`、`ibl_is_loaded`、`is_RICE_CE_temp_compatch_loaded`）

外部 mod 在自己的文件里把同名 trigger 定义成 `always = yes`，RICE 里所有 `roa_is_active = yes` 之类的判断就自动生效。文件名用 8 个 0 开头，确保按文件名排序时最早加载，任何外部 mod 的同名定义都排在它后面。同样思路的还有：

- `common/scripted_effects/00_TFE_compatibility_effects.txt:1-29`：注释「Dummy copies of effects used in TFE, overwritten when used with TFE」，7 个空效果 `RICE_TFE_struggle_*`。
- `common/scripted_effects/00_sow_compatibility_effects.txt:1-8`：注释「Dummy copies of real effects in SoW. Should be overwritten based on file name regardless of load order. However, RICE should still be loaded before SoW because CCU relies on that and is bundled inside SoW」，两个空效果 `apply_province_garrison`、`apply_province_levy`。
- `common/scripted_effects/00_dharmachakra_compatibility_effects.txt:1`：注释「Overwritten when used with Rajas of Asia or Dharmachakra」，这里不是空效果，而是一份完整的 `set_yidam_effect`（本尊神选择，:5 起），外部 mod 有更完整版本时覆盖它。

**推断/未验证**：这个手法成立的前提是「scripted_trigger/effect 同键时，按文件名排序靠后的生效」。作者的注释（「overwritten based on file name regardless of load order」）正是这个意思，但我没有在原版文档中找到明文说明。

桩函数的使用量（`grep` 统计）：`roa_is_active` 40 处、`is_dharmachakra_loaded` 40 处、`ibl_is_loaded` 10 处、`paganism_plus_is_loaded` 7 处、`is_tip_trigger` 5 处、`ME_is_loaded` 2 处、`is_RICE_CE_temp_compatch_loaded` 1 处。

`common/scripted_triggers/j_khd01_RICE_marriage_triggers.txt:1-13` 也是同类：定义 `accepts_polygamy` / `accepts_concubinage`（原版没有这两个 trigger），文件名前缀 `j_khd01_` 显然是为了与另一个 mod 的同名文件对齐；注释写「someone requested to change to parameters below for ease of compatibility, but these don't exist in vanilla」（:15）。RICE 自己只在 `events/RICE_tarim_basin_events.txt:6558` 用到一次。

### 4.4 同名共享文件 + 加载顺序「金丝雀」

**同名共享文件**：RICE 与合作 mod 发布**路径相同、内容一致**的文件（`RICE_BAP_shared_*`、`RICE_kemet_*`、`sea_*`、`EEE_*`、`brus_*`、`hfc_*` 等）。两个 mod 同时加载时，同路径文件按加载顺序只保留一份，从根本上避免重复键。为此 RICE 还会**把共享内容拆到单独文件**：`RICE_BAP_shared_title_on_actions.txt:1` 注释「kept separate to maintain compatibility with BAP」；布佐包的主题单独成文件（`common/event_themes/RICE_bozo_event_themes.txt:4`「Separated from others for compatibility with BAP」）；图阿雷格的温泉事件从 `tuareg.0012` 挪到 `RICEmisc.0020`（`events/RICE_misc_events.txt:325-327`「moved here for compatibility with BAP」），避免共享命名空间里的事件 ID 被对方覆盖。

**金丝雀检测**：如果加载顺序错了，「共享文件」会变成 RICE 的版本盖掉合作 mod 的版本。RICE 在自己版本里放一个**只有自己才有的特征值**，开局检查它是否生效：

```
			if = {
				limit = {
					roa_is_active = yes
					title:c_dagon = {
						is_holy_site_of = faith:burmic
					}
				}
				every_player = {
					trigger_event = RICEintro.0030
				}
			}
```
（`common/on_action/RICE_game_start.txt:254-264`）

## 6. 内容如何挂进地图与历史

**总原则：RICE 没有 `history/provinces/`，也没有改任何原版历史文件**。它的 `history/` 只有 characters（59 个文件）、titles（9）、cultures（1）、situations（1）、wars（1）。地图上「哪个县是什么文化/信仰、谁是领主」的改变，全部由 §1 的开局脚本完成；history 目录只负责「新增的人」「新增头衔的持有者」「新传承的初始创新」「开局即存在的情境」。

### 6.1 地理区域（map_data/geographical_regions）

7 个文件、约 126 个区域（主文件 `RICE_geographical_region.txt` 88 个）。文件头照抄原版的语法说明（:1-12），定义方式三种：

```
RICE_qanat_region = {
	regions = {
		world_middle_east world_africa_north world_africa_sahara world_steppe_tarim world_europe_west_iberia custom_sicily
	}
}

RICE_hephthalite_heartland_region = {
	duchies = {
		#khorasan
		d_balkh
		#k_transoxiana
		d_badakhshan d_khuttal
	}
}
```
（`map_data/geographical_regions/RICE_geographical_region.txt:15-28`）

- **组合原版区域**（`regions = { world_* custom_* }`）做大范围判定，如丝绸之路（:65-75）；
- **列公爵领/县**做小范围判定。被注释掉的尼罗河谷区域里作者写：「Put in counties just in case for compatibility with TFE and potentially other mods that use a different duchy setup」（:43-46 一带）——**用县而不是公爵领定义区域，可以抵御其他 mod 改公爵领**。

使用量（脚本统计 `geographical_region =`/`region =` 的引用）：RICE 区域 965 次，原版区域 2511 次，引用最多的是原版的 `custom_sicily`（215）、`world_asia_minor`（152）。也就是说 **RICE 能用原版区域就用原版的，只在原版没有合适粒度时才自定义**。RICE 区域主要用于：事件/决议 trigger、背景条件（§5.1）、开局批量改县（`every_county_in_region`）、斗争/情境的范围（`RICE_sri_lanka_struggle_region`，`RICE_sri_lanka_geographical_region.txt:15`）、创新的地区限定（§6.8）。

IBL 兼容：IBL 自带一个名为 `RICE_nubia_geographical_region_IBL_version.txt` 的文件，「named that way to ensure that it always loads after and overrides the RICE version」（`RICE_nubia_geographical_region.txt:14-15`）——**靠文件名排序覆盖同名区域**。

## 8. 命名与工程规范

### 8.1 文件命名

- **基本形**：`RICE_<包>_<类型>.txt`：`common/scripted_effects/RICE_siwa_effects.txt`、`events/RICE_siwa_events.txt`、`common/trigger_localization/RICE_siwa_trigger_loc.txt`、`localization/english/rice_siwa_l_english.yml`。音乐例外：`music/in_game/siwa_flavor_pack_music.txt`。少数不统一：`RICE_polabian_effect.txt`（单数）、`RICE_khwarezm_trigger.txt`、`RICE_mordvin_themes.txt`。
- **双下划线 = 核心/跨包**：`RICE__game_start_effects.txt`、`RICE__misc_effects.txt`、`RICE__general_*_effects.txt`、`RICE__misc_triggers.txt`、`events/RICE__setup.txt`、`RICE__test_decisions.txt`、`RICE__misc_actions.txt`、`RICE__setup_dna.txt`、`00_RICE__misc_adventurer_titles.txt`。`_`（0x5F）排在小写字母前，所以核心文件总在各包文件之前。
- **数字/字母前缀控制加载与显示顺序**：

| 前缀 | 用处 | 证据 |
|---|---|---|
| `00000000_` | 桩 trigger，确保最先加载、可被任何外部 mod 覆盖 | `common/scripted_triggers/00000000_compatibility_triggers.txt` |
| `00_` | 头衔、纹章、王朝、兼容桩效果、部分宗教文件 | `common/landed_titles/00_RICE_*`、`00_TFE_compatibility_effects.txt` |
| `000_` | 王朝遗产（界面靠前）、第二个 after_lobby on_action | `common/dynasty_legacies/000_RICE_*`、`000_RICE_game_start_after.txt` |
| `0000_` / `zzz_` | 旅行选项排在原版之前 / 之后 | `zzz_RICE_travel_options.txt:1` |
| `zzzzz_RICE_placeholder` | 占位文化/名单/宗教（宗教已注释） | 见 §8.5 |
| 外部 mod 前缀 | 与合作 mod 同名的共享文件 | `RICE_BAP_shared_*`、`EEE_*`、`sea_*`、`wap_*`、`brus_*`、`hfc_*`、`bao_*`、`RICE_kemet_*` |

### 8.2 键名前缀

几乎所有新键都带 `RICE_`：效果/触发器 `RICE_<包>_*`、主题 `RICE_theme_*`、背景 `RICE_background_*`、修正 `RICE_<包>_*`、全局变量 `RICE_<包>_*`、人物 `RICE_<包>_NNN`、头衔 `d_laamp_RICE_*`、`e_RICE_nile`。**事件命名空间例外**：直接用包名（`namespace = harran`、`siwa.0051`），只有核心用 `RICEintro / RICEmisc / RICEdebug / RICE_ancestor_worship`。少数键没有前缀（`nick_the_sangha_destroyer`、`death_sacrificed_to_ancestor`、`harranian_courtier_template`、`siberian_wanderer_character_template`），目前与原版不冲突，但属于规范上的漏洞。

### 8.4 压 error.log 的工程手段

作者非常在意 error.log 干净，形成了一套固定手法：

1. **永不执行的分支「登记」变量**：`if = { limit = { always = no } RICE_setup_have_to_set_variable_effect = yes }`（`events/RICE__setup.txt:49-52`），被调用的效果只是把一批变量「设了又删」（`RICE__misc_effects.txt:105-137`，注释「Variables need to be set up somewhere or else they'll have an error, which is dumb but oh well」）。
2. **不被调用的效果「引用」修正**：`RICE_setup_no_modifier_or_variable_silliness_effect`（`RICE__misc_effects.txt:7-103`）全 mod 只有定义没有调用，里面用 `has_character_modifier` 列出 60 多个修正和若干全局变量，注释「This is literally needed for the error log to not show a message」（:7）、「These modifiers are literally used in the code … but the error log still thinks they're unused」（:36）。
3. **为外部 mod 的人物补王朝**：`common/dynasties/00__RICE_other_mods.txt:1`。
4. **人名放进 replace 目录**避免重复键报错（§5.8）。
5. **删掉引发报错的规则**（`RICE_game_rules.txt:360`），虽然留下了悬空的检查（§3.2）。
6. 事件 `orphan = yes` 压「未引用事件」警告（如 `RICEintro.0003`、`RICEdebug.*`）。

### 8.5 存档兼容：占位符

`common/culture/cultures/zzzzz_RICE_placeholder.txt:1-8` 注释：「These cultures are placeholders. Their purpose is to ensure savegame compatibility w/ future updates if one is added」。内有 `culture_RICE_placeholder_1~10`（各自完整定义：占位传承、占位语言、占位名单），名单与支柱也有对应占位（`common/culture/name_lists/zzzzz_RICE_placeholder.txt`、`common/culture/pillars/RICE_heritage_placeholders.txt`、`RICE_language_placeholders.txt`、`common/culture/innovations/RICE_placeholders.txt`）。测试决议的注释说明了原因：「Adding new religions/faiths midway through doesn't work, won't show up. Adding new cultures midway through doesn't work, will cause mismatches for saves」（`common/decisions/RICE__test_decisions.txt:8-10`）。**推断**：作者的做法是先占好数量，将来加新文化时把占位条目「改名改内容」，而不是新增条目，从而保持数据库条目数和顺序不变；`zzzzz_` 让它们排在最后。

## 9. 可迁移的工程/架构模式（对汉晋春秋）

1. **零覆盖原则**：不改原版任何文件，只新增数据库条目 + 挂 on_action。汉晋春秋已经有不少「旧副本遮蔽原版」的历史问题，RICE 证明了大型内容 mod 完全可以做到零覆盖，每次跟进原版版本的成本因此极低。
2. **开局「包注册表」**：`on_game_start → RICE_setup_on_actions` 里一行一个 `RICE_setup_<包>_flavor_pack_effect`（`RICE_game_start.txt:84-127`）。汉晋春秋的各剧本/各子系统也可以这样集中注册，新增一个系统只加一行，便于排查开局卡顿与顺序问题。
3. **两段式开局**：改地图/人物放 `on_game_start`；需要知道玩家与规则的（扮演邀请、按规则删内容、警告）放 `on_game_start_after_lobby`。
4. **历史志向（目标任务）四件套**：变量 flag + 只带图标的修正（目标与奖励写在 desc，用 `ScriptValue` 显示数值）+ `important_action` 提醒配 `customizable_localization` + `yearly_global_pulse` 统一结算 → 奖励事件 → `fulfilled_effect` 清变量（§2.7）。适合「曹操：迎天子」「孙策：平定江东」这类人物目标，且完全不碰原版野心系统。
5. **「扮演某人」**：玩家选原版人物时弹事件，选「是」就把头衔给新增的历史人物并 `set_player_character` 切换控制（`events/RICE_harran_events.txt:2123`），再弹「快速开始 / 剧情开场」二选一。可用于让玩家改玩某个没有书签位的历史人物。
6. **世界导演 = 年度全局脉冲 + 随年份递增的概率 + 一次性全局变量**（§2.3），代替死板的固定日期事件；每个大事件再加一个 `+99999` 的测试后门变量。
7. **随机风味池用「巨大空权重」控频**（`20000 = 0`），地区事件靠自身 trigger 过滤；频率规则只调 `chance_of_no_event`。汉晋春秋做「郡县风物事件」时可直接照搬，避免某些州郡被刷屏。
8. **外观三招**：虚拟死人携带 DNA + `copy_inheritable_appearance_from`（改原版或已有人物的长相，不改人物文件）；按 `this = character:X` 或特质加权的 `portrait_modifiers` 强制冠服（与 HanJin_Clothes 直接相关）；`dna_data` 给新人物固定长相。
9. **本地化纪律**：改原版文本只放 `localization/replace/`，非 replace 目录与原版键零冲突；百科式注释用 `[Glossary( '显示', 'KEY' )]`，反复出现的术语才做 game_concept；条件文字用 trigger_localization + `custom_description`。
10. **1.20 新结构的利用**：往原版宗教里加信仰只需写 `faith_types` + `faith_details = { religion = 原版宗教 }`；书签挂进原版 `bm_group_*`；用 `history/situations` 在历史日期启动情境；用 `history/cultures/heritage_*.txt` 给新传承发初始创新；冒险者/贵族家族头衔完全照抄原版 history 写法（含「卒年 `holder = 0`」）。
11. **复用原版钩子变量与列表**：`cannot_be_converted_by_value`（原版 `common/scripted_triggers/00_councillor_triggers.txt:1080` 等处会检查，RICE 在 `events/RICE_misc_events.txt:34-49` 设置）、全局列表 `unavailable_unique_decisions`（RICE 393 处，原版 27 个文件使用）、原版 `major` 决议组、原版规则类别。顺着原版已有的「接口」接入，比自建一套更稳。
12. **兼容层工具箱**：`00000000_` 桩 trigger 留给外部 mod 覆盖；检测外部 mod 独有键（`exists = culture:xxx`）或全局变量；与合作 mod 发布同名共享文件；在自己版本里埋「金丝雀」值，开局检测加载顺序并弹警告；`is_RICE_loaded_global_variable` 供别人检测自己。汉晋春秋与 HanJin_Clothes、UUII 等子 mod 之间可以照这个模式建立约定。
13. **GUI 零覆盖**：进度条用「两个 script_value + `layoutstretchfactor_horizontal`」实现；决议多选用原版 `decision_option_list_controller` + 自制组件；文本图标、组件全部新文件，不碰原版 gui。
14. **存档兼容占位**：预先注册若干占位文化/名单/支柱，将来改内容而不增删条目（`zzzzz_RICE_placeholder.txt`）。
15. **工程卫生**：核心文件用 `RICE__` 双下划线排前；事件文件头写 ID 分段并在每段 reserved；用文件名前缀控制界面排序（`zzz_` 旅行选项、`000_` 遗产）；保持 error.log 干净（必要时用 `always = no` 分支登记变量）；所有新增人物写出处注释。
