### 0.2 随机事件的挂载方式

各包的"风味随机事件"不是自己挂钩子，而是集中在 `common/on_action/RICE_events_on_actions.txt`：

```
yearly_playable_pulse = {                         # :907
	on_actions = {
		RICE_events_yearly_maintenance_pulse
		delay = { days = { 8 288 } }
		RICE_events_yearly_pulse
		delay = { days = { 8 288 } }
		RICE_events_historical_pulse
		...
```

- 原版 `yearly_playable_pulse` / `three_year_playable_pulse` / `five_year_playable_pulse` → RICE 自己的 `RICE_events_yearly_pulse`（`:1173`）、`RICE_events_tri_yearly_pulse`（`:1475`）、`RICE_events_five_yearly_pulse`（`:1773`）、`RICE_events_courtier_yearly_pulse`（`:1983`，专门刷"来投奔的人物"）、`RICE_events_historical_pulse`（`:2102`，史实事件）。
- 每次调用前插一个 `delay = { days = { 8 288 } }`，把全图玩家/角色的事件随机打散到一年里，避免 1 月 1 日集中卡顿。
- `random_events` 里的 `chance_of_no_event` 由游戏规则 `RICE_event_frequency_*` / `RICE_courtier_spawn_frequency_*` 加减（`:1173-1200`、`:1983-2000`），玩家可以在规则里调事件频率。
- 每个事件自己的 `trigger` 负责判断地区（如 `has_title = title:c_socotra`、`capital_province = { geographical_region = ... }`），池子里全球事件共用一个权重表，按"包"分段写注释（如 `# SOCOTRA` `:1254`）。
- 非洲西部几个包（guanche / niger_delta / bozo / tuareg / south_ethiopia）的随机事件不在这个文件里，而是在 `RICE_BAP_shared_events_on_actions.txt`，结构完全相同（`:6-25` 同样挂三个 playable pulse，加 `random_yearly_everyone_pulse` `:31`）。原因见文末"外来内容"一节。

### 0.3 "历史志向"（Historical Aspiration）系统——RICE 的目标任务框架

这是 RICE 做"人物个人目标"的通用框架，非洲区里 Rahabhan（索科特拉）、al-Umari（红海）都用它。完整链条：

1. **发任务**：开局 setup 给指定历史人物 `set_variable = { name = RICE_historical_aspiration value = flag:<人物键> }`，同时挂一个 `RICE_<包>_aspiration_<目标>` 角色修正（修正本身几乎无数值，**它的描述文字就是任务书**，列出主目标、奖励、附加目标）。例：`common/scripted_effects/RICE_socotra_effects.txt:253-266`。
2. **提醒入口**：`common/important_actions/RICE__misc_actions.txt` 定义了一个通用的 `action_RICE_historical_aspiration`（`type = alert`），`check_create_action` 只看 `exists = var:RICE_historical_aspiration`，点击后 `open_view_data = { view = character }`。所有人物共用这一个"重要行动"提示。
3. **文案切换**：`common/customizable_localization/RICE_aspirations_custom_loc.txt` 用 `var:RICE_historical_aspiration ?= flag:rahabhan` 这类判断，为同一个提示切换标题/描述（标题段 `:3` 起，Rahabhan 分支在 `:279`）。
4. **年度检查**：`common/on_action/RICE_aspirations_on_actions.txt` 挂在 `yearly_global_pulse`（`:12-16`），文件头注释直说"完成度每年在 on_action 里算一次，写起来简单"（`:1-6`）。内部先按 `game_start_date = 867.1.1 / 1066.9.15 / 1178.10.1` 分书签（`:27`、`:407`、`:891`），再逐个写 `character:X = { is_alive = yes ... has_variable = RICE_historical_aspiration }`，满足就 `trigger_event` 完成事件。
5. **附加目标的记录法**：完成某个附加目标的决议/事件里写 `if = { limit = { has_character_modifier = <aspiration 修正> } add_character_flag = <完成标记> }`——只有正在执行该志向的人才会留下标记，别人做同一决议不受影响。
6. **结算**：完成事件调用 `RICE_historical_aspiration_fulfilled_effect`（`common/scripted_effects/RICE__misc_effects.txt:1608-1614`，删变量 + 显示"志向已完成"），移除修正，发主奖励（数值统一取 `common/script_values/RICE_misc_values.txt:8-15` 的 `RICE_aspiration_tiny/small/medium/large/huge_resource_bonus` = 200/500/1000/2000/4000），再逐条检查附加目标标记发附加奖励。

### 本包可迁移的设计模式
1. **志向 = 变量 + 修正描述 + 年检 + 附加目标标记**：给史实人物一个"主目标 + 附加目标"的任务书，奖励分档发放；附加目标标记只在"带着志向修正"时才记录。
2. **传说多版本由玩家选**：介绍事件让玩家决定人物来历，选项改文化并复制临时人物的外貌，AI 用权重保持史实主流版本。
3. **开局清洗并重建宫廷**：隐藏事件 fire 议员 → 处理掉路人廷臣 → 按地方人口构成重新生成。
4. **两步式选项决议**：复用原版 `decision_option_list_controller` + 复制原版 petition_liege GUI。
5. **成长型特质**：施法加 XP，三档改名，效果用 `track` 叠加。
6. **组合文本**：两个 `random_list` 给临时标记 + 两个 `first_valid`，用很少的代码拼出几百种描述。
7. **王朝遗产当长期成长线**：遗产等级作为决议条件里的"替代门槛"（OR 文化传统）。
8. **正文内嵌术语提示** `[Glossary('词','KEY')]`。

### 本包可迁移的设计模式
1. **开局定制路线事件**：人物开局三连事件（背景 → 路线 → 结语），每条路线给不同宣称/附庸关系/修正，结语按标记切描述。

3. **多人游戏保护选项**：会夺取他人头衔的选项只在受害者是 AI（或双方都是玩家）时出现。
4. **"槽位 vs 成品"表达时代**：早期开局只放特殊建筑槽，由决议/事件在后来建成。
5. **一个全局变量串联两个时代的决议组**（渡口建成前不可加税）。
6. **相邻港口互相通知的竞争性决议**。
7. **地区白名单公爵首府建筑**。
8. **人物定义里逐条写史料出处注释**，`do_not_generate_starting_family` 防止引擎乱生家人。

### 3.9 写法亮点
**四十日之路 widget：只列出玩家持有的沿线县**（`common/decisions/RICE_upper_egypt_decisions.txt:989-1124`）——每个 item 用 `is_shown = { has_title = title:c_xxx }` 过滤，图标直接借用原版地形图标 `gfx/interface/icons/terrain_types/oasis.dds` 等。AI 在 widget 上总选第一项的问题，作者用一个变量随机兜底：
```
# Not sure why AI is always picking first option, so we'll go with this for now as a wonky workaround
if = {
	limit = { is_ai = yes }
	random_list = {
		10 = { set_variable = { name = RICE_upper_egypt_darb_location value = flag:asyut } }
		...
```
（`:1190` 起）。**用 widget 的决议一定要单独写 AI 分支。**

**状态互斥的可逆决议**（`:129-329`）：关闭决议 `NOT = { has_global_variable = RICE_upper_egypt_philae_closed }` 才显示，执行后设变量并给 c_aswan 挂 10 年"近期关闭"修正；重开决议要求变量存在且没有"近期关闭"修正；两边都用 `change_fervor = { value = 3 desc = ... }` 提升本信仰狂热。用县修正当"反向操作冷却"，比给决议本身设冷却更合理（冷却跟着地点而不是人）。

**卢克索神庙三态**（`RICE_upper_egypt_effects.txt:1248-1297`）：同一地标做成三个不同的特殊建筑，`remove_building` + `add_special_building` 切换，并用带时限的全局变量 `set_global_variable = { ... days = 7300 }` 防止频繁易手（`RICE_upper_egypt_decisions.txt` 卢克索决议 effect 段）。

### 3.10 问题与局限
- 三个"重开神庙"决议的 `ai_potential` 写成 `prestige > medium_gold_value`（`:322`、`:523`、`:727`），把金币常量拿来比威望。
- 用 `NOT = { exists = culture:soissons }` 判断"是否同时运行 TFE mod"（`:145`、`:346`、`:548`），依赖外部 mod 的文化键，比较脆弱。

- 阿斯旺神庙 widget 决议整段注释（`:737-`），注释里还留着"Tooltip won't work for some reason"，说明 widget item 的 `is_valid` 里 `custom_tooltip` 不显示。
- 开渠活动定义的记忆没有被创建（`RICE_upper_egypt_open_nile_canals.txt:339-352` 注释）。

### 本包可迁移的设计模式
1. **群像开场事件**：一事件发给一组史实人物，按"谁是玩家"切换主视角、选项名和史实简介，并给出"效忠/不效忠"立场选项。
2. **故事选择驱动旅行**：`start_travel_plan` + `travel_with_domicile` 让无地人物按选择真正迁徙，并在抵达时触发后续事件。
3. **开局用 `set_mother` 等补全原版人物家谱**，不覆盖原版 history 文件。
4. **与原版新政体对接**：把依赖原版设置结果的代码放进文件名靠前的独立 on_action 文件（`000_`），并检查原版规则。
5. **日历 + 全局状态门控的活动**：只在泛滥季（8~10 月）、按当年水情开放不同活动。
6. **全局地标的可逆争夺**：全局变量表示开关，县修正表示反向冷却，信仰狂热作为回报。
7. **一个地标多个建筑态**（神庙/教堂/清真寺）。
8. **widget 决议必须写 AI 随机分支**。

### 本包可迁移的设计模式
1. **神谕/占卜活动**：供品档次 × 意图 → 奖励矩阵；问题方向 → 随机吉凶修正。
2. **一个通用活动 + 各地分派事件**（温泉之旅按男爵领分派）：新增地点只需登记一行。

4. **给无地冒险者单独开活动入口**（距离判定 + 营地位置）。
5. **古代开局给成品、后世开局给空槽**，再用一次性决议修复。

### 6.9 写法亮点
**widget 选项 → 1 天变量 → 后续事件读取**（`RICE_south_ethiopia_decisions.txt:204-279`）：
```
# Not sure why AI can't pick one option or another
if = { limit = { is_ai = yes }
	random_list = {
		10 = { set_variable = { name = RICE_south_ethiopia_sidama_groves_type value = flag:small days = 1 } }
		10 = { trigger = { gold >= RICE_south_ethiopia_sidama_tree_decision_medium_cost } ... flag:medium ... }
		...
} }
else_if = { limit = { scope:RICE_south_ethiopia_sidama_groves_decision_small_option = yes }
	set_variable = { name = RICE_south_ethiopia_sidama_groves_type value = flag:small days = 1 } }
...

```
决议本身不写 `cost`，费用在事件里按变量扣，避免 widget 选项与决议费用不同步。

**美德/罪恶特质数量加权**（`RICE_south_ethiopia_effects.txt:1525-1600`）：好结果权重按 `num_virtuous_traits >= 1/2/3` 递增、`num_sinful_traits` 递减——原版信仰美德系统直接拿来当"神明是否眷顾"的依据。

### 6.10 问题与局限
- `RICE_create_fandaanano_effect` 里 `religion:sidamic_religion = { save_scope_as = waaqism_religion }`（`RICE_south_ethiopia_effects.txt:1421`），把错误的宗教存成了 waaqism 作用域。
- 历史兜底只会在"玩家持有"的地区县里触发，并**直接把该玩家改信新宗教**（`RICE_fandaanano_appearance_effect` → `south_ethiopia.0001` 隐藏事件里 `set_character_faith`），玩家没有拒绝机会。
- 开局改县的列表里 `c_dara` 重复两次（`:55`、`:64`；`:194`、`:203`）。
- Motolomi 的故事只停在授地。

### 本包可迁移的设计模式
1. **多级人生成就仪式**：同一活动按已有特质等级自动切换类型（条件 `default` + `is_valid`），完成后升级特质，满级后不可再办。
2. **原版"隐藏宗教"机制 + 决议创立 + 历史兜底**：开局封锁改信，决议解封；无人创立时按年代递增概率自动出现。

### 9.9 写法亮点
**非侵入式扩展原版决议**（`common/on_action/RICE_BAP_shared_events_on_actions.txt:39-84`）：
```
# Don't want it to be given randomly way after the decision is taken
if = {
	limit = {
		is_target_in_global_variable_list = { name = unavailable_unique_decisions target = flag:declare_canarias_decision }
		NOT = { has_global_variable = RICE_guanche_kingdom_deadline_set }
	}
	set_global_variable = { name = RICE_guanche_kingdom_deadline_set value = yes }
	set_global_variable = { name = RICE_canarias_kingdom_decision_bonus_event_timer value = yes days = 1095 }
}
if = {
	limit = {
		exists = title:k_canarias.holder
		title:k_canarias.holder = { OR = { religion = religion:north_african_religion  culture = { ... guanches ... } } }
		... has_global_variable = RICE_canarias_kingdom_decision_bonus_event_timer
	}
	remove_global_variable = RICE_canarias_kingdom_decision_bonus_event_timer
	title:k_canarias.holder = { trigger_event = guanche.0005 }
}
```
原版决议完成时会把自己的 flag 放进 `unavailable_unique_decisions`，RICE 只是"每年看一眼这个列表"，并用带 `days = 1095` 的全局变量做时间窗——**不覆盖原版文件、不改原版决议，却给它接上了专属结局**。

**"头衔专属修正"随头衔转移**（`events/RICE_guanche_events.txt:162-183`）：`on_title_gain` 里判断 `scope:title = title:c_madeira`，把前任身上的修正移除、给新任加上。

- 风味事件：泥砖建筑维护、泥瓦匠的秘术、新泥瓦匠合同、新址要不要额外的护符保护（`events:1105-1364`）。
- 无 flavorization 文件。

### 11.9 写法亮点
**按玩家现有领地类型动态列出 widget 选项**（`common/decisions/RICE_bozo_decisions.txt:622-830`）：
```
item = {
	is_shown = { NOT = { has_title = title:c_jenne } }
	is_valid = {
		custom_description = { text = RICE_has_castle_holding_req
			any_held_title = { tier = tier_county any_county_province = { has_holding_type = castle_holding } } }
	}
	value = RICE_bozo_mud_masons_castle_option
	icon = "gfx/interface/icons/widgets/RICE_castle_holding.dds"
	...
}
item = {
	is_shown = { has_title = title:c_jenne }
	value = RICE_bozo_mud_masons_castle_jenne_option
	...
```
同一决议对"杰内持有者"和"普通泥瓦匠文化统治者"显示两套选项，用 `is_shown` 切换，`is_valid` + `custom_description` 解释为何某项不可选。

**死亡时把资格挂到继承人身上**（`events/RICE_bozo_events.txt:179-230`）：`player_heir = { set_variable = { name = RICE_ghana_burial_ancestor value = root years = 5 } }`，只对亲属关系成立的继承人生效，变量 5 年后自动过期，决议据此显示——这就是原版"为先人举行葬礼"类决议的机制。

### 11.10 问题与局限
- 加纳王葬只认 `player_heir`，AI 统治者去世不会产生该决议，AI 永远不举行王葬（`bozo.0011` 的 `exists = player_heir`，`:183-186`）。
- 多处用 `culture:soissons` 判断 TFE（如加纳王葬 `RICE_bozo_decisions.txt:467` 的 `# Check if TFE is also running`）。
- 迁城与朝圣活动硬编码 `c_jenne` / `b_jenne-jeno`。
- `bozo.0011` 本地化为 `xxxxx` 占位（隐藏事件）。
- Tapama Djenepo 人物模板因存档膨胀被禁用——侧面说明大量 `create_character` 的风味事件确实会拖累存档。

### 本包可迁移的设计模式
1. **一次性传说事件留下可重复朝圣的地标**（全局列表标记作为活动显示条件）。
2. **按已有领地类型动态生成选项**，特殊地点持有者看到专属选项。
3. **死亡时给亲属继承人挂限时变量**，驱动"为先人办丧礼"类决议（直接沿用原版天葬写法）。
4. **"首创 → 传播 → 使用"的文化革新链**（建立商网 → 引入 → 协同决议）。
5. **为社会角色虚构代表人物**并明确标注"虚构"。
6. **一次性传说人物不生成角色**，以文字与地点表现，避免存档膨胀。

## 12. 本组共性小结

### 12.1 接入本体的方式（11 个包完全一致）
1. **不覆盖原版文件**：所有内容都是新键；唯一例外是关切包用 `localization/replace` 改了原版宗教 `north_african_religion` 的显示名（9.10）。
2. **开局一次性改世界**：`on_game_start` 里按包调用 setup 效果（0.1），大量使用 `add_culture_tradition` + `remove_variable = tradition_cooldown`、`set_county_culture/faith`、`add_special_building(_slot)`、`set_culture_pillar`、`add_doctrine/remove_doctrine`；需要读游戏规则或玩家身份的放到 `on_game_start_after_lobby`；需要在原版之后执行的放进 `000_` 文件（上埃及行政制）。
3. **随机事件集中挂载**：原版 playable pulse → RICE 自己的年/三年/五年/廷臣/史实池，`delay = { days = { 8 288 } }` 打散，`chance_of_no_event` 由游戏规则调节，事件自身 `trigger` 负责地区过滤（0.2）。西非诸包走一套同构的 `RICE_BAP_shared_*`。
4. **复用原版系统而非自造 UI**：决议 widget 一律用原版 `decision_option_list_controller` + 复制原版 petition_liege GUI；活动套原版 activity 框架（`on_invalidated` 触发原版 `activity_system.03xx`）；宝物用原版 `create_artifact` + 蓝图；互动改写原版"购买停战"；王朝遗产轨道、传奇种子（`create_legend_seed` + 自定义 chronicle）、旅行选项、局势（尼罗河）、原版"隐藏宗教"变量、原版"天葬"变量写法、原版 `create_noble_family_effect`、`start_tributary_interaction_effect`、`break_subject_contract_and_establish_tributary_effect` 都被直接调用。
5. **兼容外部 mod 的两种探测法**：(a) 对方 mod 开局时设全局变量（`bap_is_loaded`、`CE_is_loaded`、`PR_is_active`），RICE 只读不写；(b) RICE 在文件名 `00000000_compatibility_triggers.txt` 里定义一组 `always = no` 的触发器（`is_tip_trigger`、`is_dharmachakra_loaded`、`roa_is_active`、`paganism_plus_is_loaded`、`ibl_is_loaded`、`ME_is_loaded`，`:4-30`），由对方 mod 或兼容补丁用同名 `always = yes` 覆盖。另外还有"拿对方独有的文化键判断"的土办法（`exists = culture:soissons` 判断 TFE）。

### 12.2 人物故事的四种做法（按投入从高到低）

|---|---|---|
| **历史志向（任务书 + 年检 + 结算）** | Rahabhan、al-Umari、Najah 三兄妹 | 变量 `RICE_historical_aspiration` + 角色修正当任务书 + 通用 important_action + `yearly_global_pulse` 年检 + "带修正才记"的附加目标标记 + 主/附加奖励分段（0.3、1.5、2.5） |
| **开局人物事件链** | Rahabhan 传说版本选择、al-Umari 开局路线、图伦群像、Azjur 迁徙、Najah 兄妹介绍 | 区分"可选/非可选"开局组；按"谁是玩家"切视角；选项改文化+复制外貌、给宣称、称臣、`start_travel_plan` |

### 12.3 目标任务的五种结构
1. **历史志向**（个人或多人共享）。
2. **全局一次性决议**：统一用全局变量列表 `unavailable_unique_decisions` 存 flag（建国、宗教创立、族群涌现、修复古迹、迁城、渡口、甘蔗）。原版自己也用这个列表，所以 RICE 能"监视"原版决议是否已完成（关切）。
3. **决议链 / 任务树**：图阿雷格"涌现 → 阿伊尔帝国"、苏斯"平定 → 三项工程"、博佐"建立 → 引入 → 协同"、南埃塞俄比亚 Fandaanano"决议创立 / 历史兜底"。
4. **进度阶梯**：苏斯西吉尔马萨繁荣度（县修正 0~4 档）、南埃塞俄比亚牛主特质（1→2 级）、索科特拉巫师特质 XP、跨撒哈拉商人 XP。
5. **可逆的地标争夺**：阿斯旺三神庙、卢克索三态建筑、奥尼之位的恢复与归还。

### 12.4 活动设计的共性
- 都是**单阶段**（`is_predefined = yes`）+ 事件链驱动；选项通常只有一两个类别（档次/类型），奖励在结算效果里按"选项 × 意图"矩阵发放，并写进 `add_activity_log_entry` 的 `show_in_conclusion`。
- **日历门控**很常见：泛滥季、新年、收获节、10 月 1 日开幕。
- **地点锁定**：`is_location_valid = { barony ?= title:b_xxx }` + `province_score`；为无地冒险者另开"营地在附近/在该地"的入口。
- **通用模板复用**："地方朝圣"四类型与三意图被阿斯旺、Hibis、Tapama Djenepo 墓共用；"温泉之旅"用一个活动按男爵领分派事件；两个埃塞俄比亚新年节庆共用意图。
- **记忆类型普遍定义了却在 `on_complete` 里注释掉**——本组所有活动与事件里，只有上埃及"祈求好泛滥"真正创建了记忆（`RICE_upper_egypt_pray_good_nile_flood.txt:351`、`:359`，用 grep 全组检索未注释的 `create_character_memory` 仅此两处）。推测是作者遇到了问题（如存档或性能）后统一关闭，但文件里没有说明。

### 12.5 风味化的共性
- 称号风味化只在关切（整套）和尼日尔三角洲（奥尼一条）出现；其余包靠文化传统、特殊建筑、游戏概念与 `[Glossary(...)]` 术语提示营造地方感。
- 历史背景开关 `RICE_historical_context_on`：几乎每个决议与重要事件都在效果末尾追加 `custom_tooltip = ..._context_tooltip`，或在选项 `flavor` 里加"历史背景"段落——**史料说明与玩法文本分离，玩家可关**。
- 每个包都有自己的音乐表、music player 封面与 2~3 张事件背景图，形成"包"的视听识别。

### 12.6 常见问题（对照自查用）
- 复制粘贴残留：文件头注释写错包名（红海写成亚琛）、ID 段写错（`0920`）、变量键多一个 R、通知对象沿用上一决议的 scope、注释与代码逻辑相反（索科特拉 AI 权重）。
- 空壳 `after`/`if`、`spawn_army = { war = war }` 这类无效参数。
- 依赖他包人物 ID 或他包的触发器（红海依赖 Muslim Enhancements 的 `me_` 人物；上埃及依赖努比亚包的尼罗河局势）。
- widget 决议在 AI 侧总选第一项，作者在三处写了随机兜底（上埃及、南埃塞俄比亚、索科特拉的 AI 分支）。
- 大量 `create_character` 的投奔/开局事件可能拖累存档（博佐注释）。

### 12.7 对"汉晋春秋"最值得直接移植的清单
1. 历史志向框架（变量 + 修正任务书 + important_action + 年检 + 附加目标标记）——可直接用于"曹操挟天子""刘备入蜀""孙策平江东"等人物目标。
2. 群像开场事件（按谁是玩家切视角 + 效忠/不效忠选项）——适合 184/190 开局的群雄。
3. 开局定制路线三连事件——替代规则菜单。
4. "未受认可"减益 + 请愿决议 + 对方裁决事件（奥尼串珠王冠）——对应"请封/受印绶/天子册封"。
5. 城市繁荣度阶梯 + 并列工程决议（西吉尔马萨）——对应"屯田/修水利/筑城"。
6. 监视原版全局列表给原版决议加后续（关切）——给原版"组建帝国"等决议接汉晋专属结局而不改原版文件。
7. 节庆按月份开放 + 地点锁定 + 通用意图模板。
8. 开局清洗并按地方人口重建宫廷（索科特拉）——对应你的"开局议会预填"问题。
